## 3. Corrections made against what was asked, and why

These are the places the shipped behaviour deliberately differs from the owner's literal
instruction. Each was raised once, each has evidence behind it, and none should be re-litigated
without new information.

1. **Dual-unit storage was NOT built** (C1.04.4). Every quantity is stored canonically and
   formatted at render, so the units toggle is already free. Storing both creates two sources of
   truth that can disagree, plus round-trip drift.
2. **The activity bands stay three** (C1.09.5). They are FAO/WHO/UNU 2004 PAL bands and the file
   already records rejecting the five-point gym ladder. The owner's condition was "if these
   levels are arbitrary"; they are not. The labelling complaint was real and is fixed separately.
3. **No six-month hormone-therapy threshold** (C1.07.16). No study validates any RMR equation in
   that population and none supports a time cut-off. van Velzen 2020 (DOI 10.1530/EJE-20-0609)
   found a fifth of transmasculine participants with no measurable change at 24 months.
4. **Creatine is grams, not milligrams** (C1.13.3), and the engine already computed it.
5. **"No milk and sugar" does not ship** (C1.13.4). No evidence supports it.
6. **Protein form advice was replaced** (C1.13.6). Isolate, concentrate and hydrolysate do not
   differ meaningfully; the advice is daily total and third-party testing.
7. **Caffeine is 0.9 to 2 mg/kg**, the resistance-training range, not the 3 to 6 usually quoted,
   whose floor at 70 kg already exceeds EFSA's safe single dose.
8. **The modal divider is pink, not lime** (C1.07.15). Lime is the limelight background.
9. **The site prose was moved, not deleted** (C1.08.10). Measuring the wrong site silently biases
   the estimate.
10. **`error.valueRequired` was not deleted** (C1.08.14). Ten call sites. What changed is when it
    renders.
11. **No gym-walk energy term** (C1.09.17). No MET coefficient exists in this project and the
    content review supplies none.
12. **The intro figure is original** (C1.01.11). The named cartoon character is third-party
    property and would have made the README licence claim false.

### Delegation, what actually works

- **Sonnet subagents via the Agent tool** are the reliable path. They edit files and run gates.
- **agy (Gemini) works only in pure print mode.** It auto-denies every tool call in headless mode,
  and the error blames permissions, which is misleading: the cause is a prompt that invites tool
  use. The recipe: run from a directory that is NOT the repo, put no file paths in the prompt,
  open with "Do not read any file. Do not write any file. Do not run any command", redirect
  stdout to a file, and apply the result yourself.
- **Run batches sequentially.** Every batch touches `src/content/copy.ts`; concurrent agents on
  one file overwrite each other.

### The trap that catches every agent

`docs/feedback/catalogue.json` pins every copy string byte for byte and
`src/content/alphaCatalogue.test.ts` asserts it. Any change to a copy key needs, in order:

```
node scripts/alpha-catalogue.mjs && node scripts/alpha-catalogue.mjs --check
node scripts/alpha-walk-pages.mjs && node scripts/alpha-walk-pages.mjs --check
```

A new key also needs a part in `scripts/alpha-parts.mjs` and a step in `scripts/alpha-walk.mjs`.
`alpha-catalogue.mjs` finds call sites with `git grep`, which cannot see untracked files, so
`git add` new files before running it.

### 5.3 Round-2 feedback — the intake protocol

The owner walked https://claude.ai/code/artifact/7aef9f95-c092-4bb2-babd-cf3d71152349 and has
feedback ready. **It arrives as a FILE, not as a conversation turn**, because the orchestrator's
context is the scarce resource and round-2 prose is long enough to force a compaction mid-round.

1. The owner pastes it verbatim to `docs/feedback/round-2/onboarding-owner-feedback.md`. Any
   route is fine: an editor, a Codex run writing the file, the page's own Assemble block.
2. Dispatch `docs/plans/subagent-briefs/H-round2-intake.md`. That subagent reads the prose and
   writes two files: `ledger.md`, one row per claim carrying the owner's EXACT words, and
   `assessment.md`, holding only what needs a ruling.
3. The orchestrator reads the ledger and the assessment. **It never reads the prose.** Briefs
   quote from the source file by id.

The verbatim column is not a formality. Round 1's value came from working against his own words,
and a hostile review of that round found eleven claims missing from the ledger because they sat
buried mid-paragraph. H tells the subagent to go sentence by sentence for that reason.

### 5.4 The copy-editing tool — AFTER round 2, by the owner's instruction

The owner wants to edit text and formatting himself rather than give sentence-level feedback.
Agreed design, not yet built:

- **A Vite dev plugin, `apply: 'serve'`,** exposing a POST endpoint that patches
  `src/content/copy.ts` on disk. In dev, `copy()` stamps each rendered string with its key;
  alt+click opens an input; HMR reloads. This is Tolgee's gesture without Tolgee.
- **A copy deck as an artifact** for what alt+click cannot reach: the `FORMAT` frames, which are
  functions, and the R10 long-form modules, which are structured objects. Uses the `db`
  capability so edits persist and can be read back with `read_db`, no paste step.
- **Rejected: Tolgee.** Not for the reason first given. The owner correctly pointed out it would
  be dev-only and never ship, which answers the privacy objection. It loses because `copy()` is
  not i18next: it is a typed union over three skin tables plus frames that are functions, so
  fitting it means either rewriting every call site or a shim that still cannot reach the prose
  that most needs editing.
- **Rejected: Decap/Sveltia CMS.** Built for markdown with frontmatter; this is a typed TS table.
  Needs an export-and-generate step plus GitHub OAuth plus a hosted admin page, for one editor.

### The activity slider, resolved

Round 1 refused a slider because the bands are not arbitrary. That was half right: they are not
arbitrary, but they are RANGES, and a stop inside a published range invents nothing. Nine stops,
three per band, every PAL inside its own FAO interval, with the examples carrying the resolution
the numbers cannot. Full design and the superseded decision are in brief G.

One consequence recorded there and repeated here because it is easy to lose: the engine currently
returns each band's FLOOR, deliberately, so it under-prescribes. Nine stops let a user select
above the floor, so the app can now over-prescribe where it structurally could not. The
mitigation is the re-measure loop at `src/store/selectors.ts:114`.

## 5.7 Parallel construction, when round 2 lands

Round 1 ran its five batches in series because every one edits `src/content/copy.ts` and
concurrent agents on one file overwrite each other. **That constraint is removable.** The Agent
tool takes `isolation: "worktree"`, which gives each agent its own checkout; the orchestrator
merges. Use it for round-2 corrections alongside the steps 5 to 7 rebuild, which are otherwise
the same-file collision all over again.

Merge order matters: whichever branch lands second must regenerate the catalogue, because
`docs/feedback/catalogue.json` pins every copy string byte for byte.
