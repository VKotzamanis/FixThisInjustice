## What to do with this page

The register is your call, not the model's. Every row below is a place a skin says something
different from the clinical default. Read it on a phone if you can, because that is where the
strings land.

Write in the last column. Three marks:

- `keep` ships the string as written.
- `cut` drops the row, and the clinical string stands on that skin.
- Anything else you write is the string you want instead, and it ships as you wrote it.

Leave a row blank and it ships as written, the same as `keep`.

No second limelight pass runs before your marks come back. The rest of the P9 work does not
depend on this page, so nothing is waiting on you except the words.

## What the marks cannot change

Two rules bind whatever you write, and both are in the master plan rather than in anyone's
taste.

A skin changes words, never facts. Every `{slot}` is a number the app computed, so it survives
every rewrite, and so do the units and the defined quantity names: `60 kg`, `8 reps` and
`beverage intake` read the same on every skin.

A skin never jokes on a control whose misreading costs data. The wipe, the import, the legacy
delete, the export, the save failures, the reminder states and the install steps have no rows
here and will not get any. `src/content/copy.limelight.ts` names all 110 of them with the
reason beside each group.

## The strings you named

Three strings are frozen because you asked for them: `advice.drinkToThirst` reads `hydrate or
diedrate`, `status.prStamp` reads `MOTHER`, and `button.startSession` reads `LET'S GO BABES`.
`status.weekMetStamp` carries the same `MOTHER` at the key the week stamp reads. Mark them like
any other row if you want them changed.

## How to read the tables

One table per screen, in tab order, then the popups. A key appears once, under the first screen
that renders it, so a control shared by two screens is listed with the earlier one. `same` in
the board column means the departures board has no row and the clinical string stands there.
