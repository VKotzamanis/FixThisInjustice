## 1. The name

Three candidates were drafted. All are lowercase, none is a third-party mark, and none names a real
person, an artist, an album or a song.

| Candidate | Skin id | The case for it | Why it lost |
| --- | --- | --- | --- |
| **limelight** | `"limelight"` | Names **both** parents in one word: *lime* is brat's flat field, the single most visible thing inherited from E, and *the limelight* is stan's marquee and the fandom gaze that the whole F register is built on. A limelight is also literally a stage light, which is what the marquee is. No collision with any vocabulary in this codebase. | — **picked** |
| serve | `"serve"` | Native to the ballroom and stan register, one syllable, active voice, and it describes what the app actually does: it serves you a session. | Collides with the ambient vocabulary of a web codebase. `skin === "serve"` sitting near service, server and `serveStatic` is ambiguous at a glance, and a persisted enum value has to survive being read out of context in a JSON export. |
| flopera | `"flopera"` | A portmanteau of "flop era", the user's own favourite string, and it is the funniest of the three. | It names the skin after failure. The id appears in Settings, in an exported state file and in any bug report, always without the joke's context, and the tone rule this skin is built on is that **the joke is about the app or the week, never about the user**. A skin id that reads as the app's standing verdict on you breaks that rule in the one string that can never be softened by what sits next to it. |

**Picked: `limelight`.** Display name in Settings: **`the limelight`**.

### 1.1 One candidate rejected on the master-plan rule, and the user can overrule it

The brief asks for "cunty" icons and says not to shy away from being vulgar. The vulgarity is honoured
throughout §3 — it is the user's register, their app and their friend group. It is kept out of **the
skin id and the Settings label only**, and for one narrow reason rather than squeamishness:

- Master-plan §3 Skins: *"they may not use slurs"*. Whether "cunty" is a slur is genuinely contested —
  in ballroom and queer stan vernacular it is an affirmation, in American English it is a
  misogynistic slur, and in British and Australian English it is general-purpose profanity. The word
  is doing different work in each.
- Every other string in this skin arrives with context around it: a joke sits next to the honest
  sentence, on a screen the user chose to open. The **id** arrives with no context — in a JSON export,
  in a shared screenshot of a Settings list, in a crash report — and it is the one string that cannot
  be read as a joke about the app.

This is a rule from the master plan, not a judgement about the user's taste, and the master plan is
the user's own document. **If the user wants it, it is a one-line change** (`SkinId` gains
`"cunty"`, `settings_skin` display becomes `cunty`) and nothing else in the design moves.

## 2. What came from each parent, and the ground

### 2.1 Taken from E — brat summer

| Taken | Why it survives the merge |
| --- | --- |
| **The flat lime field `#8ACE00`, edge to edge, every screen** | It is the ground and it does not change. Round two's own comparison rated E **best in set for gym legibility** and F merely adequate, on one argument: a light ground does not mirror an LED ceiling, and 10.91:1 black-on-lime is the highest body contrast of any of the eight directions built so far. Merging onto F's aubergine would have thrown away the one property that made E win a criterion. |
| **Lowercase everything** | Cheap-flyer register, and it is what makes the three shouted strings mean anything (§3.2). |
| **Stretched narrow display type** (Archivo variable, `wdth 62`, `wght 800`) | One family at two widths, as a one-Pantone flyer would have had. It also solves a merge problem: F's Bungee is a signage face with no width axis and no small-size range, and this skin needs one family that can be both a 76 px shout and a 12.5 px footnote. |
| **Size-only hierarchy for content** | The prescription list, the set rows and the target rows stay unruled and uncarded. Cards are spent only on the camp chrome (§2.2), never on a list of numbers. |
| **The mascot** (`agy-artifacts/brat-mascot-128.png`) | It is the character the four new illustrations extend (§5). |

**Dropped from E: the resample blur.** E blurred its 76 px session label by 0.4 px so the display type
looked resaved. In the merge it lands directly under F's hard 4 px offset shadow, and a soft edge
beneath a hard shadow does not read as a style — it reads as a rendering fault. It was also already
fenced in round two (`no quantity is ever blurred`), which is the shape of a device that costs more
than it returns. It is replaced by a **hard-shadow snap** (§2.5): same sense of the type arriving,
zero legibility cost, and the device now belongs to the stan parent rather than fighting it.

### 2.2 Taken from F — stan twitter

| Taken | Why it survives, and what changed |
| --- | --- |
| **The marquee** | The user's stated favourite. Retained and improved in four specific ways — see §2.4. |
| **The quote-tweet card** | Round two's best single idea: last week's number literally embedded inside this week's remark, which is a week-over-week comparison in a shape no other visual culture produces. It moves from a dark inset box to a black-ruled inset on lime. |
| **The rubber-stamp moment (MOTHER) and the sparkle fan** | Named by the user as something enjoyed immensely. Kept whole. The twelve Twemoji sparkles become twelve icons from the new set (§4). |
| **The drop-shadowed display face** | A hard offset shadow, never a blur. On lime the shadow is `--pink`, which is the only way pink can legally touch the display type at all (§2.3). |
| **Hard-shadowed cards** | Kept, but only for camp chrome. Round two's adopted rule holds and is tightened: **no element carrying live set data, a load, a rep count, a clock or a delta is rotated, and none is shadowed in a colour that could be mistaken for a state.** |

**Dropped from F: the aubergine ground, white body type, and card rotation on anything.** The tilt was
already limited to ±1.0° in round two and to chrome only; on a lime ground with black rules, a 1°
tilt reads as a printing misregistration rather than as attitude, and it costs the clean edge that
makes the flat field work. Rotation now exists in exactly one place: the stamp, at −6°, where it is
the whole point.

### 2.3 The ground, decided by computed contrast

Both candidate grounds were computed (WCAG 2.1 relative luminance, sRGB, script in
`scratchpad/contrast.py`). Both are legible, so contrast alone does not decide it — but contrast
decides what the *accent* is allowed to do, and that turned out to be the interesting result.

**Option (i) — lime ground, black type, one pink accent**

| Pair | Ratio | Verdict |
| --- | --- | --- |
| `#000000` on `#8ACE00` | **10.91:1** | all display and body type |
| `#454545` on `#8ACE00` | **4.98:1** | fine-print floor, inherited from E |
| `#FFFFFF` on `#8ACE00` | **1.92:1** | **banned**, as in E. No white type on lime anywhere. |
| `#FF5FCB` on `#8ACE00` | **1.41:1** | **fails at every size.** Pink is never type on lime. |
| `#C4006B` on `#8ACE00` | **3.06:1** | clears large-text 3:1 only — **rejected**, see below |
| `#9E0050` on `#8ACE00` | **4.25:1** | the darkest pink still readable as pink, and it **still fails 4.5:1** |
| `#000000` on `#FF5FCB` fill | **7.75:1** | pink works as a **fill** with black type on it |
| `#FFFFFF` on `#FF5FCB` fill | 2.71:1 | banned; black is the only type colour on pink |
| `#FFFFFF` on `#000000` panel | **21.00:1** | type inside an inverted panel |
| `#8ACE00` on `#000000` panel | **10.91:1** | lime type inside an inverted panel |
| `#FF5FCB` on `#000000` panel | **7.75:1** | the **only** place pink is ever type |

**Option (ii) — aubergine ground, lime and pink accents** (F's palette, for comparison)

| Pair | Ratio |
| --- | --- |
| `#FFFFFF` on `#16041F` | 19.60:1 |
| `#D6FF3B` acid on `#16041F` | 17.01:1 |
| `#8ACE00` lime on `#16041F` | 10.18:1 |
| `#C9A6DC` on `#16041F` | 9.31:1 |
| `#FF5FCB` on `#16041F` | 7.24:1 |

**Decision: option (i), the lime ground.** Three reasons, in order of weight.

1. **It keeps the property that won a criterion.** E beat F on gym legibility in round two on the
   LED-mirroring argument, and 10.91:1 on a light field is the highest body contrast in the whole
   project. Option (ii) is legible, but it is legible in the way F already was.
2. **The constraint that falls out of it is productive rather than costly.** Because no pink is
   readable as type on lime at any size, pink is confined to fills, outlines and offset shadows —
   which is exactly where F was already using it well (the stamp, the primary slab, the 5 px offset
   shadow, the day cells) and nowhere near the places F used it as decorative type. A palette rule
   that removes a bad option for free is worth more than a fourth hue.
3. **Every F form survives the move and gains contrast doing it.** The marquee becomes the one
   inverted strip on a light page; the quote-tweet becomes a black-ruled inset; the rest panel is
   black with white and lime type at 21.00:1 and 10.91:1, against F's 17.93:1 and 8.51:1.

**`#C4006B` rejected, and the rule stated without a size exception.** A deep pink at 3.06:1 would
have been legal as large text (≥ 24 px). It is rejected anyway, because a palette rule with a size
exception is a rule that gets broken by the next person who resizes a heading. The rule is therefore
absolute and has one sentence: **pink is never type on lime, at any size; pink is type only inside a
black panel.** A checker can enforce that; "pink is type only above 24 px" is how E's blur rule went
wrong in the first place.

### 2.4 The marquee, retained and improved

The user named the moving banner specifically. Four changes, each with a reason.

1. **It inverts.** On lime it is the single black strip on the page, so it reads as a lit sign rather
   than as another card. Type inside it is lime (10.91:1) and white (21.00:1), with pink (7.75:1)
   for the one item that is a state.
2. **It can be stopped.** F's marquee scrolled at 22 s per loop and could not be paused, so a stat
   that went past was gone. It is now a real `<button>`, 44 px tall, labelled for screen readers, and
   it pauses while pressed (`animation-play-state: paused`). This is the one change that makes it
   information rather than decoration, which is what the user called it: *"the moving banner
   /information"*. It carries `touch-action: pan-y` so a vertical scroll started on the bar is never
   captured by it, and its only effect is to pause, so a stray tap costs nothing. See §8 for the
   objection this answers and the part of it that remains untested.
3. **It is where the icon set lives.** The megaphone leads the strip and sparkles separate the items,
   so the sixteen icons of §4 have a home that is not a button label.
4. **It carries different content per screen, and the first item is the one that matters.** Under
   `prefers-reduced-motion: reduce` it stops and centres a single static line — so the item chosen to
   be first is the item a reduced-motion user gets. F had this behaviour; it did not have the rule
   about which item goes first.

### 2.5 Motion budget

Three orchestrated moments and nothing else moves.

| Moment | What happens | Under `prefers-reduced-motion: reduce` |
| --- | --- | --- |
| **The shadow snap** (replaces E's focus pull) | On load the display line's pink offset shadow travels 12 px → 4 px and the type settles from `letter-spacing: .06em` to `-.045em` over 260 ms, staggered 80 ms across at most three lines. No blur, no opacity fade on a numeral. | No animation; final state rendered. |
| **The stamp landing** (F's, kept) | MOTHER scales 2.4 → 1.0 and rotates −14° → −6° over 700 ms; at 240 ms twelve sparkle icons fan out on individual translate/rotate tracks. | Stamp renders in place at final transform; sparkles render static at 92 % opacity. |
| **The marquee** | Continuous `translateX(0 → −50 %)` over a doubled item list, 24 s per loop; pauses while pressed. | Animation removed, strip centres one static line. |

**No quantity is ever animated, blurred, or faded.** The rest clock ticks because it is a clock; it
does not transition. This is the round-two rule kept verbatim, and it is a data-integrity rule
wearing a motion rule's clothes.

## 3. The copy contract

### 3.1 The rules

Inherited from master-plan §3 and binding here:

- Buttons **≤ 3 words**, hero lines **≤ 8 words**, advice lines **≤ 12 words**.
- **No em-dashes anywhere in a user-facing string**, which is the scope master-plan §3 sets and the
  scope the mockup is checked against (verified: zero in the HTML file). En-dashes survive in numeric
  ranges only (`6–8`, `130–160 g`). This design document is not a user-facing string and uses them.
- **No emoji characters.** Not one, anywhere in the file, including in comments and the copy table.
  Enforced by grep over the emoji Unicode ranges (§7 criterion 5).
- **Numbers, units and control semantics are never skinned.** `140 lb`, `63.50 kg`, `61.2 kg`,
  `1:47`, `2 of 4`, `−2` print exactly as `src/domain/units.ts` produced them. A skin may put a word
  beside a number; it may never restate a number in words or round one for effect.
- Camp, profanity and slang are allowed and wanted. **No slurs, no body-shaming, no food morality.**

Added by this round, from the user's complaint (b):

- **No explanatory arithmetic on any screen.** No percentages, no plate-rounding steps, no delta
  formula, no storage-unit conversion. The two strings the user quoted are the specimen failures and
  both are deleted outright:
  - ~~"All sets reached 8 reps on 25 Aug, so +2.5 % (3.4 lb) rounded up to the 5 lb barbell step.
    Entered in lb, stored as 63.50 kg."~~ → **`140 lb. up 5. why?`**
  - ~~"two of four, bestie. the week flopped, not you. 2 completed, 1 skipped, 1 not logged. Weekly
    target 4. Delta = completed − target = −2."~~ → **`2 of 4. flop era.`** with `1 skipped. 1 not
    logged.` as fine print beneath.
- **Every "because" lives behind `why?`, and it is one sentence of ≤ 12 words.** `why?` is a
  `<details>/<summary>` disclosure, closed by default, and it is the *only* place a reason appears.
  Opening it shows a plain sentence: `all sets hit 8 last time.`
- **The ban is on *justification* arithmetic, not on *instructional* numbers.** This distinction was
  missing from the first draft and the `agy` critique found the hole. A percentage, a rounding step,
  a delta formula or a unit conversion explains a decision the app already made, and the user does
  not need it. A number the user has to *act on* is not arithmetic, it is an instruction, and it is
  always allowed on the screen: the load, the reps, the rest, and a plate breakdown if the app ever
  computes one. `140 lb` is an instruction. `+2.5 % (3.4 lb) rounded up to the 5 lb step` is a
  justification. The first stays; the second goes.
- **What was deleted rather than moved.** `Entered in lb, stored as 63.50 kg` does not go behind
  `why?`; it leaves the training screen entirely. The canonical storage unit is an implementation
  fact that belongs in Export, not on a screen someone reads between sets. The logged value is still
  displayed exactly as entered, which is the rule that actually protects the user.
- **The honest sentence is kept but made terse.** Round two's safety rule was that the funny line
  always sits beside the honest one. That rule holds. What changed is that the honest line is now
  *data* (`1 skipped. 1 not logged.`) and never *method* (`Delta = completed − target = −2`). Counts
  are facts; the formula is arithmetic, and only the arithmetic was the complaint.

### 3.2 Case, and the three strings that shout

Everything is lowercase. Three strings are uppercase, and they are uppercase *because* everything
else is not: **`MOTHER`**, **`LET'S GO BABES`**, and the marquee, which is a sign. Shouting is only
legible against a quiet baseline, so the uppercase list is closed at three and no fourth string joins
it.

### 3.3 The tone rule, and the one screen where it is hardest

**The joke is about the app, or about the week. Never about the user.** Round two established this
and it holds unchanged. The screen where it is closest to breaking is `the intervention`, shown after
a missed week — which is exactly why round two named it in all four mockups and drew it in none.
It is drawn here (screen 4), and the rule is enforced structurally rather than by good intentions:

- The **title** may be camp (`the intervention`).
- The **body** may not be. `intervention_body` is plain, ≤ 12 words, contains no verdict, no
  second-person judgement and no joke: **`the week flopped, not you. monday is the next slot.`**
- The **illustration** on that screen is the mascot *resting*, not the mascot *flopping*. The flop
  illustration goes on Week review, where the user's own word "flop era" is aimed at a week. Putting
  a collapsed mascot on the screen shown to someone who has just missed a week is the picture version
  of a joke about the user, and round two's finding about direction G was that a lever in a picture
  cannot be argued away by the words next to it.

## 4. The icon set — sixteen icons that replace every emoji

The user's instruction was explicit: *"get rid of the emojis. Replace them with cunty/stan twitter/
brat summer icons."* Direction F carried six inline Twemoji SVG glyphs. All six are gone, and so is

Two of the six exist, in smooth-vector sets, at 256- and 24-unit grids. Redrawing them on a 32 × 32
pixel grid is not "using an icon set"; it is drawing an icon while inheriting an MIT notice.

**Two further findings that decided it, neither of which is about licensing:**

1. **Pixelarticons is 24 × 24 and the target cell is 32 × 32.** 32 / 24 = 1.333. A non-integer scale
   destroys the pixel grid and reintroduces exactly the anti-aliasing the set exists to avoid. The
   only pixel set that lands on 32 exactly is Kenney's 1-Bit Pack at 16 × 16 (2 ×).
2. **The 1-Bit Pack ships tilesheets and Tiled `.tmx`/`.tsx` only — no named per-icon PNGs.** Every
   icon must be sliced out by grid coordinate, and it has no droplet, no pause or skip transport
   glyph, no stopwatch and no megaphone, so it cannot even cover the utility half.

<!-- decision: round3-icons-generated-not-restyled | status: adopted | supersedes: none -->

**Decision: generate all sixteen with `agy`, do not restyle a set.** Mixing sources was the obvious
alternative and it is the wrong answer three times over. Eight rescaled 24 × 24 MIT icons beside
eight generated 32 × 32 icons would be visibly two sets, and the seam would fall exactly along the
line between the boring icons and the funny ones. The rescale itself is lossy (finding 1 above). And
a restyle deep enough to hide both — regridding, refilling and repalettising every glyph — is more
work than generating, produces a derivative work whose MIT notice still has to ship, and converges on
the generated half anyway. One source, one grid, one palette, one licence, and the licence is the
simplest possible because the whole set is own work.

**Pixelarticons remains the right fallback if a later icon is needed and generation cannot match
it**, accepting the 24 → 32 rescale for that one glyph. Its MIT licence requires the copyright and
permission notice to ship, which is a real obligation rather than a formality; the generated set
carries none, because it is own work.

### 4.2 How they were made, and the check that was stated first

**The check, stated before generating:** an icon passes if, after slicing, downscaling to 32 × 32 and
snapping to the palette, its silhouette is identifiable at true 32 px on the lime ground **without a
label beside it**. Any icon that fails is hand-authored as a pixel grid instead, as round two did for
direction G's sprites.

Method:

1. **One sheet, not sixteen prompts.** A single `agy` generation of a 4 × 4 grid of sixteen
   pictograms, in the mascot's own style paragraph (coarse 32 × 32 grid, hard-edged pixels, no
   anti-aliasing, thick black outline, flat lime field, and an explicit demand for no text, no
   lettering and no watermark). One sheet guarantees a consistent stroke weight and palette across
   the set in a way sixteen separate generations cannot. **No real person, brand, character or
   artist is named in the prompt**, and none appears in the output.
2. **Sliced by connected component, not by grid.** Five of the sixteen overflow their nominal 256 px
   cell. Cutting on a rigid 4 × 4 grid would have clipped the fan, the barbell and the martini, so
   the slicer labels connected foreground regions and takes every component whose centroid lands in
   the cell. The lime field is keyed to alpha by a green-dominance test (`G > R+40 ∧ G > B+80 ∧
   G > 150`); no icon contains green, so the test cannot eat artwork. **That fixed threshold was
   later found to be brittle and the illustrations use a different key — see §5.1.** It is kept for
   the icon sheet because it is what actually produced the shipped files (background fraction 0.601)
   and re-running it would change bytes for no gain.
3. **Premultiplied downscale.** RGBA is premultiplied before the area average and unpremultiplied
   after, or the transparent lime bleeds a green fringe into every outline. Alpha is then thresholded
   at 110/255, which restores hard pixel edges.
4. **Palette-snapped to seven opaque colours plus alpha** — eight entries, inside the ≤ 8 limit.
   The palette is the **mascot's own** (`#000000`, `#FCA3BE`, `#BB5F7B`, `#6D6D6D`, plus `#242424` in
   the illustrations), extended by the skin accent `#FF5FCB`, a light metal grey `#C9C9C9` and white.
   Using the mascot's palette is not a nicety: it is what makes the icons and the illustrations
   provably the same drawn world rather than two things that look similar.
5. **Result: 16 of 16 passed the stated check.** No icon needed hand-authoring. Files are 180–492
   bytes each, 2–6 colours used per icon.

**One bug worth recording, because it is the class that only a visual check catches.** The first
palette snap ran in `int16`. A squared channel difference reaches 255² = 65 025, which overflows a
signed 16-bit integer, so `argmin` selected on wrapped-negative distances and every pink fill snapped
to black. The icons came out as photographic negatives of themselves. Nothing threw, nothing warned,
and the file sizes looked plausible. It was found by rendering a contact sheet and looking at it.

### 4.3 The panel variant

Icons sit in two places, and a black outline is invisible on a black panel. Rather than ship two
drawings, five icons carry a **derived panel variant** in which `#000000` is remapped to `#8ACE00`:
outline lime on black at **10.91:1**, fills pink at **7.75:1**. The five are the ones that appear
inside the marquee, the rest panel or the stamp: `megaphone`, `sparkle`, `barbell`, `stopwatch`,
`crown`. The remaining eleven only ever appear on lime and need no variant.

The rule that makes this work at all: **the silhouette is always carried by the outline, never by
the fill.** Pink on lime is 1.41:1 and could not carry a shape; black on lime is 10.91:1 and does.
Fills are interior only, which is why the icons survive both grounds.

### 5.1 Generation and processing

Same pipeline as §4.2 with one correction. The fixed green-dominance threshold was **brittle and it
broke**: the regenerated crown sheet came back on a more yellow lime, `(165, 202, 47)`, where
`G − R = 37` and the `G > R + 40` test fails. The whole background was classified as foreground and
snapped to opaque grey. It was caught by looking at the output, not by an exception.

The key is now **self-calibrating**: it samples the four 16 × 16 corners of the image, takes their
median as the reference, and masks every pixel within Euclidean distance 72 of it, then asserts the
resulting background fraction lands between 0.25 and 0.90 so a silent failure of this kind throws
instead of shipping. Measured background fractions: lifting 0.709, resting 0.728, flop 0.735, crown
0.763. Then premultiplied box downscale to 256 × 256, alpha threshold at 110/255, and a palette snap
to the mascot's own colours plus white and a light grey. Every raw generation is kept at
1024 × 1024 for provenance and is **not** inlined.

## 6. Sound

Master-plan §3 already allows a skin "optional sound effects". This is the first skin with a moment
worth scoring: a rubber stamp that lands is a sound-shaped event, and a rest timer that ends while
the phone is face-down on a bench is the one piece of information in the app that a screen cannot
deliver.

**Nothing here is built.** No audio can be generated on this machine and none is shipped with this
mockup. §6 is a specification and a shopping list; §12 records it as not done.

### 6.1 The four moments

Four, and no more. A fifth sound turns a training app into a slot machine.

| Key | Fires when | Character | Length |
| --- | --- | --- | --- |
| `sfx.session_done` | the last set of the session is logged and `session_done` (`ate.`) renders | the one celebratory sound; a short rising figure | 1.2–2.0 s |
| `sfx.pr_stamp` | the MOTHER stamp lands, i.e. a `LoggedSet` beats the previous best for that exercise | a hard percussive stamp with a bright tail, timed to the 700 ms landing | 0.8–1.2 s |
| `sfx.rest_over` | the rest countdown reaches 0 | the only *functional* sound of the four; must be audible in a noisy gym and must not sound like a notification the user will ignore | 1.0–1.5 s |
| `sfx.intervention` | the missed-week modal opens | soft and low, not a sting. It plays over `intervention_body`, and a triumphant noise on that screen would break §3.3 | 1.0–1.5 s |

### 6.2 The playback rule

1. **One `AudioContext`, unlocked by the first user gesture of any kind, never on load.** Mobile
   Safari and Chrome both start an `AudioContext` in the `suspended` state and will only resume it
   inside a user gesture. A one-time `pointerdown` listener on `document`, plus an explicit
   `resume()` on the Settings sounds toggle, does the unlock; the listener removes itself after the
   first fire.

   **The first draft bound this to the `start_session` tap and that was a bug**, found by the `agy`
   critique. A PWA resumed from the home screen straight back into a session in progress never passes
   through that button, so `sfx.rest_over` would have failed silently on exactly the path where it is
   the only useful sound in the set. A gesture listener is not autoplay: it still plays nothing until
   the user touches the screen.
2. **Decode once, at unlock.** All four buffers are fetched and `decodeAudioData`'d immediately after
   the unlock, then held. Decoding at fire time costs a variable delay, and a stamp sound that
   arrives 300 ms after the stamp is worse than no sound.
3. **Never autoplayed.** No sound plays on page load, on view change, on reminder delivery, or when
   the tab is backgrounded (`document.visibilityState !== 'visible'` suppresses playback).
4. **One-shot, never looped, never overlapping.** A new fire stops the previous source.
5. **`prefers-reduced-motion` has no bearing on this.** It is stated explicitly because the inference
   is tempting and wrong: that media query governs motion, not audio, and a user who suppresses
   animation has expressed nothing about sound. The gate is a **separate `sounds` toggle** in
   Settings, persisted on `UiPrefs`, and it is the only thing that silences the skin.
   (`prefers-reduced-motion` still governs the marquee, the stamp animation and the shadow snap, as
   in §2.5.)
6. **Default: off.** The honest default for a feature whose failure mode is a phone shouting in a
   public gym. The toggle is on screen 5 so it is one tap away, not buried.

### 6.3 The format rule

**Ship AAC in an `.m4a` (MP4) container as the universal file; optionally add Opus as a smaller
alternate; never ship Ogg alone.** Ogg is the trap: Ogg Vorbis and Ogg Opus have no Safari support,
so an Ogg-only asset is silent on every iPhone, which is the platform this PWA is most likely to be
installed on.

```html
<audio preload="none">
  <source src="/sfx/pr_stamp.webm" type="audio/webm; codecs=opus">   <!-- smaller, optional -->
  <source src="/sfx/pr_stamp.m4a"  type="audio/mp4;  codecs=mp4a.40.2"> <!-- universal -->
</audio>
```

With the Web Audio path above, the same choice is made with
`ctx.createBufferSource()` fed by whichever URL `HTMLAudioElement.canPlayType()` reports as
`"probably"`, falling back to the `.m4a`.

**Size target: < 60 kB per file, < 240 kB for the set.** A 2 s mono clip at 96 kb/s AAC is roughly
24 kB, so the target has about 2× headroom and no clip needs stereo. The four files are **not**
precached by the service worker: master-plan §3 already excludes media from `injectManifest`, and the
same argument applies — they are fetched and cached on first unlock, not shipped in the app shell.

**Sonniss GDC bundles were checked and are excluded.** They are frequently described as free-to-use
and they are **not CC0**: the bundle licence is a proprietary royalty-free agreement that forbids
supplying the sounds onward *as sound effects*, which a repository shipping its own `sfx/` directory
would be doing. Recorded here so the mistake is not made later.

**One verified fact that turns the format rule from a preference into a requirement.** *Every Kenney
audio pack ships Ogg Vorbis only* — no wav, no mp3, no m4a. MDN marks **Vorbis as unsupported in
Safari**. So whichever Kenney file is chosen, **transcoding to AAC/`.m4a` is mandatory, not
optional**, and shipping the downloaded file as-is would be silent on every iPhone.

**Where MDN contradicts itself, and what this plan does about it.** MDN's *Media container formats*
page states that Safari 18.4+ (iOS/iPadOS 18.4+, macOS 15.4+) added Opus and Vorbis in Ogg
containers; MDN's *Web audio codec guide* still carries an older footnote saying Safari supports Opus
only inside a CAF file. Both are cited in `REFERENCES.md`. This plan does not pick a winner: it
treats Opus as an **alternate `<source>` listed first and never as the only file**, which is correct
under either reading. The claim the rule actually rests on is the one MDN states plainly and without
contradiction: *"AAC in an MP4 container is supported by all major browsers ... likely your best
choice if you can only support one audio format."*

## 8. The `agy` critique, and what changed because of it

One adversarial critique of §1–§7 was run through `agy` and is logged in `REFERENCES.md`. It is a
**paraphrase from another model**; nothing in it is treated as evidence, and it changed the plan only
where the change is independently defensible. It was asked seven specific questions and told not to
summarise or compliment. It found one outright bug and one copy string that breaks the plan's own
rule, which is more than round two's critique found.

### Adopted

1. **`plan_progress` labelled a specific past session as a failure — adopted in full, and it is the
   most important change.** The string was `10 served. 1 flop. 37 to go.` The critique's point is
   exactly right and it is the plan's own rule that catches it: "flop era" is aimed at a **week**,
   which §3.3 permits, but "1 flop" is aimed at **one particular session the user did not do**, and
   that session may carry a `skipReason` recording illness, work or bereavement. A count is data; a
   count with a verdict attached to each item is the app judging the user. Changed to
   **`10 served. 1 skipped. 37 to go.`** — which is also, as it happens, the honest word the data
   model uses (`AssignmentStatus = "skipped"`). Nothing else in the table has this shape: every other
   camp string attaches to a week, to the app, or to nothing.

2. **The arithmetic ban had a hole — adopted as a clarification that should have been in the first
   draft.** §3.1 banned "explanatory arithmetic" without distinguishing a *justification* from an
   *instruction*. Under the literal rule a plate breakdown would have been banned along with the
   rounding-step explanation, and a lifter standing at a rack does need to know what goes on the bar.
   The rule is now split: a percentage, a rounding step, a delta formula and a unit conversion are
   justifications and are hidden; a load, a rep count, a rest duration and a plate breakdown are
   instructions and are always on screen. **The specific proposal was declined**, though — a plate
   breakdown is not a copy change a skin can make. `src/domain/units.ts` quantises suggested loads to
   `Profile.equipmentSteps` but nothing computes a per-side plate list, so shipping that string would
   mean a skin inventing a number. It is recorded in §12 as a feature the Train screen should have,
   which is a different plan's work.

3. **Unlocking audio on the `start_session` tap was a real bug — adopted in full.** A PWA resumed
   from the home screen directly into a session in progress never passes through that button, so
   `sfx.rest_over` would have failed silently on precisely the path where it is the only sound in the
   set that does any work. The unlock moves to a one-time `pointerdown` listener on `document`, plus
   an explicit `resume()` on the Settings toggle so a sound preview works before any session. §6.2
   rule 1 is rewritten. This is the kind of finding that justifies running the critique at all: it is
   a behaviour bug in a specification, invisible on every screen.

4. **The marquee's touch behaviour — partially adopted.** The objection is that a full-width 44 px
   interactive bar high on the screen captures scroll drags and fires stray clicks. Half of it has a
   real fix and is taken: the bar carries `touch-action: pan-y`, so a vertical scroll begun on it is
   never captured. The other half is overstated — a `<button>` does not block scrolling, a click
   needs a touch that stays inside the slop threshold, and the only effect of a stray tap is to pause
   a ticker. The proposed alternative (`pointer-events: none` plus a separate pause button) trades
   one 44 px target for two elements and a smaller one. **What remains true and is recorded in §12:
   touch collision cannot be measured in headless Chromium, so this is reasoned, not tested.**

### Rejected

1. **"The ground decision is rationalising a contrast failure into a virtue." Rejected as framing,
   and its alternative was computed rather than waved away.** The critique's premise is that a
   fill-only accent forces every status into a boxed container, inflating line height on a 390 px
   screen. That premise does not hold here: status in this skin is carried by **black type and an
   icon**, never by pink. Pink marks the primary action, the stamp and the offset shadow, all of
   which are fills by nature. Nothing had to be boxed to accommodate the rule.

   Its concrete alternative was better than its argument and was tested: a dark plum
   **`#4A002E` on `#8ACE00` computes at 8.20:1** and would be perfectly legal as type. It is still
   rejected, on design grounds rather than contrast grounds, and the distinction matters:

   - A third ink undoes what was taken from E in the first place. E's hierarchy is **size alone**;
     the moment there are two type colours, hierarchy starts being carried by hue and the discipline
     that made E the most legible thing in round two is gone.
   - `#4A002E` at 13 px on lime reads as *nearly* the accent pink. A colour that is almost the accent
     but is not the accent is worse than no second colour, because it invites the reader to look for
     a meaning that is not there.

   Recorded as: **the alternative passes the test that would have dismissed it, and is rejected
   anyway for a stated reason.** If a later screen genuinely needs a second ink on lime, `#4A002E` at
   8.20:1 is the value to use.

2. **"Generated icons cannot hold a pixel grid; use Pixelarticons for the utility half and hand-draw
   the camp half." Rejected, on evidence, and the licence verification strengthened the rejection.**
   The objection is a reasonable prior and it was already answered by the check stated in §4.2:
   **16 of 16 icons are identifiable at true 32 px** on the lime ground with no label, verified by
   rendering contact sheets at 1 × and 4 × and looking at them. The proposed alternative is worse
   than the critique knew: Pixelarticons is **24 × 24**, the target cell is 32 × 32, and 32/24 = 1.333
   — a non-integer rescale that destroys the pixel grid and reintroduces the anti-aliasing the set
   exists to avoid. The only pixel set that lands on 32 exactly is Kenney's 1-Bit Pack, which ships
   no named per-icon files and has no droplet, pause, skip, stopwatch or megaphone.

   **The half of the objection that is correct is adopted as a recorded cost:** adding a seventeenth
   icon later means re-prompting the sheet or accepting style drift. That is a genuine standing
   liability of a generated set and it is listed in §12.

3. **"Putting the resting mascot on the intervention screen is self-flattering hair-splitting."
   Rejected, and recorded as the least certain judgement in this plan.** The critique's claim is that
   both screens are triggered by the same failure state and that no user distinguishes a resting
   slump from a couch collapse. That is an assertion about perception offered without evidence, from
   a model reasoning from priors, and the distinction it dismisses is the one round two identified as
   the reason direction G was rejected: a lever in a picture is not answerable by the words next to
   it. Rest and collapse are different pictures making different claims — one says recovery is
   legitimate, the other says you gave up.

   Its alternative (an active pose: the mascot lacing shoes or chalking hands) is genuinely good and
   is the change to make if a second reader disagrees with me. It was not built because it needs a
   fifth generation and because the four illustrations map one-to-one onto the four screens that need
   one. **This is the single highest-risk unverified judgement in the round**, it is mine rather than
   the user's, and §12 records it as such.

   so it is now a fill, an outline and an offset shadow, and it is type only inside a black panel.
3. **E's 0.4 px resample blur is gone**, replaced by the hard-shadow snap (12 px → 4 px over 260 ms).
   A blurred edge under a hard offset shadow reads as a fault, not a style.
4. **Bungee is gone.** F used it for display and stamps. It has no width axis and no usable
   small-size range, and the merged skin needed one family that could carry both a 76 px shout and a
   12.5 px footnote. Archivo at `wdth 62` does both.
5. **Card rotation is gone.** F tilted chrome cards ±1.0°. On a flat lime field with black rules a
   1° tilt reads as printing misregistration. Rotation now exists in exactly one place: the stamp, at
   −6°, where it is the point.
6. **All six Twemoji glyphs are gone**, with them the CC-BY attribution obligation F carried, and
   with them every emoji character in the file. Sixteen original icons replace them.
7. **The marquee became a control.** 44 px, a real `<button>`, pauses while pressed,
   `touch-action: pan-y`, and it now shows one designated static line under
   `prefers-reduced-motion: reduce` rather than a centred overflow of the whole track.
8. **Every reason moved behind `why?`.** F printed `All sets reached 8 reps on 25 Aug, so +2.5 %
   (3.4 lb) rounded up to the 5 lb barbell step. Entered in lb, stored as 63.50 kg.` on the screen.
   The screen now reads `140 lb. up 5.` with a closed disclosure that opens to `all sets hit 8 reps
   last time.` The storage-unit sentence was deleted rather than moved.
9. **The week line lost its formula.** F printed `Delta = completed − target = −2`. The screen now
   reads `−2`, then `2 of 4. flop era.`, then `1 skipped. 1 not logged.` and stops.
10. **`plan_progress` lost the word "flop".** `10 served. 1 flop. 37 to go.` became
    `10 served. 1 skipped. 37 to go.` See §8, adopted item 1.
11. **Two screens were added that neither parent had:** the missed-week intervention modal, and a
    Settings screen with the skin picker and the sounds toggle.
12. **Four illustrations replaced one.** E had a single 96 px corner mascot; the merged skin has four
    poses at 176–210 px, one per screen that needs one.

### Changed during the build, from looking at the rendered result

Three defects that only a screenshot catches, all fixed:

1. **Archivo collapses the word space at narrow widths.** At `wdth 62–76` with negative
   letter-spacing, `the intervention` rendered as `theintervention` and `reduce motion` as
   `reducemotion`. Fixed with per-class `word-spacing` from `.06em` to `.18em`, scaled to how narrow
   each class sets `wdth`. **No numeral class received word-spacing** — a quantity has no spaces in
   it and a rule that touches numbers is not a typography rule.
2. **The MOTHER stamp fell below the dock on the Train screen.** The single most important moment in
   the skin was off-screen. The redundant 52 px `upper` display line was removed from Train (the
   status bar and the marquee both already name the session), the rest clock went 88 px → 78 px, and
   the stamp moment was restructured so the crowned mascot leads and the stamp lands over its lower
   edge rather than beside it.
3. **Today carried the same character twice.** The round-two 96 px corner mascot sat above the new
   lifting illustration. The corner mascot was removed; `brat-mascot-128.png` is therefore **not
   inlined** in this file.

## 10. Verification, what it actually returned

The checker specified in §7 was written before the mockup and run against it at 390 × 844, twice.

| Criterion | `no-preference` | `reduce` |
| --- | --- | --- |
| 1. viewport meta present | `width=device-width,initial-scale=1,viewport-fit=cover` | same |
| 2. no horizontal scroll | scrollWidth **390** vs innerWidth 390 | same |
| 3. tap targets ≥ 44 px | 24 interactive, **0 under 44 px** | same |
| 4. contrast | **319 text runs measured, 0 below threshold** | same |
| 5. no emoji characters | **0** literal, **0** decodable entities, **0** em-dashes | same |
| 6. disclosures closed on load, summary ≥ 44 px | **0 bad** | same |
| Motion | 19 animations running: `scroll`, `snap`, `fan`, `land` | **0 running** |

**Result: passes all six criteria in both motion modes.**

Motion was checked behaviourally rather than asserted. Under `reduce` every marquee reports **1 of 8
items visible, `text-align: center`**, and the visible item is the designated first one on each
screen (`ep. 12 of 48 · upper`, `set 3 of 3 · bench`, `2 of 4 this week`) — so the rule in §2.4 rule 4
about which item a reduced-motion user gets is enforced, not just intended.

Assets: **25 distinct inlined images, largest 4 023 B, 21.1 kB raw in total**, against a 300 kB
per-image ceiling. Whole file 101.3 kB including all base64.

### One numerical bug found and fixed during asset processing

The palette snap first ran in `int16`. A squared channel difference reaches 255² = 65 025, which
overflows a signed 16-bit integer, so `argmin` selected on wrapped-negative distances and every pink
fill snapped to black. Nothing threw and the file sizes looked plausible. It was caught by rendering
a contact sheet and looking at it, and it is recorded here because the same class of silent numeric
failure produced the second defect too (§5.1, the brittle chroma threshold). Both are now guarded:
`int32` arithmetic, and an assertion on the background fraction.

### What the checker still does not measure, restated as a limitation

- **Declared colours, not rendered pixels.** Images composited over lime are not sampled. Every icon
  silhouette is `#000000` on lime (10.91:1) or `#8ACE00` on black (10.91:1) by construction, and
  those figures are computed, not measured.
- **Text nodes only.** The day cells, the target bars, the depletion meter and the icons were
  reasoned about against the 3:1 non-text guideline, not measured. The day cells are the one place
  this could have mattered and they carry three distinct *treatments* (solid fill, diagonal hatch,
  dashed outline), so they do not depend on hue.

## 11. Recommendation

<!-- decision: round3-merged-skin-limelight | status: adopted | supersedes: round2-skin-architecture -->

**Ship `limelight` as the single merged skin, opt-in, never the default, and retire `brat` and `stan`
as separate `SkinId` values rather than keeping three.** `SkinId` becomes
`"clinical" | "limelight" | "board"`.

The case is that the merge is not a compromise between E and F, it is a resolution of them. E's
weakness was that one flat field and one typeface leave no hierarchy to spend, so the skin lives or
dies on copy. F's weakness was that its camp had no discipline underneath it and its dark ground was
the worse of the two for a gym. Putting F's forms on E's ground fixes both directions at once: the
marquee, the quote-tweet and the stamp give E the three hierarchy events it did not have, and E's
10.91:1 lime field and size-only discipline give F a floor it could not fall below. The palette rule
that fell out of the merge — pink is a fill, never type — is the thing that keeps it from drifting
back into F's decoration.

It also costs less than round two's recommendation. Round two proposed shipping three skins in order,
which is three copy tables to review and three token sets to maintain. This is one, and it is the one
the user asked for by name.

### The rejected alternative

<!-- decision: round3-keep-e-and-f-separate | status: rejected | supersedes: none -->

**Keeping E and F as two shipping skins and adding `limelight` as a third was considered and
rejected.** It is the obvious cautious option: nothing is lost, the user picks. It is wrong for three
reasons, in order of weight.

1. **It answers a question the user did not ask.** The brief is *"I want us to combine the brat summer
   with the stan twitter one"*. Shipping all three is a way of not deciding, and a skin picker with
   three near-identical camp options is worse than one good one.
2. **Two of the three would carry defects this round fixed.** E still has the resample blur on live
   screens; F still has the Twemoji CC-BY obligation, the exposed arithmetic the user complained
   about twice, and `1 flop` attached to a specific logged session. Keeping them means keeping those,
   or fixing them three times.
3. **Every skin is a standing copy-review cost.** §3.3's rule has to hold in every string of every
   table, and the reviewing is the expensive part, not the CSS.

**What is kept from the rejection:** E and F stay in `docs/design/round2/` as the record of where the
merge came from, and `#4A002E` at 8.20:1 on lime is recorded in §8 as the value to reach for if a
second ink on the lime field is ever genuinely needed.

## 12. What I did not do

- **No audio exists.** §6 is a specification and a shopping list. No sound was generated, auditioned,
  transcoded or shipped; no `AudioContext` code was written; the Settings toggle is a drawing of a
  control, not a control. The four Kenney packs were verified by licence and file listing, not by
  listening to a single file, and every one of them ships Ogg Vorbis that would have to be transcoded.
- **The illustration on the intervention screen is the least certain judgement in this round.** It is
  mine, not the user's, the `agy` critique disagreed with it (§8, rejected item 3), and the named
  swap if a second reader also disagrees is an active pose (the mascot lacing shoes or chalking
  hands), which needs a fifth generation.
- **A plate breakdown was specified and not built.** §8 adopted item 2 concluded that `why?` may
  legitimately carry what goes on the bar, but nothing in `src/domain/` computes a per-side plate
  list, so shipping that string would mean a skin inventing a number. It is a Train-screen feature
  for a later plan.
- **`session_done` (`ate.`) is the only copy key with no on-screen instance.** The Train screen is
  drawn mid-session with set 3 still open, so the end-of-session state is documented in the copy
  table and not rendered.
- **Adding a seventeenth icon is a standing liability.** The set is coherent because it came off one
  sheet in one generation. A later icon means re-prompting the whole sheet or accepting visible style
  drift. That cost is real and it was accepted, not solved.
- **The icons were judged by eye, not by grid analysis.** The stated check (identifiable at true
  32 px without a label) passed 16 of 16, but stroke widths are not provably uniform across the set
  and no script verified that every edge lands on the pixel grid. `heel` and `megaphone` are the two
  with visibly ragged edges.
- **No device testing, and the marquee's touch behaviour is therefore untested.** Everything is
  headless Chromium at 390 × 844. The `agy` critique's touch-collision objection (§8, adopted item 4)
  is answered with `touch-action: pan-y` by reasoning; whether a thumb scrolling from the marquee
  behaves is not something this environment can measure. Nothing was opened on an Android phone or an
  iPhone, no Safari rendering was checked, and the 44 px floors are CSS pixels rather than thumbs.
- **No gym-lighting test.** The claim that a light ground beats a dark one under an LED ceiling is
  inherited from round one and round two. It is an argument, not a measurement, and it is load-bearing
  for the §2.3 ground decision.
- **No colour-vision-deficiency simulation.** The palette was not run through a CVD simulator. It is
  the least exposed of the eight directions so far, because the only two hues are lime and pink and
  no state is carried by hue alone (the day cells use solid, hatched and dashed treatments), but it
  was not checked.
- **The 3:1 non-text contrast guideline was not enforced for graphics.** The checker walks text nodes.
- **No token file and no copy-table module.** This is one static HTML page with inline CSS. The
  `SkinId` change proposed in §11 is a recommendation, not an edit to master-plan §5, and nothing was
  added to `UiPrefs`. `sounds` is not a real preference yet.
- **Only five screens.** Plan, Log, Atlas, Export, the setup wizard and reminder settings are absent,
  as is every empty, error, offline and first-run state.
- **No `prefers-color-scheme` variant.** The skin is a fixed scheme, deliberately.
- **The copy table was not reviewed by a second person.** The `agy` critique caught one string that
  broke the plan's own rule, which is evidence that a second reader finds things I do not.
- **`agy` was consulted once for critique, not iteratively**, and its output is a paraphrase from
  another model. §8 records what was adopted and what was rejected; nothing in it is cited as evidence.
- **Licence facts were verified by a subagent, not by me directly.** Every claim in §4.1 and §6.4 was
  fetched from a primary source (repo `LICENSE` files, git trees, the licence text inside the
  downloaded zips, MDN) and every URL is in `REFERENCES.md` with its method. The Pixelarticons **Pro**
  set's licence could not be verified and is not cited; only the 1 036 free MIT icons are.
- **MDN contradicts itself on Safari and Opus and this plan does not resolve it** (§6.3). It routes
  around the contradiction rather than settling it.
- **The knowledge graph was not updated.** The decision headers in this file are not in
  `graphify-out/graph.json`. Run `graphify . --update` before treating the graph as current; it was
  not run here because other agents are editing `src/` concurrently.
- **Nothing outside `docs/design/round3/`, `agy-artifacts/` and `REFERENCES.md` was touched.** `src/`,
  `legacy/`, `public/`, `docs/plans/`, `docs/review/` and the round-one and round-two design files are
  unchanged.
