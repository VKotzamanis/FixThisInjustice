## Rulings (owner wants rulings, not questions; each names the rejected alternative)
- R1 Session lifecycle. One open session per profile, persisted in `fti.v3` on its assignment (rest timer, set drafts). Train always shows the open session, whatever its date. On launch/visible: an open session started on an earlier civil date auto-closes: `completed` if it has logged sets (completedAt = last set loggedAt), else the assignment is removed so the session stays next. A toast says what happened. Rejected: keep sessionStorage mirror + read `activeAssignmentDate` in Train (iOS relaunch loses it, C04).
- R2 Skip = postpone. "Skip Today" never advances the cursor; the session is served on the next visit. No "drop session" control (YAGNI). Rejected: keep skip-as-drop with a confirm (owner's mental model is postpone).
- R3 Any day is trainable. Today always offers Start for the next session (cursor). Availability = preferred days (forecast, reminders, .ics), never a gate. Forecast serves at most `sessionsPerWeek` per ISO week minus sessions already done that week. Rejected: full rotation rewrite without `plan.sessions` (D's option): every consumer + migration; the cursor already is a rotation pointer. Rejected: "train anyway" button only (fixes D02, not D04).
- R4 Numbers. One `NumericField` (`type="text" inputMode="decimal"`, app parser accepts `,` and `.`, rejects ambiguous), used by every numeric input. Plausibility gate on load (> 2x or < 0.5x last/suggested) and body mass (> 10 % from last) asks once inline. Rejected: keep `type=number` (browser drops the comma: 62,5 -> 625 stored, C02).
- R5 Store boundary validates. Every action that writes user input parses its slice with the schema the loader uses (`parseOrThrow` pattern, `src/store/training.ts`). Setup completes through one atomic `completeSetup(result)`. Rejected: validate whole doc in `save()` (cost per debounce; reports after the user left the field).
- R6 Shell. Hash router (no dependency) with one history entry per view + one per open overlay; back closes the top overlay, then goes to the previous view, never exits with an overlay up. One overlay stack. Fixed bottom tab bar (safe-area padded), one-line header. Toasts top, non-blocking. `env(safe-area-inset-*)` on every fixed edge. Rejected: React Router (bundle, loaders unused).
- R7 Updates. `registration.update()` on visible + every 30 min; waiting SW auto-applies at cold launch when no session is open, banner only mid-session; `clients.claim()`; build stamp out of the hashed main chunk. Rejected: `autoUpdate` (reloads mid-workout).
- R8 Durability. `navigator.storage.persist()` after setup; install guidance decoupled from reminders (shown when not standalone); `beforeinstallprompt` on Android.
- R9 Measurements. Body mass loggable any day (Today), edit/delete with undo, entry role (`morning`/`pre`/`post`); body-fat re-measure as a dated entry; profile editor reusing wizard validators; PAL is the only stored activity value; one fluid target + always-on quick add. Rejected: patch delete into `BodyMassQuickLog` (entry point stays inside TrainView).
- R10 Games. Rest games open as a bottom sheet over Train; the active set row stays reachable; one round per rest. Rest Word redesigned (QWERTY rows sized to width, larger tiles, clear win/lose state). New original families: Plate Math (load the bar to a target), Reaction (tap on lime), Sequence Recall (repeat a growing pad sequence), Gym Anagram (gym-word scramble). Each obeys `docs/design/rest-games.md` constraints (never touches the timer, offline, sound gated). Rejected: more Wordle variants only.
- R11 Exercise library. Add at least: reverse lunge (db/bw), walking lunge (db), forward lunge (bw), split squat (bw), step-up (db/bw), hip thrust (bb/bw glute bridge), dumbbell bench press, seated cable row, leg extension, cable triceps pushdown, cable lateral raise, dead bug, side plank, farmer carry. Each tagged with required inventory items; `resolveSlot` filters by inventory. Form cues/rest per existing cited tables (AGENTS rule 1: no new health numbers).
- R13 Storage engine. Persistence moves from one localStorage document to IndexedDB, one object store per record type (sets, assignments, bodyMass, hydration, intake, weeklyReviews, plans, profiles, ...) + one meta record (schemaVersion, revision). The in-memory `AppState` and Zustand store keep their shape; only `src/store/persistence.ts` changes: per-action write of the records whose identity changed (no debounce), read validates per record and quarantines invalid ones (listed to the user, exportable), BroadcastChannel + revision makes a stale instance reload instead of writing. First boot with IDB empty imports `fti.v3` and leaves the key untouched as a fallback backup (rule 7). JSON export/import of the whole state stays the portable backup. Unknown keys and enum values are preserved on read (B06). Rejected: many localStorage keys (same 5 MiB cap, no cross-key transaction); write-ahead journal in localStorage (narrows B08 only, shares quota); OPFS + SQLite WASM (bundle, iOS unverified); server sync (privacy decision). Reverses the ARCHITECTURE "IndexedDB for all state (async boot, no gain)" rejection: four reproduced loss paths (B01, B03, B05, B08) outweigh one loading state.
- R12 Tests that see the phone. Playwright e2e (`e2e/`, iPhone 13 + Pixel 7 emulation, fixed clock, same-zone context) for every S1/S2 fixed here. jsdom suite stays. A property test: any answers the wizard accepts load through `parseState`.
