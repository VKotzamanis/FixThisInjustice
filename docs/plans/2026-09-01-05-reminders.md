# P5 — Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** deliver scheduled training reminders end to end — a Cloudflare Worker that stores each device's next three weeks of reminder instants in KV and pushes them on a one-minute cron, plus the client that computes those instants, subscribes the device, keeps the Worker in sync, displays the notification, and explains to an iPhone user why the app must be on the Home Screen first.

**Architecture:** the client owns all scheduling logic. `computeReminderInstants` turns the projected calendar (P3) into a flat list of `{ key, at, title, body }` and uploads it with `PUT /v1/devices/{deviceId}`; the Worker never knows what a session is. The Worker's cron tick reads an index key, reads each device record, sends every reminder whose `at` falls in the last 15 minutes and is not already in `sent`, and writes a record back only when something changed. Push transport is VAPID Web Push via `@pushforge/builder`; the service worker renders the notification and focuses or opens the app on click.

**Tech Stack:** Cloudflare Workers (Wrangler 4, Workers KV, Cron Triggers), `@pushforge/builder` 2.0.5, TypeScript 5.9, Vitest 4 (pure tests, no Miniflare), React 19 + Zustand 5 on the client, `date-fns` 4 + `@date-fns/tz` through `src/domain/dates.ts`.

## Platform facts this plan must respect

Every line below is already recorded in `REFERENCES.md` with its URL, fetch time, method, and session id. Do not restate any of them from memory; if one needs re-checking, re-fetch and append a new `REFERENCES.md` line.

1. **iOS Web Push requires the app to be installed to the Home Screen** (iOS/iPadOS 16.4+). A Safari tab cannot receive Web Push. This is why Task 8 ships `InstallGuide.tsx` and why `subscribe()` refuses with `"not-installed"` on iOS outside standalone display mode. Source: `https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/`.
2. **This app's floor is iOS 18.4** (master plan §1.1): Web Push needs 16.4, but Screen Wake Lock inside an installed Home Screen web app was broken until 18.4. Source: `https://bugs.webkit.org/show_bug.cgi?id=254545`.
3. **No web API schedules a future local notification without a server** — Notification Triggers development ended; Periodic Background Sync gives no timing control. Hence the Worker. Sources: `https://developer.chrome.com/docs/web-platform/notification-triggers`, `https://developer.chrome.com/docs/capabilities/periodic-background-sync`.
4. **Cloudflare Workers free plan:** 100,000 requests/day; Cron Triggers fire at a minimum granularity of one minute; 5 cron triggers. Sources: `https://developers.cloudflare.com/workers/platform/limits/`, `https://developers.cloudflare.com/workers/configuration/cron-triggers/`.
5. **Workers KV free tier:** 100,000 reads/day, 1,000 writes/day, 1 GB. Source: `https://developers.cloudflare.com/kv/platform/limits/`.
6. **Workers free plan, per invocation:** 50 subrequests and 10 ms CPU time for a Cron Trigger invocation. CPU time excludes waiting on `fetch` and KV I/O, but VAPID signing and payload encryption are CPU. Source: `https://developers.cloudflare.com/workers/platform/limits/`.
7. **pushforge API:** `buildPushHTTPRequest({ privateJWK, subscription, message: { payload, adminContact, options } })` resolves to `{ endpoint, headers, body }`; `privateJWK` accepts a JWK object **or a JSON string**; `options` accepts `ttl` (default 86400, max 86400), `urgency`, `topic`. VAPID keys come from `npx @pushforge/builder vapid`. Source: `https://www.npmjs.com/package/@pushforge/builder`.
8. **`applicationServerKey` accepts a Base64-encoded string**, so the VAPID public key is passed to `pushManager.subscribe` as-is; `userVisibleOnly: true` is required by Chrome and Edge. Source: `https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe`.
9. **`nodejs_compat`** is required in `compatibility_flags` for `compatibility_date` between 2024-09-23 and 2026-08-03 and is enabled by default from 2026-08-04. This plan sets it explicitly anyway so the file states its own requirements. Source: `https://developers.cloudflare.com/workers/runtime-apis/nodejs/`.
10. **KV semantics:** `get(key, "text")` resolves to `null` when the key is absent; `delete()` on a missing key is a successful delete. Sources: `https://developers.cloudflare.com/kv/api/read-key-value-pairs/`, `https://developers.cloudflare.com/kv/api/delete-key-value-pairs/`.

### KV budget arithmetic (stated before the work, checked in Task 4)

Let `N` be the number of subscribed devices.

- **Reads per day:** the cron fires 1440 times; each tick reads `idx` once and each device record once → `1440 × (1 + N)`. The 100,000 reads/day free cap gives `N ≤ 68`.
- **Writes per day:** the cron writes a device record at most once per tick and only when that record changed (a push was sent, or an expired reminder or `sent` entry was pruned). With two reminders per training day and four training days per week, a device changes on roughly 8 ticks/week ≈ 1.2 writes/day; client syncs add at most one write per schedule change. The 1,000 writes/day free cap is not the binding constraint.
- **Binding constraint is subrequests:** one tick issues `1 + N` KV reads, up to `N` KV writes and one `fetch` per due push, against a 50-subrequest free-plan ceiling → roughly `N ≤ 20` devices before a tick can trip the limit. Record this in the runbook; it is the number to watch, not the daily quotas.
- **Not verified:** whether Cron Trigger invocations consume the 100,000 requests/day quota. The limits page does not say. Treat it as if they do (1440/day, well inside the cap either way).

  - `secretsMatch(a: string, b: string): boolean` — length-checked, branch-free string comparison used for the `PUT` and `DELETE` secret checks
  - `pruneDelta(before: DeviceRecord, after: DeviceRecord): number`
  - constants `MAX_REMINDERS = 200`, `PAST_WINDOW_MS`, `FUTURE_WINDOW_MS`, `DUE_WINDOW_MS`, `SENT_RETENTION_MS`
- Task 4 imports every one of these. Task 3 imports `ReminderInstant` and `PushSubscriptionRecord`.

**Why `validatePut` takes a third argument.** The master plan §6.6 requires a `PUT` on an existing device to present the same secret or receive `403`. That comparison is impossible without the stored record, so the signature is `validatePut(body, now, existing)`; pass `null` on create. This is a Worker-internal function, not a master-plan contract, so no amendment is needed.

**Why `sent` survives a re-upload.** `validatePut` carries the existing record's `sent` map (pruned) into the new record. Without this, a client re-sync minutes after a push would clear the dedupe map and the Worker would send the same reminder again on the next tick. This is the single most important line in the file for the "exactly one send" gate.

```ts
/**
 * Pure scheduling logic for the reminders Worker. No KV, no fetch, no globals —
 * everything here is a total function of its arguments so the master plan's §7
 * "exactly one send across 30 cron ticks" gate can be proved without Miniflare.
 *
 * Units: every timestamp is epoch milliseconds, UTC (EpochMs). Durations are ms.
 */

export type EpochMs = number;

export interface ReminderInstant {
  key: string;
  at: EpochMs;
  title: string;
  body: string;
}

export interface PushSubscriptionRecord {
  endpoint: string;
  keys: { p256dh: string; auth: string };
}

export interface DeviceRecord {
  secret: string;
  subscription: PushSubscriptionRecord;
  reminders: ReminderInstant[];
  /** key -> instant the push was accepted by the push service. Dedupe map. */
  sent: Record<string, EpochMs>;
}

export type ValidateResult =
  | { ok: true; record: DeviceRecord }
  | { ok: false; status: 400 | 403; error: string };

/** Master plan §6.6: at most 200 reminders per device. */
export const MAX_REMINDERS = 200;
/** Master plan §6.6: `at` must be >= now - 1 h. */
export const PAST_WINDOW_MS = 60 * 60 * 1000;
/** Master plan §6.6: `at` must be <= now + 21 d. */
export const FUTURE_WINDOW_MS = 21 * 24 * 60 * 60 * 1000;
/** Master plan §6.6: a reminder is due while `at > now - 15 min`. */
export const DUE_WINDOW_MS = 15 * 60 * 1000;
/** Master plan §6.6: prune `sent` entries older than 24 h. */
export const SENT_RETENTION_MS = 24 * 60 * 60 * 1000;

const MAX_SECRET_LENGTH = 200;
const MIN_SECRET_LENGTH = 16;
const MAX_ENDPOINT_LENGTH = 1024;
const MAX_KEY_LENGTH = 120;
const MAX_TITLE_LENGTH = 100;
const MAX_BODY_LENGTH = 300;

function isRecordObject(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}

function readString(source: Record<string, unknown>, key: string): string | null {
  const value = source[key];
  return typeof value === "string" ? value : null;
}

function boundedString(value: string | null, min: number, max: number): string | null {
  if (value === null) return null;
  return value.length >= min && value.length <= max ? value : null;
}

/**
 * Length-independent string comparison. Not a substitute for a real constant-time
 * primitive — the Workers runtime exposes none for strings — but it removes the
 * trivial early-exit signal from the secret check.
 */
export function secretsMatch(a: string, b: string): boolean {
  if (a.length !== b.length) return false;
  let diff = 0;
  for (let i = 0; i < a.length; i += 1) {
    diff |= a.charCodeAt(i) ^ b.charCodeAt(i);
  }
  return diff === 0;
}

function prunedSent(sent: Record<string, EpochMs>, now: EpochMs): Record<string, EpochMs> {
  const kept: Record<string, EpochMs> = {};
  for (const [key, at] of Object.entries(sent)) {
    if (now - at <= SENT_RETENTION_MS) kept[key] = at;
  }
  return kept;
}

function parseSubscription(value: unknown): PushSubscriptionRecord | { error: string } {
  if (!isRecordObject(value)) return { error: "subscription must be an object" };
  const endpoint = boundedString(readString(value, "endpoint"), 1, MAX_ENDPOINT_LENGTH);
  if (endpoint === null || !endpoint.startsWith("https://")) {
    return { error: "subscription.endpoint must be an https URL" };
  }
  const keys = value["keys"];
  if (!isRecordObject(keys)) return { error: "subscription.keys must be an object" };
  const p256dh = boundedString(readString(keys, "p256dh"), 1, 200);
  const auth = boundedString(readString(keys, "auth"), 1, 100);
  if (p256dh === null) return { error: "subscription.keys.p256dh must be a string" };
  if (auth === null) return { error: "subscription.keys.auth must be a string" };
  return { endpoint, keys: { p256dh, auth } };
}

function parseInstant(value: unknown, index: number, now: EpochMs): ReminderInstant | { error: string } {
  if (!isRecordObject(value)) return { error: `reminder ${index}: must be an object` };
  const key = boundedString(readString(value, "key"), 1, MAX_KEY_LENGTH);
  if (key === null) return { error: `reminder ${index}: key must be a 1..120 character string` };
  const at = value["at"];
  if (typeof at !== "number" || !Number.isInteger(at)) {
    return { error: `reminder ${index}: at must be an integer` };
  }
  if (at < now - PAST_WINDOW_MS || at > now + FUTURE_WINDOW_MS) {
    return { error: `reminder ${index}: at is outside [now - 1 h, now + 21 d]` };
  }
  const title = boundedString(readString(value, "title"), 1, MAX_TITLE_LENGTH);
  if (title === null) return { error: `reminder ${index}: title must be a 1..100 character string` };
  const bodyText = boundedString(readString(value, "body"), 0, MAX_BODY_LENGTH);
  if (bodyText === null) return { error: `reminder ${index}: body must be a 0..300 character string` };
  return { key, at, title, body: bodyText };
}

function hasError(value: object): value is { error: string } {
  return "error" in value;
}

/**
 * Validate a `PUT /v1/devices/{id}` body.
 * `existing` is the stored record for that id, or null when the device is new.
 * On an update the presented secret must match, and the existing (pruned) `sent`
 * map is carried into the new record so a re-upload cannot cause a second send.
 */
export function validatePut(body: unknown, now: EpochMs, existing: DeviceRecord | null): ValidateResult {
  if (!isRecordObject(body)) return { ok: false, status: 400, error: "body must be a JSON object" };

  const secret = boundedString(readString(body, "secret"), MIN_SECRET_LENGTH, MAX_SECRET_LENGTH);
  if (secret === null) {
    return { ok: false, status: 400, error: "secret must be a 16..200 character string" };
  }
  if (existing !== null && !secretsMatch(existing.secret, secret)) {
    return { ok: false, status: 403, error: "secret mismatch" };
  }

  const subscription = parseSubscription(body["subscription"]);
  if (hasError(subscription)) return { ok: false, status: 400, error: subscription.error };

  const rawReminders = body["reminders"];
  if (!Array.isArray(rawReminders)) {
    return { ok: false, status: 400, error: "reminders must be an array" };
  }
  if (rawReminders.length > MAX_REMINDERS) {
    return { ok: false, status: 400, error: "reminders: at most 200 entries" };
  }

  const reminders: ReminderInstant[] = [];
  const seen = new Set<string>();
  for (let index = 0; index < rawReminders.length; index += 1) {
    const parsed = parseInstant(rawReminders[index], index, now);
    if (hasError(parsed)) return { ok: false, status: 400, error: parsed.error };
    if (seen.has(parsed.key)) {
      return { ok: false, status: 400, error: `reminders: duplicate key "${parsed.key}"` };
    }
    seen.add(parsed.key);
    reminders.push(parsed);
  }

  return {
    ok: true,
    record: {
      secret,
      subscription,
      reminders,
      sent: existing === null ? {} : prunedSent(existing.sent, now),
    },
  };
}

/** Reminders whose instant has passed within the last 15 minutes and were never sent. */
export function selectDue(record: DeviceRecord, now: EpochMs): ReminderInstant[] {
  return record.reminders
    .filter((r) => r.at <= now && r.at > now - DUE_WINDOW_MS && !(r.key in record.sent))
    .sort((a, b) => a.at - b.at);
}

/** Record `keys` as sent at `now`, pruning `sent` entries older than 24 h. Pure. */
export function markSent(record: DeviceRecord, keys: string[], now: EpochMs): DeviceRecord {
  const sent = prunedSent(record.sent, now);
  for (const key of keys) sent[key] = now;
  return { ...record, sent };
}

/**
 * Drop reminders that can never be selected again (`at <= now - 15 min`, the exact
 * complement of selectDue's window) and prune `sent`. Pure; only ever shrinks the
 * record, which is what makes pruneDelta a valid change detector.
 */
export function removeExpired(record: DeviceRecord, now: EpochMs): DeviceRecord {
  return {
    ...record,
    reminders: record.reminders.filter((r) => r.at > now - DUE_WINDOW_MS),
    sent: prunedSent(record.sent, now),
  };
}

/** How many entries `removeExpired` dropped. Zero means nothing needs writing back. */
export function pruneDelta(before: DeviceRecord, after: DeviceRecord): number {
  return (
    before.reminders.length -
    after.reminders.length +
    (Object.keys(before.sent).length - Object.keys(after.sent).length)
  );
}

/** Narrow a value read back from KV. Returns null rather than throwing on corruption. */
export function parseDeviceRecord(raw: unknown): DeviceRecord | null {
  if (!isRecordObject(raw)) return null;
  const secret = readString(raw, "secret");
  if (secret === null) return null;
  const subscription = parseSubscription(raw["subscription"]);
  if (hasError(subscription)) return null;
  const rawReminders = raw["reminders"];
  if (!Array.isArray(rawReminders)) return null;
  const reminders: ReminderInstant[] = [];
  for (const candidate of rawReminders) {
    if (!isRecordObject(candidate)) return null;
    const key = readString(candidate, "key");
    const at = candidate["at"];
    const title = readString(candidate, "title");
    const bodyText = readString(candidate, "body");
    if (key === null || title === null || bodyText === null) return null;
    if (typeof at !== "number" || !Number.isFinite(at)) return null;
    reminders.push({ key, at, title, body: bodyText });
  }
  const rawSent = raw["sent"];
  if (!isRecordObject(rawSent)) return null;
  const sent: Record<string, EpochMs> = {};
  for (const [key, value] of Object.entries(rawSent)) {
    if (typeof value !== "number" || !Number.isFinite(value)) return null;
    sent[key] = value;
  }
  return { secret, subscription, reminders, sent };
}
```

**Files:**

**Interfaces:**

- Produces:
  - `interface PushEnv { VAPID_PRIVATE_JWK: string; ADMIN_CONTACT: string }`
  - `type PushOutcome = "sent" | "gone" | "failed"`
  - `const APP_URL_PATH = "/FixThisInjustice/"`

- Task 4 calls `sendPush` and branches on the three outcomes.

**Design notes that the tests enforce.**
- `privateJWK` is passed as the raw secret string. `@pushforge/builder` accepts a JWK object **or** a JSON string, so the Worker never calls `JSON.parse` on it and never needs an `as` cast, satisfying the global "no `as` casts on external data" constraint.
- RFC 8030 specifies `201 Created` for an accepted push, and the master plan §6.6 maps `201` to sent. The implementation checks `201` first and then falls back to any other `2xx`. Reason: an outcome other than `"sent"` leaves the key out of the `sent` map, so a push service that answered `200` would be re-sent on every tick for 15 minutes. Treating all `2xx` as sent is the only mapping consistent with the single-send gate.
- `404` and `410` mean the subscription is dead; Task 4 deletes the device.
- Nothing throws out of `sendPush`. A transport error becomes `"failed"`, is logged, and is retried on the next tick while the reminder is still inside its 15-minute window — a free retry for transient `5xx`.

```ts
import { buildPushHTTPRequest } from "@pushforge/builder";
import type { PushSubscriptionRecord, ReminderInstant } from "./schedule";

/** The bindings sendPush needs. Env in index.ts extends this. */
export interface PushEnv {
  /** VAPID private key as a JWK **JSON string**. Secret; set with `wrangler secret put`. */
  VAPID_PRIVATE_JWK: string;
  /** RFC 8292 contact for the push service, e.g. "mailto:owner@example.com". */
  ADMIN_CONTACT: string;
}

export type PushOutcome = "sent" | "gone" | "failed";

/** GitHub Pages project path. The notification click target, resolved against the SW origin. */
export const APP_URL_PATH = "/FixThisInjustice/";

/** Web Push message lifetime, seconds. A reminder is worthless once the session has passed. */
const TTL_SECONDS = 3600;

/**
 * Send one reminder. Never throws.
 *  - "sent"   the push service accepted it (2xx; RFC 8030 specifies 201)
 *  - "gone"   404/410: the subscription is dead, the caller deletes the device
 *  - "failed" anything else, logged; the caller leaves the key unsent so the next
 *             cron tick retries it while the reminder is still inside its window
 */
export async function sendPush(
  env: PushEnv,
  subscription: PushSubscriptionRecord,
  instant: ReminderInstant,
): Promise<PushOutcome> {
  try {
    const { endpoint, headers, body } = await buildPushHTTPRequest({
      // pushforge accepts a JWK object or a JSON string; passing the secret through
      // untouched avoids JSON.parse and the `as` cast it would need.
      privateJWK: env.VAPID_PRIVATE_JWK,
      subscription,
      message: {
        payload: {
          title: instant.title,
          body: instant.body,
          tag: instant.key,
          url: APP_URL_PATH,
        },
        adminContact: env.ADMIN_CONTACT,
        options: { ttl: TTL_SECONDS, urgency: "high" },
      },
    });

    const response = await fetch(endpoint, { method: "POST", headers, body });
    if (response.status === 201) return "sent";
    if (response.status === 404 || response.status === 410) return "gone";
    if (response.ok) return "sent";
    console.warn(`push rejected: status=${response.status} key=${instant.key}`);
    return "failed";
  } catch (error) {
    console.warn(`push threw: key=${instant.key} error=${String(error)}`);
    return "failed";
  }
}
```

**Interfaces:**
- Consumes: everything Task 2 exports, plus `sendPush`, `PushEnv` from `./push` (Task 3).
- Produces:
  - `interface KvStore { get(key: string, type: "text"): Promise<string | null>; put(key: string, value: string): Promise<void>; delete(key: string): Promise<void> }`
  - `interface Env extends PushEnv { REMINDERS: KvStore; VAPID_PUBLIC_KEY: string; ALLOWED_ORIGIN: string }`
  - `interface TickSummary { devices: number; sent: number; failed: number; removed: number; writes: number }`
  - `handleFetch(request: Request, env: Env, now: EpochMs): Promise<Response>`
  - `runTick(env: Env, now: EpochMs): Promise<TickSummary>`
  - `default { fetch, scheduled }`
- No later task imports from this file; the client talks to it over HTTP only.

**Why `Env.REMINDERS` is typed `KvStore` and not `KVNamespace`.** The master plan requires Miniflare-free pure tests. Declaring the binding as the three methods this Worker actually calls lets the in-memory stub satisfy the type with no cast, keeping the "no `as` casts" constraint intact. The cost is that TypeScript no longer proves the real binding matches; the runbook's smoke test and `wrangler dev` cover that, and the three methods used (`get(key, "text")`, `put(key, value)`, `delete(key)`) are the stable core of the KV API.

**KV key layout.**
- `idx` — JSON `string[]` of device ids.
- `dev:{deviceId}` — JSON `DeviceRecord`.

**Write budget.** A tick writes a device record only when `sentKeys.length > 0` or `pruneDelta(record, trimmed) > 0`, i.e. at most one write per device per tick and only when the record actually changed. `idx` is written at most once per tick, and only when a device was removed. `TickSummary.writes` counts them so the tests can assert it.

```ts
    parsed = JSON.parse(raw);
  } catch {
    console.warn("idx is not valid JSON; treating it as empty");
    return [];
  }
  if (!Array.isArray(parsed)) return [];
  return parsed.filter((value): value is string => typeof value === "string");
}

async function readDevice(kv: KvStore, id: string): Promise<DeviceRecord | null> {
  const raw = await kv.get(deviceKey(id), "text");
  if (raw === null) return null;
  let parsed: unknown = null;
  try {
    parsed = JSON.parse(raw);
  } catch {
    console.warn(`device record ${id} is not valid JSON`);
    return null;
  }
  const record = parseDeviceRecord(parsed);
  if (record === null) console.warn(`device record ${id} failed validation; treating as absent`);
  return record;
}

async function handlePut(request: Request, env: Env, id: string, now: EpochMs): Promise<Response> {
  const text = await request.text();
  if (text.length > MAX_BODY_BYTES) {
    return jsonResponse(env, 413, { error: "body too large" });
  }
  let parsed: unknown = null;
  try {
    parsed = JSON.parse(text);
  } catch {
    return jsonResponse(env, 400, { error: "body must be valid JSON" });
  }

  const existing = await readDevice(env.REMINDERS, id);
  const result = validatePut(parsed, now, existing);
  if (!result.ok) return jsonResponse(env, result.status, { error: result.error });

  if (existing === null) {
    const ids = await readIndex(env.REMINDERS);
    if (!ids.includes(id)) {
      if (ids.length >= MAX_DEVICES) {
        return jsonResponse(env, 503, { error: "device capacity reached" });
      }
      await env.REMINDERS.put(deviceKey(id), JSON.stringify(result.record));
      await env.REMINDERS.put(INDEX_KEY, JSON.stringify([...ids, id]));
      return noContent(env);
    }
  }
  await env.REMINDERS.put(deviceKey(id), JSON.stringify(result.record));
  return noContent(env);
}

async function handleDelete(request: Request, env: Env, id: string): Promise<Response> {
  const header = request.headers.get("Authorization");
  if (header === null || !header.startsWith("Bearer ")) {
    return jsonResponse(env, 401, { error: "missing bearer secret" });
  }
  const secret = header.slice("Bearer ".length);
  const existing = await readDevice(env.REMINDERS, id);
  if (existing === null) return noContent(env); // idempotent delete
  if (!secretsMatch(existing.secret, secret)) {
    return jsonResponse(env, 403, { error: "secret mismatch" });
  }
  await env.REMINDERS.delete(deviceKey(id));
  const ids = await readIndex(env.REMINDERS);
  if (ids.includes(id)) {
    await env.REMINDERS.put(INDEX_KEY, JSON.stringify(ids.filter((value) => value !== id)));
  }
  return noContent(env);
}

export async function handleFetch(request: Request, env: Env, now: EpochMs): Promise<Response> {
  const origin = request.headers.get("Origin");
  // CORS is a browser convenience here, not the authorisation boundary; the
  // per-device secret is. A request with no Origin (curl, uptime check) is allowed.
  if (origin !== null && origin !== env.ALLOWED_ORIGIN) return forbidden();

  if (request.method === "OPTIONS") return noContent(env);

  const url = new URL(request.url);
  if (url.pathname === "/v1/health" && request.method === "GET") {
    return jsonResponse(env, 200, { ok: true, vapidPublicKey: env.VAPID_PUBLIC_KEY });
  }

  const match = /^\/v1\/devices\/([^/]+)$/.exec(url.pathname);
  if (match !== null) {
    const id = match[1] ?? "";
    if (!DEVICE_ID_PATTERN.test(id)) return jsonResponse(env, 404, { error: "unknown device" });
    if (request.method === "PUT") return handlePut(request, env, id, now);
    if (request.method === "DELETE") return handleDelete(request, env, id);
    return jsonResponse(env, 405, { error: "method not allowed" });
  }

  return jsonResponse(env, 404, { error: "not found" });
}

/**
 * One cron tick. Sequential on purpose: the free plan allows 50 subrequests and
 * 10 ms CPU per invocation, so a burst of parallel pushes is a liability, not a win.
 */
export async function runTick(env: Env, now: EpochMs): Promise<TickSummary> {
  const ids = await readIndex(env.REMINDERS);
  const summary: TickSummary = { devices: ids.length, sent: 0, failed: 0, removed: 0, writes: 0 };
  const removed: string[] = [];

  for (const id of ids) {
    const record = await readDevice(env.REMINDERS, id);
    if (record === null) {
      removed.push(id);
      continue;
    }

    const due = selectDue(record, now);
    const sentKeys: string[] = [];
    let gone = false;
    for (const reminder of due) {
      const outcome = await sendPush(env, record.subscription, reminder);
      if (outcome === "sent") sentKeys.push(reminder.key);
      else if (outcome === "gone") {
        gone = true;
        break;
      } else summary.failed += 1;
    }

    if (gone) {
      await env.REMINDERS.delete(deviceKey(id));
      removed.push(id);
      continue;
    }

    summary.sent += sentKeys.length;
    const trimmed = removeExpired(record, now);
    const next = sentKeys.length > 0 ? markSent(trimmed, sentKeys, now) : trimmed;
    if (sentKeys.length > 0 || pruneDelta(record, trimmed) > 0) {
      await env.REMINDERS.put(deviceKey(id), JSON.stringify(next));
      summary.writes += 1;
    }
  }

  if (removed.length > 0) {
    summary.removed = removed.length;
    await env.REMINDERS.put(INDEX_KEY, JSON.stringify(ids.filter((id) => !removed.includes(id))));
    summary.writes += 1;
  }

  return summary;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    return handleFetch(request, env, Date.now());
  },
  async scheduled(controller: ScheduledController, env: Env): Promise<void> {
    const summary = await runTick(env, controller.scheduledTime);
    console.log(
      `tick devices=${summary.devices} sent=${summary.sent} failed=${summary.failed} ` +
        `removed=${summary.removed} writes=${summary.writes}`,
    );
  },
};
```

```ts
import { MAX_HORIZON_MS, MAX_INSTANTS } from "../../config/reminders";
import { instantOf } from "../dates";
import { projectedCalendar } from "../schedule/calendar";
import type { AppState, EpochMs, LocalDate, ReminderInstant } from "../types";

const MS_PER_MINUTE = 60_000; // milliseconds per minute

/**
 * Concrete push instants for the next `days` days, master plan §6.6.
 *
 * For every projected calendar day that has an availability slot, is not paused, and
 * has a projected session: one "day-of" instant at ReminderSettings.dayOfTime and one
 * instant `leadMinutes` before the slot's start time. Instants already in the past are
 * dropped. Wall-clock times are converted through dates.ts, so a DST transition inside
 * the window shifts the epoch value and leaves the local time alone.
 *
 * Returns [] when the profile, its availability, its plan, or its settings are missing,
 * or when reminders are disabled.
 */
export function computeReminderInstants(
  state: AppState,
  profileId: string,
  from: LocalDate,
  days: number,
  now: EpochMs,
): ReminderInstant[] {
  const profile = state.profiles[profileId];
  const settings = state.reminderSettings[profileId];
  const cursor = state.cursors[profileId];
  if (profile === undefined || settings === undefined || cursor === undefined) return [];
  if (!settings.enabled) return [];
  const plan = state.plans[cursor.planId];
  if (plan === undefined) return [];

  const timezone = profile.timezone;
  const totalSessions = plan.sessions.length;
  const leads = [...new Set(settings.leadMinutes)].sort((a, b) => b - a);
  // Upper bound in elapsed milliseconds, not in calendar days: a fall-back inside the
  // window makes 21 calendar days 21 d + 1 h, which the Worker would reject with 400.
  const horizonEnd = now + MAX_HORIZON_MS;

  const instants: ReminderInstant[] = [];
  for (const day of projectedCalendar(state, profileId, from, days)) {
    if (day.paused || day.slot === null || day.projectedSession === null) continue;
    const session = day.projectedSession;
    const slot = day.slot;
    const title = `${session.label} today`;
    const body = `${session.name} at ${slot.startTime}, session ${session.ordinal} of ${totalSessions}`;

    const dayOfAt = instantOf(day.date, settings.dayOfTime, timezone);
    if (dayOfAt > now && dayOfAt <= horizonEnd) {
      instants.push({ key: `${day.date}:day-of:0`, at: dayOfAt, title, body });
    }

    const slotAt = instantOf(day.date, slot.startTime, timezone);
    for (const lead of leads) {
      const at = slotAt - lead * MS_PER_MINUTE;
      if (at <= now || at > horizonEnd) continue;
      instants.push({ key: `${day.date}:lead:${lead}`, at, title, body });
    }
  }

  instants.sort((a, b) => (a.at === b.at ? a.key.localeCompare(b.key) : a.at - b.at));
  return instants.slice(0, MAX_INSTANTS);
}

/**
 * Order-independent 32-bit FNV-1a digest of a schedule, used only to decide whether
 * the Worker's copy is stale. It is a change detector, not a security primitive; a
 * collision would delay one re-upload until the six-hour staleness rule fires.
 */
export function scheduleHash(instants: ReminderInstant[]): string {
  const canonical = instants
    .map((i) => `${i.key}|${i.at}|${i.title}|${i.body}`)
    .sort()
    .join("\n");
  let hash = 0x811c9dc5;
  for (let index = 0; index < canonical.length; index += 1) {
    hash ^= canonical.charCodeAt(index);
    hash = Math.imul(hash, 0x01000193) >>> 0;
  }
  return hash.toString(16).padStart(8, "0");
}
```

**Why `subscribe` takes the stored device.** `pushManager.subscribe` returns the existing subscription when one is already registered. Minting a fresh `deviceId` in that case would orphan the previous Worker record, which would keep sending. When the endpoint matches the stored device, its id and secret are reused. `lastSyncAt` and `lastSyncHash` are always reset to `null` because `unsubscribe` has deleted the Worker record — the invariant is "after `subscribe`, the Worker holds nothing for this device".

**Why the sync has a six-hour floor.** A schedule whose hash is unchanged is still re-uploaded every six hours. The Worker prunes reminders as they expire, so a client that never re-uploads silently runs out of reminders after 21 days.

```ts
/**
 * Capability and installation detection. Kept apart from client.ts so the UA parsing
 * is a pure function of its arguments and can be tested without stubbing navigator.
 */

/** True when the runtime can register a service worker and receive Web Push. */
export function isPushSupported(): boolean {
  if (typeof window === "undefined" || typeof navigator === "undefined") return false;
  return "serviceWorker" in navigator && "PushManager" in window && "Notification" in window;
}

/**
 * iPadOS 13+ reports a desktop Macintosh user agent, so a touch-capable Mac UA is
 * treated as iOS. A real desktop Mac reports maxTouchPoints 0.
 */
export function isIosUserAgent(userAgent: string, maxTouchPoints: number): boolean {
  if (/iPad|iPhone|iPod/.test(userAgent)) return true;
  return /Macintosh/.test(userAgent) && maxTouchPoints > 1;
}

export function isIos(): boolean {
  if (typeof navigator === "undefined") return false;
  return isIosUserAgent(navigator.userAgent, navigator.maxTouchPoints);
}

/**
 * True when the page is running as an installed app. The media query covers Android
 * and modern iOS; navigator.standalone is the non-standard iOS Safari fallback and is
 * read through Reflect.get because it is not in the DOM type definitions.
 */
export function isInstalledPwa(): boolean {
  if (typeof window === "undefined") return false;
  if (window.matchMedia("(display-mode: standalone)").matches) return true;
  const legacy: unknown = Reflect.get(navigator, "standalone");
  return legacy === true;
}
```

```ts
import {
  MAX_HORIZON_MS,
  REMINDER_API_BASE,
  SCHEDULE_HORIZON_DAYS,
  SYNC_MAX_AGE_MS,
} from "../../config/reminders";
import { todayLocal } from "../dates";
import { newId } from "../ids";
import type { AppState, EpochMs, PushDevice } from "../types";
import { computeReminderInstants, scheduleHash } from "./instants";
import { isInstalledPwa, isIos, isPushSupported } from "./platform";

export type SubscribeFailure =
  | "unsupported"
  | "not-configured"
  | "not-installed"
  | "denied"
  | "failed";

export type SubscribeResult =
  | { ok: true; device: PushDevice }
  | { ok: false; reason: SubscribeFailure };

export type SyncResult =
  | { status: "unconfigured" }
  | { status: "no-device" }
  | { status: "disabled" }
  | { status: "unchanged" }
  | { status: "synced"; device: PushDevice }
  | { status: "failed"; error: string };

/** 32 random bytes, base64url, no padding: 43 characters. */
function randomSecret(): string {
  const bytes = new Uint8Array(32);
  crypto.getRandomValues(bytes);
  let binary = "";
  for (const byte of bytes) binary += String.fromCharCode(byte);
  return btoa(binary).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
}

function deviceUrl(deviceId: string): string | null {
  return REMINDER_API_BASE === null ? null : `${REMINDER_API_BASE}/v1/devices/${deviceId}`;
}

function readSubscriptionFields(
  json: ReturnType<PushSubscription["toJSON"]>,
): { endpoint: string; p256dh: string; auth: string } | null {
  const endpoint = json.endpoint;
  const p256dh = json.keys?.["p256dh"];
  const auth = json.keys?.["auth"];
  if (typeof endpoint !== "string" || typeof p256dh !== "string" || typeof auth !== "string") {
    return null;
  }
  return { endpoint, p256dh, auth };
}

/**
 * Register this device for Web Push.
 *
 * iOS refuses Web Push outside an installed Home Screen app (iOS 16.4+), so the
 * "not-installed" refusal comes before the permission prompt: prompting in a Safari
 * tab burns the user's one-shot permission decision for nothing.
 *
 * `existing` is the device already in the store, or null. When the browser hands back
 * a subscription with the same endpoint, its id and secret are reused so no orphan
 * record is left on the Worker. lastSyncAt/lastSyncHash are always reset, because a
 * subscribe means the Worker holds no record for this device yet.
 */
export async function subscribe(
  vapidPublicKey: string,
  existing: PushDevice | null,
  now: EpochMs,
): Promise<SubscribeResult> {
  if (!isPushSupported()) return { ok: false, reason: "unsupported" };
  if (isIos() && !isInstalledPwa()) return { ok: false, reason: "not-installed" };

  let permission: NotificationPermission;
  try {
    permission = await Notification.requestPermission();
  } catch {
    return { ok: false, reason: "failed" };
  }
  if (permission !== "granted") return { ok: false, reason: "denied" };

  try {
    const registration = await navigator.serviceWorker.ready;
    const current = await registration.pushManager.getSubscription();
    const subscription =
      current ??
      (await registration.pushManager.subscribe({
        userVisibleOnly: true,
        // MDN: applicationServerKey accepts a Base64-encoded string.
        applicationServerKey: vapidPublicKey,
      }));
    const fields = readSubscriptionFields(subscription.toJSON());
    if (fields === null) return { ok: false, reason: "failed" };

    const sameDevice = existing !== null && existing.endpoint === fields.endpoint;
    return {
      ok: true,
      device: {
        deviceId: sameDevice ? existing.deviceId : newId(),
        secret: sameDevice ? existing.secret : randomSecret(),
        endpoint: fields.endpoint,
        keys: { p256dh: fields.p256dh, auth: fields.auth },
        createdAt: sameDevice ? existing.createdAt : now,
        lastSyncAt: null,
        lastSyncHash: null,
      },
    };
  } catch {
    return { ok: false, reason: "failed" };
  }
}

/**
 * Upload the next SCHEDULE_HORIZON_DAYS days of instants when they differ from what
 * the Worker holds, or when the last upload is older than SYNC_MAX_AGE_MS. The Worker
 * prunes reminders as they expire, so the periodic re-upload is what keeps a device
 * that never changes its plan from running dry.
 */
export async function syncSchedule(
  state: AppState,
  profileId: string,
  now: EpochMs,
): Promise<SyncResult> {
  const device = state.pushDevice;
  const url = device === null ? null : deviceUrl(device.deviceId);
  if (device === null) return { status: "no-device" };
  if (url === null) return { status: "unconfigured" };

  const settings = state.reminderSettings[profileId];
  const profile = state.profiles[profileId];
  if (settings === undefined || profile === undefined) return { status: "disabled" };
  if (!settings.enabled) return { status: "disabled" };

  const from = todayLocal(profile.timezone, now);
  const instants = computeReminderInstants(state, profileId, from, SCHEDULE_HORIZON_DAYS, now);
  const hash = scheduleHash(instants);
  const stale = device.lastSyncAt === null || now - device.lastSyncAt > SYNC_MAX_AGE_MS;
  if (hash === device.lastSyncHash && !stale) return { status: "unchanged" };

  // Defence in depth: the Worker rejects the whole request if one instant is out of range.
  const withinWindow = instants.filter((i) => i.at > now - 60 * 60 * 1000 && i.at <= now + MAX_HORIZON_MS);

  let response: Response;
  try {
    response = await fetch(url, {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        secret: device.secret,
        subscription: { endpoint: device.endpoint, keys: device.keys },
        reminders: withinWindow,
      }),
    });
  } catch {
    return { status: "failed", error: "network" };
  }
  if (!response.ok) return { status: "failed", error: `HTTP ${response.status}` };

  return { status: "synced", device: { ...device, lastSyncAt: now, lastSyncHash: hash } };
}

/**
 * Delete the Worker record and drop the browser subscription. The local unsubscribe
 * runs even when the Worker call fails, so the user is never left receiving pushes
 * they switched off; the caller reports the error and the orphaned Worker record
 * expires on its own once its reminders run out.
 */
export async function unsubscribe(device: PushDevice): Promise<{ ok: boolean; error: string | null }> {
  let error: string | null = null;

  const url = deviceUrl(device.deviceId);
  if (url !== null) {
    try {
      const response = await fetch(url, {
        method: "DELETE",
        headers: { Authorization: `Bearer ${device.secret}` },
      });
      if (!response.ok) error = `HTTP ${response.status}`;
    } catch {
      error = "network";
    }
  }

  try {
    const registration = await navigator.serviceWorker.ready;
    const subscription = await registration.pushManager.getSubscription();
    if (subscription !== null) await subscription.unsubscribe();
  } catch {
    error = error ?? "local unsubscribe failed";
  }

  return { ok: error === null, error };
}
```

```ts
/**
 * Push payload parsing, shared by the service worker and its tests. No imports, so it
 * adds nothing to the service-worker bundle beyond these two functions.
 */

/** GitHub Pages project path; also the fallback click target. */
export const APP_SCOPE_PATH = "/FixThisInjustice/";

export interface PushPayload {
  title: string;
  body: string;
  tag: string;
  url: string;
}

/** Same-origin absolute path only. "//host" is a protocol-relative URL, not a path. */
function safePath(candidate: unknown): string | null {
  if (typeof candidate !== "string") return null;
  if (!candidate.startsWith("/") || candidate.startsWith("//")) return null;
  return candidate;
}

/**
 * Narrow a decrypted push payload. Returns null when there is no title, because a
 * notification with no title is not worth showing and iOS requires user-visible output.
 */
export function parsePushPayload(raw: unknown): PushPayload | null {
  if (typeof raw !== "object" || raw === null || Array.isArray(raw)) return null;
  const source: Record<string, unknown> = { ...raw };
  const title = source["title"];
  if (typeof title !== "string" || title.length === 0) return null;
  const body = source["body"];
  const tag = source["tag"];
  return {
    title,
    body: typeof body === "string" ? body : "",
    tag: typeof tag === "string" && tag.length > 0 ? tag : title,
    url: safePath(source["url"]) ?? APP_SCOPE_PATH,
  };
}

/** The path a notification click should open, read back from Notification.data. */
export function resolveClickUrl(data: unknown): string {
  if (typeof data !== "object" || data === null) return APP_SCOPE_PATH;
  return safePath(Reflect.get(data, "url")) ?? APP_SCOPE_PATH;
}
```

```ts
// The Worker sends { title, body, tag, url }. tag is the ReminderInstant key, so a
// re-sent reminder replaces the previous notification instead of stacking.

self.addEventListener("push", (event: PushEvent) => {
  let raw: unknown = null;
  try {
    raw = event.data === null ? null : event.data.json();
  } catch {
    raw = null;
  }
  const payload = parsePushPayload(raw);
  if (payload === null) return;

  event.waitUntil(
    self.registration.showNotification(payload.title, {
      body: payload.body,
      tag: payload.tag,
      data: { url: payload.url },
      icon: `${APP_SCOPE_PATH}icons/icon-192.png`,
      badge: `${APP_SCOPE_PATH}icons/icon-192.png`,
    }),
  );
});

self.addEventListener("notificationclick", (event: NotificationEvent) => {
  event.notification.close();
  const target = new URL(resolveClickUrl(event.notification.data), self.location.origin).href;
  event.waitUntil(focusOrOpen(target));
});

/** Focus an app window if one is open, otherwise open a new one. */
async function focusOrOpen(target: string): Promise<void> {
  const scope = new URL(APP_SCOPE_PATH, self.location.origin).href;
  const windows = await self.clients.matchAll({ type: "window", includeUncontrolled: true });
  for (const client of windows) {
    if (!client.url.startsWith(scope)) continue;
    await client.focus();
    if ("navigate" in client) await client.navigate(target);
    return;
  }
  await self.clients.openWindow(target);
}
```

```tsx
  const [permissionDenied, setPermissionDenied] = useState(false);

  const pushSchedule = useCallback(async (): Promise<void> => {
    if (profileId === null) return;
    const result = await syncSchedule(useAppStore.getState(), profileId, Date.now());
    if (result.status === "synced") setPushDevice(result.device);
  }, [profileId, setPushDevice]);

  const handleToggle = useCallback(
    (enabled: boolean): void => {
      if (profileId === null || VAPID_PUBLIC_KEY === null) return;
      setBusy(true);
      void (async () => {
        try {
          if (enabled) {
            const result = await subscribe(VAPID_PUBLIC_KEY, pushDevice, Date.now());
            if (!result.ok) {
              setPermissionDenied(result.reason === "denied");
              return;
            }
            setPermissionDenied(false);
            setPushDevice(result.device);
            setReminderSettings(profileId, { ...settings, enabled: true });
            await pushSchedule();
          } else {
            if (pushDevice !== null) await unsubscribe(pushDevice);
            setPushDevice(null);
            setReminderSettings(profileId, { ...settings, enabled: false });
          }
        } finally {
          setBusy(false);
        }
      })();
    },
    [profileId, pushDevice, pushSchedule, setPushDevice, setReminderSettings, settings],
  );

  const handleDayOfTime = useCallback(
    (time: LocalTime): void => {
      if (profileId === null) return;
      setReminderSettings(profileId, { ...settings, dayOfTime: time });
    },
    [profileId, setReminderSettings, settings],
  );

  const handleLeadToggle = useCallback(
    (minutes: number, on: boolean): void => {
      if (profileId === null) return;
      const next = on
        ? [...new Set([...settings.leadMinutes, minutes])].sort((a, b) => b - a)
        : settings.leadMinutes.filter((value) => value !== minutes);
      setReminderSettings(profileId, { ...settings, leadMinutes: next });
    },
    [profileId, setReminderSettings, settings],
  );

      status={currentStatus(settings.enabled, permissionDenied)}
      settings={settings}
      lastSyncAt={pushDevice?.lastSyncAt ?? null}
      timezone={profile.timezone}
      busy={busy}
      onToggle={handleToggle}
      onDayOfTimeChange={handleDayOfTime}
      onLeadToggle={handleLeadToggle}
    />
  );
```

```tsx
import { useEffect, useRef } from "react";
import { syncSchedule } from "../domain/reminders/client";
import { useAppStore } from "../store";

/** Collapse a burst of store writes (a logged set, a reshuffle) into one upload. */
const DEBOUNCE_MS = 2000;

/**
 * Effect-only component. Renders nothing; it keeps the Worker's copy of the schedule
 * in step with the store by syncing on mount, whenever the document becomes visible,
 * and (debounced) whenever any store slice changes. syncSchedule itself no-ops when
 * the schedule hash is unchanged and the last upload is under six hours old, so a
 * broad subscription costs one calendar projection per debounce window.
 */
export function ReminderSync(): null {
  const inFlight = useRef(false);
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => {
    let cancelled = false;

    const run = async (): Promise<void> => {
      if (inFlight.current || cancelled) return;
      const state = useAppStore.getState();
      const profileId = state.activeProfileId;
      if (profileId === null) return;
      inFlight.current = true;
      try {
        const result = await syncSchedule(state, profileId, Date.now());
        if (!cancelled && result.status === "synced") {
          useAppStore.getState().setPushDevice(result.device);
        }
      } finally {
        inFlight.current = false;
      }
    };

    const schedule = (): void => {
      if (timer.current !== null) clearTimeout(timer.current);
      timer.current = setTimeout(() => {
        timer.current = null;
        void run();
      }, DEBOUNCE_MS);
    };

    const onVisibility = (): void => {
      if (document.visibilityState === "visible") void run();
    };

    void run();
    document.addEventListener("visibilitychange", onVisibility);
    const unsubscribeStore = useAppStore.subscribe(schedule);

    return () => {
      cancelled = true;
      if (timer.current !== null) clearTimeout(timer.current);
      document.removeEventListener("visibilitychange", onVisibility);
      unsubscribeStore();
    };
  }, []);

  return null;
}
```

```ts
import { loadEnv, type Plugin } from "vite";
import * as videoInstances from "../src/config/videoInstances";

/** Turn "host", "https://host" or "https://host/path" into "https://host", or null. */
function toOrigin(raw: string): string | null {
  const candidate = raw.startsWith("https://") ? raw : `https://${raw}`;
  let origin: string | null = null;
  try {
    const url = new URL(candidate);
    origin = url.hostname.includes(".") ? url.origin : null;
  } catch {
    origin = null;
  }
  return origin;
}

/**
 * Every origin named anywhere in the video-instances module. Reading the whole module
 * namespace rather than one named export keeps frame-src and src/config/videoInstances.ts
 * from drifting apart, whatever that file chooses to call its export.
 */
export function collectOrigins(module: Record<string, unknown>): string[] {
  const found = new Set<string>();
  for (const value of Object.values(module)) {
    const candidates = typeof value === "string" ? [value] : Array.isArray(value) ? value : [];
    for (const candidate of candidates) {
      if (typeof candidate !== "string") continue;
      const origin = toOrigin(candidate);
      if (origin !== null) found.add(origin);
    }
  }
  return [...found].sort();
}

/** The deployed reminders Worker, reduced to an origin. Empty when the build had no var. */
export function workerConnectSrc(reminderApi: string | undefined): string[] {
  if (typeof reminderApi !== "string" || reminderApi.trim().length === 0) return [];
  const origin = toOrigin(reminderApi.trim());
  return origin === null ? [] : [origin];
}

export interface CspOptions {
  frameSrc: string[];
  connectSrc: string[];
}

/** Master plan §3, with connect-src narrowed from https://*.workers.dev to the real origin. */
export function buildCsp({ frameSrc, connectSrc }: CspOptions): string {
  const connect = ["'self'", ...connectSrc].join(" ");
  const frame = frameSrc.length === 0 ? "'none'" : frameSrc.join(" ");
  return [
    "default-src 'self'",
    "script-src 'self'",
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' data: blob:",
    "media-src 'self' blob:",
    "font-src 'self'",
    `connect-src ${connect}`,
    `frame-src ${frame}`,
    "worker-src 'self'",
    "base-uri 'none'",
    "form-action 'none'",
    "object-src 'none'",
  ].join("; ");
}

const CSP_META = /<meta\s+http-equiv="Content-Security-Policy"\s+content="[^"]*"\s*\/?>/i;

/**
 * Rewrites the CSP meta tag in index.html at build and dev time. GitHub Pages cannot
 * set response headers, so the meta tag is the only place the policy can live.
 */
export function cspPlugin(): Plugin {
  let reminderApi = "";
  let isBuild = false;

  return {
    name: "fti-csp",
    configResolved(resolved) {
      // loadEnv reads the .env files and then merges matching process.env entries over
      // them, so a variable supplied inline by CI wins and no Node typings are needed
      // here. (vite/src/node/env.ts: "merge them with the matching variables already
      // present in process.env".)
      const env = loadEnv(resolved.mode, resolved.root, "VITE_");
      reminderApi = env["VITE_REMINDER_API"] ?? "";
      isBuild = resolved.command === "build";
    },
    transformIndexHtml: {
      order: "post",
      handler(html) {
        const connectSrc = workerConnectSrc(reminderApi);
        if (isBuild && connectSrc.length === 0) {
          console.warn(
            "[fti-csp] VITE_REMINDER_API is unset or unparseable; connect-src will be 'self' " +
              "only and reminders will not reach the Worker from this build.",
          );
        }
        const csp = buildCsp({
          frameSrc: collectOrigins({ ...videoInstances }),
          connectSrc,
        });
        if (!CSP_META.test(html)) {
          throw new Error(
            "[fti-csp] no Content-Security-Policy meta tag found in index.html; refusing to " +
              "ship a page without a policy.",
          );
        }
        return html.replace(
          CSP_META,
          `<meta http-equiv="Content-Security-Policy" content="${csp}">`,
        );
      },
    },
  };
}
```

- [ ] **Step 5: Write the runbook**

Create `docs/RUNBOOK-reminders.md`:

````markdown
# Runbook: reminders (Cloudflare Worker + Web Push)

Deploying the reminders service is a one-off operator task. Everything here is done from
the repository root on a machine with Node 22 and a browser.

The Worker stores, per device, only a random secret, a push subscription, and the next
three weeks of reminder instants. No name, no body data, no location.

## 0. What you will end up with

| Thing | Where it lives | Public? |
| --- | --- | --- |
| Worker URL, e.g. `https://fti-reminders.<subdomain>.workers.dev` | GitHub repository variable `VITE_REMINDER_API` | yes |
| VAPID public key | GitHub repository variable `VITE_VAPID_PUBLIC_KEY`, and `wrangler.toml` `[vars] VAPID_PUBLIC_KEY` | yes |
| VAPID private key (JWK) | Cloudflare secret `VAPID_PRIVATE_JWK` | no; never commit it |
| KV namespace id | `worker/wrangler.toml` `[[kv_namespaces]] id` | yes |
| Pages origin, e.g. `https://<user>.github.io` | `wrangler.toml` `[vars] ALLOWED_ORIGIN` | yes |

## 1. Create a free Cloudflare account

1. Go to `https://dash.cloudflare.com/sign-up` and create an account with an email
   address and password. No payment method is required for the Workers Free plan.
2. Confirm the address from the verification email.

Free-plan limits this service runs inside: 100,000 requests/day, 5 Cron Triggers,
one-minute minimum cron granularity, 50 subrequests and 10 ms CPU per invocation, and
Workers KV at 100,000 reads/day, 1,000 writes/day, 1 GB.

## 2. Authenticate Wrangler

```bash
npx wrangler login
```

A browser window opens and asks you to authorise Wrangler. Confirm it worked:

```bash
npx wrangler whoami
```

Expected: your account email and account id.

## 3. Create the KV namespace

```bash
cd worker && npx wrangler kv namespace create REMINDERS
```

The command prints a namespace id. Paste it into `worker/wrangler.toml`, replacing
`REPLACE_WITH_KV_NAMESPACE_ID`:

```toml
[[kv_namespaces]]
binding = "REMINDERS"
id = "<the id the command printed>"
```

Check it took:

```bash
grep -A2 'kv_namespaces' worker/wrangler.toml
```

The `id` line must no longer contain the word `REPLACE`.

## 4. Generate the VAPID key pair

```bash
npx @pushforge/builder vapid
```

This prints a public key (a long base64url string) and a private key in JWK format.
Keep the terminal open; you need both in the next two steps. Generate the pair once.
Regenerating it invalidates every existing subscription, and every device has to
re-enable reminders.

## 5. Store the private key as a Worker secret

```bash
cd worker && npx wrangler secret put VAPID_PRIVATE_JWK
```

Paste the **entire JWK JSON object** on one line, including the braces, then press
Enter. The Worker passes this string straight to `@pushforge/builder`, which accepts a
JWK JSON string, so do not reformat it.

For local development instead:

```bash
cp worker/.dev.vars.example worker/.dev.vars
```

and edit `worker/.dev.vars`. That file is gitignored; never commit it.

## 6. Set the three plain variables

Edit `worker/wrangler.toml`:

```toml
[vars]
VAPID_PUBLIC_KEY = "<the public key from step 4>"
ADMIN_CONTACT = "mailto:<your email>"
ALLOWED_ORIGIN = "https://<your-github-username>.github.io"
```

`ADMIN_CONTACT` is the RFC 8292 contact the push service uses to reach you if your
sender misbehaves. `ALLOWED_ORIGIN` is the exact scheme-and-host of the Pages site,
with no trailing slash and no path.

## 7. Deploy

```bash
npm --prefix worker run deploy
```

Expected output ends with a `https://fti-reminders.<subdomain>.workers.dev` URL and a
line confirming the `* * * * *` schedule. Verify it is alive:

```bash
curl -s https://fti-reminders.<subdomain>.workers.dev/v1/health
```

Expected: `{"ok":true,"vapidPublicKey":"<the public key from step 4>"}`. If the key in
that response is not the one you generated, steps 4 and 6 disagree. Fix them before
going further, because pushes will fail silently otherwise.

Watch the cron run:

```bash
npm --prefix worker run tail
```

Within a minute you should see a `tick devices=0 sent=0 failed=0 removed=0 writes=0`
line. Stop with Ctrl-C.

## 8. Give the Pages build the two variables

In GitHub: **Settings → Secrets and variables → Actions → Variables tab → New
repository variable**. Add both:

| Name | Value |
| --- | --- |
| `VITE_REMINDER_API` | `https://fti-reminders.<subdomain>.workers.dev` (no trailing slash) |
| `VITE_VAPID_PUBLIC_KEY` | the public key from step 4 |

`deploy.yml` passes them to the build step. Re-run the deploy workflow, then confirm the
policy tightened:

```bash
curl -s https://<your-github-username>.github.io/FixThisInjustice/ | grep -o "connect-src [^;]*"
```

Expected: `connect-src 'self' https://fti-reminders.<subdomain>.workers.dev`. If it says
`connect-src 'self'` alone, the build ran without `VITE_REMINDER_API`.

## 9. Smoke test on a phone

Do this on the phone that will actually use the app. On iPhone this is not optional:
iOS delivers Web Push only to a web app installed on the Home Screen (iOS 16.4+), and
this app requires iOS 18.4 or later.

1. Open `https://<your-github-username>.github.io/FixThisInjustice/` in Safari (iPhone)
   or Chrome (Android).
2. iPhone: tap Share, then **Add to Home Screen**, then **Add**. Close Safari and open
   the app from the Home Screen icon. Android: accept the install prompt, or use the
   browser menu's **Install app**.
3. Go to **Settings → Reminders**. The status line must read `Reminders are off.`
   If it reads `Add this app to the Home Screen first.`, you are
   still in a browser tab; go back to step 2.
4. Turn on **Enable reminders** and allow notifications when the system asks.
5. The status line should become `Reminders are active. Schedule last sent at HH:MM.`
6. In **Settings → Availability**, add a slot on today's weekday starting **5 minutes
   from now**, and set the lead times to include **30 minutes before** so a lead instant
   also lands in the window.
7. Return to the Reminders panel and confirm the last-sent time updated within a few
   seconds. On a laptop, confirm the Worker received it:

   ```bash
   npm --prefix worker run tail
   ```

   You should see a tick line with `devices=1`.
8. Lock the phone and wait. The notification must arrive within about a minute of the
   instant. Tap it: the app opens (or comes to the front) on the Today view.
9. Confirm it arrives exactly once, with no repeat on the following minutes.

Record the outcome (device, OS version, browser, arrival delay) at the bottom of this
file so a later regression has a baseline to compare against.

## 10. Troubleshooting

| Symptom | Likely cause | Check | Fix |
| --- | --- | --- | --- |
| `wrangler deploy` fails with an invalid namespace id | step 3 not applied | `grep REPLACE worker/wrangler.toml` | paste the real id from `npx wrangler kv namespace create REMINDERS` |
| `/v1/health` returns a key you do not recognise | `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_JWK` came from different runs of step 4 | compare the two | regenerate the pair, redo steps 5, 6, 8; every device must re-enable |
| Settings shows `Reminders are not configured in this build.` | the Pages build had no `VITE_REMINDER_API` / `VITE_VAPID_PUBLIC_KEY` | `curl` the page and grep `connect-src` | add the repository variables (step 8) and re-run the deploy workflow |
| Settings shows `Add this app to the Home Screen…` on iPhone | running in a Safari tab | look for the browser chrome | install to the Home Screen and reopen from the icon |
| Settings shows `This browser cannot receive push notifications.` | no service worker or Push API | open the same page on another browser | use Safari on iOS 18.4+ or Chrome on Android |
| Enabling does nothing and the status stays `Reminders are off.` | permission prompt dismissed rather than granted | browser/system notification settings for the site | reset the site's notification permission and try again |
| Status stays `Reminders are on. Schedule not sent yet.` | the `PUT` failed | browser devtools network tab; `npm --prefix worker run tail` | a CSP `connect-src` violation means step 8 was skipped; a `403` means `ALLOWED_ORIGIN` does not match the Pages origin exactly |
| `PUT` returns 400 | an instant outside `[now − 1 h, now + 21 d]`, more than 200 instants, or a duplicate key | the JSON error body names the failing reminder index | usually a wrong device clock; check the phone's time and time zone |
| `PUT` returns 403 | the device id exists with a different secret | none | disable and re-enable reminders, which mints a new device |
| Tick log shows `devices=1` but no notification arrives | push accepted but not displayed | `npm --prefix worker run tail` for a `push rejected: status=…` line | `404`/`410` means the subscription died, so re-enable reminders; `429` is rate limiting, it retries on the next tick |
| Notification arrives more than once | two device records for one browser | `npm --prefix worker run tail` for two `devices=` entries | disable reminders, wait for the tick to report `devices=0`, re-enable |
| `wrangler tail` shows `Exceeded CPU limit` | more due pushes in one tick than the free plan's 10 ms CPU allows | count devices | stagger `dayOfTime` across devices, or move to the paid plan |
| Nothing at all in `wrangler tail` for minutes | cron not registered | `grep -A2 '\[triggers\]' worker/wrangler.toml` | confirm the file contains `crons = ["* * * * *"]`, then redeploy with `npm --prefix worker run deploy` |

## 11. Rolling back

```bash
cd worker && npx wrangler rollback
```

Reminders stop arriving; nothing else in the app is affected, because every other
feature works offline against local state.
````

**3. Type consistency.** Checked across tasks: `DeviceRecord`, `ReminderInstant`, `PushSubscriptionRecord`, `EpochMs` are defined once in `worker/src/schedule.ts` and imported everywhere else in the Worker; `PushEnv` is defined in `push.ts` and extended by `Env` in `index.ts`; `KvStore` is defined once and satisfied by the test stub; the payload field names `title`/`body`/`tag`/`url` are identical in `worker/src/push.ts` (writer) and `src/domain/reminders/payload.ts` (reader). `ReminderSettings` (type, `src/domain/types.ts`) and `ReminderSettingsPanel` (component) are deliberately different identifiers.

**4. What this plan does not do.**

- It does not test `src/sw.ts` itself. Service workers cannot be instantiated in jsdom, so the decisions were moved into `payload.ts`, which is tested, leaving two event registrations covered only by the build and the phone smoke test.
- It does not test the Worker against the real Workers runtime. All Worker tests are pure; `wrangler dev` (Task 4 Step 6) and the runbook smoke test are the only checks that the real KV binding and cron behave as typed. `Env.REMINDERS` is typed as the three methods used, so TypeScript does not prove the binding matches.
- It does not verify whether Cron Trigger invocations count against the free plan's 100,000 requests/day. Cloudflare's limits page does not say. At 1,440 ticks/day it is inside the cap either way.
- It does not measure the actual CPU cost of a tick against the free plan's 10 ms limit. VAPID signing and payload encryption are CPU work and scale with the number of due pushes in one minute; the runbook's troubleshooting table names the symptom, but no benchmark was run.
- It does not handle a device whose clock is wrong. A phone several hours off will have its whole upload rejected with `400`; the runbook names this, the app does not detect it.
- It does not implement Declarative Web Push (iOS 18.4+), which would render notifications without waking the service worker. The classic `push` handler works on both platforms and was kept for that reason.
- It does not add a rate limit to the Worker's HTTP surface. Anyone who learns a Worker URL can create device records up to the `MAX_DEVICES` cap; each record needs a valid push subscription to be useful, and the cap plus Cloudflare's own request limits are the only defence.
- It leaves `worker/` outside the root ESLint configuration. The Worker is checked by `tsc --noEmit` and Vitest only; the master plan's lint gates apply to `src/`.
- It does not touch P1–P4 files beyond the six single-line or single-block edits listed in the file structure section.

## Master plan amendments requested

Each item changes something the master plan states or omits. None changes a persisted type in §5.

1. **§6.6 — `GET /v1/health` response.** Contract says `{ ok: true }`; this plan returns `{ ok: true, vapidPublicKey: string }`. Reason: a mismatch between `VAPID_PUBLIC_KEY` (Worker var, client build var) and `VAPID_PRIVATE_JWK` (Worker secret) is the most likely deployment error and is otherwise invisible — pushes are accepted and never arrive. Echoing the public key makes it a one-command check, and the key is public by definition.
2. **§6.6 — push status mapping.** Contract implies `201` means sent. This plan treats `201` first and then any other `2xx` as sent. Reason: an outcome other than `"sent"` leaves the key out of `sent`, so a push service answering `200` would be re-sent on every tick for 15 minutes, breaking the §7 single-send gate.
3. **§6.6 — additional HTTP responses.** The contract lists `204`, `400`, `403`. This plan also returns `401` (no bearer secret on `DELETE`), `404` (malformed or unknown device id, unknown path), `405` (wrong method on a device path), `413` (body over 64 KB), and `503` (device index at the `MAX_DEVICES = 100` cap). All are refusals; none changes the success path.
4. **§6.6 — forward clamp in `computeReminderInstants`.** The contract says only "skip instants already in the past". Instants must also be clamped to `now + 21 d` **in milliseconds**: 21 calendar days spanning a daylight-saving fall-back are 21 d + 1 h of elapsed time, and one out-of-range instant makes the Worker reject the entire upload with `400`. The clamp is implemented and tested in Task 5.
5. **§4 file tree — files this plan adds that the tree does not list:** `src/config/env.d.ts`, `src/domain/reminders/platform.ts`, `src/domain/reminders/payload.ts`, `src/domain/reminders/state.fixture.ts` (test-only), `src/app/ReminderSync.tsx`, `build/cspPlugin.ts` (P1's CSP transform, which §4 describes but does not name), `worker/test/config.test.ts`, `worker/test/raw.d.ts`, `worker/.gitignore`.
6. **§4 — component export name.** `src/ui/reminders/ReminderSettings.tsx` exports `ReminderSettingsPanel`, not `ReminderSettings`, because the latter is already the persisted type name in §5.
7. **§4 — CI.** `.github/workflows/ci.yml` gains a `worker` job (`npm ci`, `npm run typecheck`, `npm test` in `worker/`), and `.github/workflows/deploy.yml`'s build step gains `VITE_REMINDER_API` and `VITE_VAPID_PUBLIC_KEY` from the repository `vars` context.
8. **§3 — CSP `connect-src`.** The baseline `connect-src 'self' https://*.workers.dev` is replaced at build time by `connect-src 'self' <exact Worker origin>`, and by `connect-src 'self'` alone when `VITE_REMINDER_API` is unset. A build without the variable therefore ships a page that cannot reach the Worker, which is the fail-closed behaviour but means the deploy workflow must carry the variable.
9. **Worker-internal, recorded for completeness:** `validatePut(body, now, existing)` takes the stored record as a third argument, because §6.6's "must present the same secret" cannot be checked without it; and the stored `sent` map is carried into the updated record, without which a client re-sync would clear the dedupe map and cause a second send.
10. **§1.7 and §6.6, push handling in the service worker.** Three things the contract leaves unstated. (a) `parsePushPayload` is total: it returns a `PushPayload` for every input and never `null`, and the `push` handler has no early return, so a delivered push always shows a notification, with the constant fallback title when the payload is malformed or absent. Reason: §1.7 records that Safari revokes the subscription after repeated silent pushes, and Chrome and Edge require `userVisibleOnly` on the subscription, so showing nothing costs the subscription rather than merely the reminder. (b) The service worker's length bounds are pinned to the Worker's, 100 for the title, 300 for the body and 120 for the tag, the last taken from `MAX_KEY_LENGTH` because `worker/src/push.ts` sends `tag: instant.key`. A tighter bound in the service worker does not shorten anything; it discards a payload the Worker already validated, replacing a real title with the generic fallback and collapsing two reminders that differ only by key into one notification. The three numbers are asserted against the Worker's source text in `payload.test.ts`, so the pairing cannot drift silently. (c) `WindowClient.navigate()` is called inside a try/catch. It rejects with a `TypeError` when the window is not controlled by this service worker, which is exactly the set of windows `matchAll({ includeUncontrolled: true })` is asked to return, and an unguarded rejection propagates through `event.waitUntil`, so `clients.openWindow` never runs and the click does nothing at all. On rejection the handler falls through to `openWindow`.
11. **Task 10 Step 1 — `env:` scope.** Step 1 says to add an `env:` block to the build **step**. That is wrong; the variables belong at **job** level, on `verify` in `ci.yml` and `build` in `deploy.yml`. `scripts/check-dist-csp.sh` (Task 9) reads `VITE_REMINDER_API` itself (line 35) and asserts that the built `connect-src` names exactly that origin (line 36), so a step-scoped variable is out of scope by the time that check runs and its assertion is inert. Measured 2026-09-02 on a `dist/index.html` whose `connect-src` is `'self'` alone: the script PASSes with the variable unset and FAILs with it set, which is the whole point of the check.
