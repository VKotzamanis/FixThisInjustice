# P3 Schedule Correctness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Weeks are graded against what they could hold, the Log grid and the session names come from the schedule model, training days are editable after setup, programme boundaries stop leaking verdicts and cut-scenes, and the setup wizard and intro stop losing or misreading what the user typed.

**Architecture:** One pro-rated expectation in `src/domain/schedule/quota.ts` (`expectedSessions` = min(weekly quota, preferred days inside the programme span that are not paused)) feeds the weekly grade (`weekly.ts`, which stores it on each review as `target`), one review verdict (`reviewVerdict`), and a new pure Log model (`compliance.ts`). Session titles are derived from position (`rotation.ts`), and the plot-twist window stops at the block boundary. A new store transition (`src/store/availability.ts`) grades ended weeks before storing edited availability, behind a Settings editor. The wizard keeps its two-tier draft but converts units, keeps the buffer on Previous, restores by step id, flushes on backgrounding, ignores hidden fields, and sits inside its own error boundary.

**Tech Stack:** React 19, TypeScript 5.9 (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), Vite 8, Zustand 5, Zod 4, date-fns 4 + @date-fns/tz, Vitest 4 + Testing Library (jsdom), Playwright 1.63 (Chromium, `iphone13` + `pixel7` emulation).

**Spec:** `docs/plans/2026-11-04-aaa-rebuild-spec.md` (phase P3 line; rulings R2, R3, R5, R12) EXCEPT R11/D07/D08 (exercise library, branch `p3a-library`, plan `docs/plans/2026-11-04-p3a-library.md`). Audit evidence: `docs/private/audit-2026-11-04/D-schedule.md` (D03, D05, D06, D09-D13, D15, D16) and `A-onboarding.md` (A04-A07, A09, A12, A13; A17 is in the spec's P3 line). ## Rulings this plan makes (each names the rejected alternative)

- PR-1 Pro-rate, not exempt. `target` of a week = `expectedSessions(week)` = min(quota, preferred weekdays in [Monday, Sunday] that are inside [cursor.startedOn, cursor.completedOn] and not paused). A day before `startedOn` that still carries a kept finished row (ROADMAP B1d start week) is inside the span. Rejected: exempting partial weeks (a first week begun on Wednesday with two missed sessions would grade nothing); grading `completed` against the raw quota (D03).
- PR-2 `paused` stays on the review as a fact; it no longer zeroes `delta`. One verdict function `reviewVerdict` decides missed / met / none for the popup, the stamp, the intervention and the Today ticker. Legacy paused reviews (`paused: true, delta: 0`, target = full quota) read as `none` because `completed < target` and `delta = 0`. Rejected: keep "any pause excuses the week" (D10).
- PR-3 History (D16): a stored review is never recomputed (closeWeeks skips reviewed weeks; the grid reads the stored `target`). The availability editor grades every ended week BEFORE storing new days. Rejected: a target-history array on Availability (schema growth for the one backlog case that closeWeeks-before-write already covers; a week held open by AM-6 is graded with the new days, stated in the code comment).
- PR-4 Log grid: seven columns Monday-Sunday (any day is trainable, R3; a make-up Tuesday must be visible). Misses are counted, not inferred per cell: owed = max(0, target - completed) for a graded week, expectation up to yesterday for the running week; marked on the earliest unserved preferred days. A past postponed day is judged like any past day (`cursor.postponed` is pruned to today and later, so a past postponement is not reliably recorded). Rejected: "every past preferred day without a completion is missed" (marks three misses on a Mon/Wed/Fri target-2 week with one missing session).
- PR-5 Session title = "Week N <label>" with N from the session's position (ordinal), not `PlannedSession.name`. Same format the generator bakes, so an unswapped plan reads unchanged; a swapped or legacy one stops lying. `name` stays in the data (old documents, `sameProgramme`). Rejected: drop the week from the title (loses the programme position the owner reads on Today).
- PR-6 Plot twist (D15): the window ends at the last index of the block the cursor stands in; inside one block a swap moves only the rotation label, deloads stay positional. Rejected: swapping across blocks with renamed sessions (the deload would still follow position, but the block's label multiset would change).
- PR-7 Phase-transition marker (D13): new optional `ui.lastBlockSeenByPlan` keyed by plan id; `applyReplacePlan` seeds the new plan at 0; the gate reads by plan with the legacy per-profile value as fallback and writes both. Rejected: resetting `lastBlockSeenByProfile` in `applyReplacePlan` only (works, but the brief asks for a plan key, and an older deployed build reading a new document still finds a per-profile value).
- PR-8 Wizard units (A04): switching units converts body mass, target mass, girths and stature to the new unit (mass and girths to 0.1, stature to whole cm / whole inches, the wizard's own integer-only rule); load steps keep the existing reseed to the new unit's defaults (a converted 2.5 kg step is 5.51 lb, a plate nobody owns). Rejected: blocking the unit change after Body (the user could not correct a wrong first answer).
- PR-9 Previous keeps the step buffer (A05); only Next commits. Rejected: an "Undo changes" control (YAGNI; nothing in the audit asks for it).
- PR-10 Draft restore (A06): persist `stepId` beside `stepIndex`; restore by id, else clamp the index to the last step. The schema bound `MAX_SETUP_DRAFT_STEP_INDEX` stays 8 (lowering it to 7 would make `.catch(null)` drop a stored draft at 8, rule 7); only its stale comment is corrected.
- PR-11 Wizard boundary (A12): a local error boundary around the wizard with Restart Setup (clears `setupDraft` only, then remounts) and Reload; the root boundary gains Reload. Rejected: retry without clearing (a deterministic throw from the draft repeats).
- PR-12 Intro (A13): the first tap or Enter/Space/ArrowRight completes the typing, the next advances; other keys do nothing; Settings gains Replay Intro (sets `ui.introSeen` false). // src/domain/schedule/quota.ts
```ts
//
// The weekly session quota and its pro-rated expectation (AM-5, P3 D03/D10/D16). ONE quota
// feeds the forecast (calendar.ts), the weekly grade (weekly.ts) and the Log grid
// (compliance.ts), so the three can never disagree about how many sessions a week asks for.
//
// Every date is a LocalDate in the profile's zone. Counts are [sessions] or [days].

import { addDays, compareLocalDate, isoWeekday } from '../dates';
import { isPaused } from './cursor';
import type { AppState, IsoWeekday, LocalDate } from '../types';

/**
 * The slices the schedule reads. Every AppState is one; the Log view builds one from the slices
 * it subscribes to, so a memo keyed on them recomputes exactly when the schedule changes.
 */
export type ScheduleState = Pick<AppState, 'availability' | 'cursors' | 'plans' | 'pauses' | 'assignments'>;

/** [sessions/week] One availability target for the forecast and weekly grading (AM-5). */
export function weeklyQuota(state: ScheduleState, profileId: string): number {
  return state.availability[profileId]?.weeklySessionTarget ?? 0;
}

/** The distinct ISO weekdays the profile prefers to train on (one per availability slot). */
export function preferredWeekdays(state: ScheduleState, profileId: string): ReadonlySet<IsoWeekday> {
  return new Set((state.availability[profileId]?.slots ?? []).map((slot) => slot.weekday));
}

/**
 * [days] Preferred days in the inclusive range [from, to] that the programme can ask for: inside
 * the programme span [cursor.startedOn, cursor.completedOn] (open-ended while it runs) and not
 * paused. 0 with no cursor or an empty range.
 *
 * A day before startedOn that still carries a finished row counts as inside the span: those are
 * the start week's days trained under the plan a restart replaced (applyReplacePlan keeps them,
 * ROADMAP B1d), and closeWeeks counts their completions, so the expectation must count their
 * days too or a restart week would be graded on more sessions than days.
 */
export function askableDays(
  state: ScheduleState,
  profileId: string,
  from: LocalDate,
  to: LocalDate,
): number {
  const cursor = state.cursors[profileId];
  if (cursor === undefined) return 0;
  const preferred = preferredWeekdays(state, profileId);
  const pauses = state.pauses[profileId] ?? [];
  const recorded = new Set((state.assignments[profileId] ?? []).map((a) => a.date));
  let n = 0; // [days]
  for (let d = from; compareLocalDate(d, to) <= 0; d = addDays(d, 1)) {
    if (compareLocalDate(d, cursor.startedOn) < 0 && !recorded.has(d)) continue;
    if (cursor.completedOn !== null && compareLocalDate(d, cursor.completedOn) > 0) continue;
    if (!preferred.has(isoWeekday(d))) continue;
    if (isPaused(pauses, d)) continue;
    n += 1;
  }
  return n;
}

/**
 * [sessions] What the range [from, to] (inside one ISO week) can fairly ask for: the weekly
 * quota, pro-rated to the preferred days the programme actually spanned, unpaused.
 * expected = min(quota, askableDays). A first week begun on Wednesday, a final week that ended
 * on Monday and a week with a pause in it are each graded against what they could hold (D03,
 * D10), never against the full quota.
 */
export function expectedSessions(
  state: ScheduleState,
  profileId: string,
  from: LocalDate,
  to: LocalDate,
): number {
  return Math.min(weeklyQuota(state, profileId), askableDays(state, profileId, from, to));
}
```

```ts
// src/domain/schedule/compliance.ts
//
// The Log compliance grid, derived from the schedule model rather than from which rows happen to
// exist (audit D06). Assignments are materialised only when the user opens a day, so "no row"
// meant nothing; this module answers what each day WAS or IS for the programme:
//
//   completed / skipped / in-progress   a recorded row, shown as recorded
//   missed      a past preferred day the week still owed a session for (see below)
//   planned     today or later, and the forecast serves a session on it
//   postponed   today or later, handed back by Skip Today (spec R2)
//   paused      inside a pause
//   none        nothing was asked of the day (a rest day, or the quota was already met)
//   blank       outside the programme's span [startedOn, completedOn]
//
// Misses are COUNTED, not inferred per day: a past week owes max(0, target - completed)
// sessions, where target is the stored review's (D16: never regraded) or, for the running week,
// the pro-rated expectation up to yesterday (quota.ts). The owed misses are marked on the
// earliest unserved preferred days. A made-up session (trained on another day) therefore clears
// a miss, and a week whose quota was met shows no miss even with a preferred day left empty.
//
// Pure: no clock (the caller passes its civil today), no store.

import { addDays, compareLocalDate, daysBetween, isoWeekday } from '../dates';
import { projectedCalendar } from './calendar';
import { isPaused } from './cursor';
import { expectedSessions, preferredWeekdays, type ScheduleState } from './quota';
import type { AppState, LocalDate } from '../types';

export type DayMark =
  | 'completed'
  | 'skipped'
  | 'in-progress'
  | 'missed'
  | 'planned'
  | 'postponed'
  | 'paused'
  | 'none'
  | 'blank';

export interface ComplianceDay {
  date: LocalDate;
  mark: DayMark;
}

export interface ComplianceWeek {
  /** Monday of the ISO week. */
  monday: LocalDate;
  completed: number; // [sessions]
  /** The stored review's target once the week is graded, else the pro-rated expectation. */
  target: number; // [sessions/week]
  /** Monday..Sunday, seven entries. */
  days: ComplianceDay[];
}

export type ComplianceSource = ScheduleState & Pick<AppState, 'weeklyReviews'>;

/** [d] Days in an ISO week. */
const WEEK_DAYS = 7;

export function complianceWeek(
  state: ComplianceSource,
  profileId: string,
  monday: LocalDate,
  today: LocalDate,
): ComplianceWeek {
  const sunday = addDays(monday, WEEK_DAYS - 1);
  const cursor = state.cursors[profileId];
  const rows = new Map<LocalDate, string>();
  let completed = 0; // [sessions]
  for (const a of state.assignments[profileId] ?? []) {
    if (compareLocalDate(a.date, monday) < 0 || compareLocalDate(a.date, sunday) > 0) continue;
    rows.set(a.date, a.status);
    if (a.status === 'completed') completed += 1;
  }
  const review = (state.weeklyReviews[profileId] ?? []).find((r) => r.weekStart === monday) ?? null;
  const target = review?.target ?? expectedSessions(state, profileId, monday, sunday); // [sessions/week]

  // [sessions] owed by the days that have passed: the stored grade, or the expectation up to
  // yesterday for the running week.
  const yesterday = addDays(today, -1);
  const lastPast = compareLocalDate(yesterday, sunday) < 0 ? yesterday : sunday;
  const owedPast =
    review !== null
      ? review.target
      : compareLocalDate(lastPast, monday) < 0
        ? 0
        : expectedSessions(state, profileId, monday, lastPast);
  let missesLeft = Math.max(0, owedPast - completed); // [sessions]

  // The forecast for today and later, from the projection itself (rule 2).
  const served = new Set<LocalDate>();
  if (compareLocalDate(today, sunday) <= 0) {
    const from = compareLocalDate(today, monday) > 0 ? today : monday;
    const span = daysBetween(from, sunday) + 1; // [d] from..Sunday inclusive
    for (const day of projectedCalendar(state, profileId, from, span)) {
      if (day.assignment === null && day.projectedSession !== null) served.add(day.date);
    }
  }
  const postponed = new Set<LocalDate>(cursor?.postponed ?? []);
  const preferred = preferredWeekdays(state, profileId);
  const pauses = state.pauses[profileId] ?? [];

  const days: ComplianceDay[] = [];
  for (let i = 0; i < WEEK_DAYS; i += 1) {
    const date = addDays(monday, i); // [d]
    const status = rows.get(date);
    let mark: DayMark;
    if (status === 'completed' || status === 'skipped' || status === 'in-progress') {
      mark = status;
    } else if (status === 'planned') {
      mark = compareLocalDate(date, today) < 0 ? 'missed' : 'planned';
    } else if (
      cursor === undefined ||
      compareLocalDate(date, cursor.startedOn) < 0 ||
      (cursor.completedOn !== null && compareLocalDate(date, cursor.completedOn) > 0)
    ) {
      mark = 'blank';
    } else if (isPaused(pauses, date)) {
      mark = 'paused';
    } else if (compareLocalDate(date, today) >= 0) {
      mark = postponed.has(date) ? 'postponed' : served.has(date) ? 'planned' : 'none';
    } else if (preferred.has(isoWeekday(date)) && missesLeft > 0) {
      mark = 'missed';
      missesLeft -= 1;
    } else {
      mark = 'none';
    }
    days.push({ date, mark });
  }
  return { monday, completed, target, days };
}
```

```tsx
// src/ui/settings/AvailabilitySettings.tsx
//
// Training days, start times and the weekly target after setup (audit D05). Before this, the
// only way to change them was Wipe All. Calendar only: the running plan and its cursor are not
// touched (docs/design/programme-lifecycle.md keeps re-planning behind Update Programme).
//
// The form is local until Save Days; Save goes through the store's updateAvailability, which
// grades every ended week under the old days first (D16) and parses the new availability with
// the loader's schema (spec R5). A refusal is shown here, beside the control that raised it.
import { useState, type JSX } from 'react';
import { FORMAT } from '../../content/copy';
import { useCopy } from '../../content/useCopy';
import { isValidLocalTime } from '../../domain/dates';
import type { Availability, IsoWeekday, Profile, Seconds } from '../../domain/types';
import { useAppStore } from '../../store';
import { displayClass } from '../format/display';
import { WEEKDAYS } from '../setup/SetupWizard';

interface DayRow {
  enabled: boolean;
  startTime: string; // "HH:mm" in the profile's zone, as typed
}

type DayRows = Record<IsoWeekday, DayRow>;

/** The stored slots as one row per weekday; an unused day starts at the first slot's time. */
function rowsOf(a: Availability): DayRows {
  const fallback = a.slots[0]?.startTime ?? '';
  const rows = {} as DayRows;
  for (const d of WEEKDAYS) {
    const slot = a.slots.find((s) => s.weekday === d.value);
    rows[d.value] = { enabled: slot !== undefined, startTime: slot?.startTime ?? fallback };
  }
  return rows;
}

/**
 * [s] The expected duration a day keeps: its own slot's, else the first slot's. The editor does
 * not ask for durations (the wizard does); a newly added day inherits the one already chosen.
 */
function durationOf(a: Availability, weekday: IsoWeekday): Seconds {
  return (a.slots.find((s) => s.weekday === weekday) ?? a.slots[0])?.expectedDurationS ?? 0;
}

export function AvailabilitySettings(props: { profile: Profile }): JSX.Element | null {
  const stored = useAppStore((s) => s.availability[props.profile.id] ?? null);
  if (stored === null) return null;
  // Keyed by the stored value, so a successful save (or an import) reseeds the form from it.
  return <AvailabilityForm key={JSON.stringify(stored)} profileId={props.profile.id} stored={stored} />;
}

function AvailabilityForm(props: { profileId: string; stored: Availability }): JSX.Element {
  const t = useCopy();
  const { profileId, stored } = props;
  const [days, setDays] = useState<DayRows>(() => rowsOf(stored));
  const [target, setTarget] = useState<number>(stored.weeklySessionTarget); // [sessions/week]
  const [refused, setRefused] = useState(false);

  const enabled = WEEKDAYS.filter((d) => days[d.value].enabled);
  // [sessions/week] bounded by the days, as AvailabilitySchema requires; shown and saved as one.
  const shownTarget = Math.max(1, Math.min(target, enabled.length));
  const dayError = enabled.length === 0 ? t('error.pickOneDay') : null;
  const timeError = (weekday: IsoWeekday): string | null =>
    isValidLocalTime(days[weekday].startTime) ? null : t('error.startTimeRequired');
  const valid = dayError === null && enabled.every((d) => timeError(d.value) === null);

  const candidate: Availability = {
    slots: enabled.map((d) => ({
      weekday: d.value,
      startTime: days[d.value].startTime,
      expectedDurationS: durationOf(stored, d.value), // [s]
    })),
    weeklySessionTarget: shownTarget, // [sessions/week]
  };
  const changed = JSON.stringify(candidate) !== JSON.stringify(stored);

  const patchDay = (weekday: IsoWeekday, next: Partial<DayRow>): void => {
    setRefused(false);
    setDays((rows) => ({ ...rows, [weekday]: { ...rows[weekday], ...next } }));
  };

  const onSave = (): void => {
    try {
      useAppStore.getState().updateAvailability(profileId, candidate, Date.now()); // [ms] epoch, UTC
    } catch {
      // The store wrote nothing (spec R5); say so here rather than letting the throw escape.
      setRefused(true);
    }
  };

  return (
    <>
      <h2 className={displayClass(t('hero.trainingDays'))}>{t('hero.trainingDays')}</h2>
      <p className="view-note">{t('advice.trainingDaysCalendarOnly')}</p>
      {WEEKDAYS.map((d) => (
        <div key={d.value}>
          <label className="view-inline">
            <input
              id={`avail-day-${String(d.value)}`}
              type="checkbox"
              checked={days[d.value].enabled}
              onChange={(e) => {
                patchDay(d.value, { enabled: e.target.checked });
              }}
            />
            {t(d.labelKey)}
          </label>
          {days[d.value].enabled && (
            <div className="view-field">
              <label htmlFor={`avail-start-${String(d.value)}`}>
                {FORMAT.slotField(t(d.labelKey), t('label.startTime'))}
              </label>
              <input
                id={`avail-start-${String(d.value)}`}
                type="time"
                required
                aria-invalid={timeError(d.value) !== null}
                value={days[d.value].startTime}
                onChange={(e) => {
                  patchDay(d.value, { startTime: e.target.value });
                }}
              />
              {timeError(d.value) !== null && <p className="view-error">{timeError(d.value)}</p>}
            </div>
          )}
        </div>
      ))}
      {dayError !== null && <p className="view-error">{dayError}</p>}
      <div className="view-field">
        <label htmlFor="avail-target">{t('quantity.weeklySessionTarget')}</label>
        <select
          id="avail-target"
          value={String(shownTarget)}
          onChange={(e) => {
            setRefused(false);
            setTarget(Number(e.target.value));
          }}
        >
          {Array.from({ length: Math.max(1, enabled.length) }, (_, i) => i + 1).map((n) => (
            <option key={n} value={String(n)}>
              {n}
            </option>
          ))}
        </select>
      </div>
      <button type="button" id="avail-save" disabled={!valid || !changed} onClick={onSave}>
        {t('button.saveTrainingDays')}
      </button>
      {refused && (
        <p className="view-error" role="alert">
          {t('error.availabilityRefused')}
        </p>
      )}
    </>
  );
}
```

```ts
// src/domain/schedule/rotation.ts
//
// What a session is CALLED, derived from where it stands (audit D09, D15). A session is a
// rotation label (Upper A, Full body C) at a plan position; its programme week is a fact about
// the position, never about the name baked into the plan at generation. assignToday's swap
// moves labels between positions and rewrites ordinals, so a baked "Week 4 Full body B" landed
// in week 3; reading the week from the position cannot.
//
// The title format is the generator's own (src/domain/plan/generator.ts, copy contract R2:
// "Week 12 Upper A"); rotation.test.ts pins sessionTitle to every generated name (rule 2).

import type { PlannedSession, PlanTemplate } from '../types';

/**
 * [weeks] 1-based programme week of the session at `sessionIndex` (0-based position in
 * plan.sessions). A plan with no weekly rate is one undivided week.
 */
export function programmeWeekOf(plan: Pick<PlanTemplate, 'sessionsPerWeek'>, sessionIndex: number): number {
  if (plan.sessionsPerWeek <= 0) return 1;
  return Math.floor(Math.max(0, sessionIndex) / plan.sessionsPerWeek) + 1;
}

/**
 * "Week N <label>", with N from the session's position (ordinal - 1; the invariant
 * plan.sessions[i].ordinal === i + 1 is kept by every writer, including assignToday).
 */
export function sessionTitle(
  plan: Pick<PlanTemplate, 'sessionsPerWeek'>,
  session: Pick<PlannedSession, 'ordinal' | 'label'>,
): string {
  return `Week ${String(programmeWeekOf(plan, session.ordinal - 1))} ${session.label}`;
}
```

```ts
// src/ui/setup/unitSwitch.ts

// Audit A04: the wizard keeps typed quantities as text in the unit chosen on the first step, so
// switching units used to REINTERPRET them: 80 kg became "80 lb" (36.3 kg) and every target was
// computed from it. Switching now converts what was typed into the new unit (plan ruling PR-8).
// Text that does not parse is left exactly as typed; the field's own validator still reports it.

import { CM_PER_IN, displayGirth, displayMass, toStoredGirthCm, toStoredMass } from '../../domain/units';
import type { SetupAnswers, UnitSystem } from '../../domain/types';
import { parseDecimal } from '../components/UnitInput';

const CM_PER_M = 100; // [cm/m]
const IN_PER_FT = 12; // [in/ft]

/** The typed fields whose meaning depends on the unit system. Load steps are re-seeded instead. */
export type UnitBoundAnswers = Pick<
  SetupAnswers,
  'mass' | 'targetMass' | 'neck' | 'waist' | 'hip' | 'heightM' | 'heightCm' | 'heightFt' | 'heightIn'
>;

/** A body mass typed in `from`, shown in `to` at 0.1 resolution ([kg] or [lb]). */
function massText(text: string, from: UnitSystem, to: UnitSystem): string {
  const entered = parseDecimal(text);
  return entered === null ? text : String(displayMass(toStoredMass(entered, from), to));
}

/** A girth typed in `from`, shown in `to` at 0.1 resolution ([cm] or [in]). */
function girthText(text: string, from: UnitSystem, to: UnitSystem): string {
  const entered = parseDecimal(text);
  return entered === null ? text : String(displayGirth(toStoredGirthCm(entered, from), to));
}

/** [cm] Stature from the pair of fields of `units`, or null when both are blank. */
function statureCm(a: UnitBoundAnswers, units: UnitSystem): number | null {
  if (units === 'metric') {
    const metres = parseDecimal(a.heightM);
    const centimetres = parseDecimal(a.heightCm);
    if (metres === null && centimetres === null) return null;
    return (metres ?? 0) * CM_PER_M + (centimetres ?? 0); // [cm]
  }
  const feet = parseDecimal(a.heightFt);
  const inches = parseDecimal(a.heightIn);
  if (feet === null && inches === null) return null;
  return ((feet ?? 0) * IN_PER_FT + (inches ?? 0)) * CM_PER_IN; // [cm]
}

/**
 * The unit-bound answers re-expressed in `to`. Stature is whole numbers only, as the wizard
 * requires ("ONLY integers", round 1 C1.07.21): whole inches or whole centimetres.
 */
export function convertBodyAnswers(a: SetupAnswers, to: UnitSystem): UnitBoundAnswers {
  const from = a.units;
  const same: UnitBoundAnswers = {
    mass: a.mass,
    targetMass: a.targetMass,
    neck: a.neck,
    waist: a.waist,
    hip: a.hip,
    heightM: a.heightM,
    heightCm: a.heightCm,
    heightFt: a.heightFt,
    heightIn: a.heightIn,
  };
  if (from === to) return same;
  const cm = statureCm(same, from); // [cm]
  let height = {};
```

```tsx
// src/ui/setup/SetupErrorBoundary.tsx
//
// Audit A12: a render throw anywhere in the setup wizard used to reach the ROOT boundary, whose
// only way out is Clear (every logged session with it) and which has no reload on an installed
// iOS app. The persisted draft survived, so a throw caused by the draft repeated on every launch.
// This boundary sits around the wizard alone: Restart Setup clears the draft only and remounts
// the wizard from scratch; Reload is there for a throw that was not the draft's fault.
import { Component, Fragment, type ErrorInfo, type JSX, type ReactNode } from 'react';
import { useCopy } from '../../content/useCopy';
import { useAppStore } from '../../store';

interface Props {
  children: ReactNode;
  /** Injected by tests; the app reloads the page. */
  onReload?: () => void;
}

interface State {
  failed: boolean;
  /** Bumped on Restart Setup, so the wizard remounts and re-reads the (now empty) draft. */
  attempt: number;
}

export class SetupErrorBoundary extends Component<Props, State> {
  public override state: State = { failed: false, attempt: 0 };

  public static getDerivedStateFromError(): Partial<State> {
    return { failed: true };
  }

  public override componentDidCatch(error: unknown, info: ErrorInfo): void {
    // Development only, as in RootErrorBoundary: tree-shaken from the production bundle.
    if (import.meta.env.DEV) {
      console.error('SetupErrorBoundary caught', error, info.componentStack);
    }
  }

  private readonly restart = (): void => {
    useAppStore.getState().clearSetupDraft();
    this.setState((s) => ({ failed: false, attempt: s.attempt + 1 }));
  };

  private readonly reload = (): void => {
    if (this.props.onReload !== undefined) {
      this.props.onReload();
      return;
    }
    window.location.reload();
  };

  public override render(): ReactNode {
    if (!this.state.failed) {
      return <Fragment key={this.state.attempt}>{this.props.children}</Fragment>;
    }
    return <SetupFailed onRestart={this.restart} onReload={this.reload} />;
  }
}

function SetupFailed(props: { onRestart: () => void; onReload: () => void }): JSX.Element {
  const t = useCopy();
  return (
    <div className="wiz" role="alert">
      <h2>{t('hero.setupFailed')}</h2>
      <p className="wiz-note">{t('advice.setupRestartClearsDraft')}</p>
      <div className="wiz-nav">
        <button type="button" onClick={props.onRestart}>
          {t('button.restartSetup')}
        </button>
        <button type="button" onClick={props.onReload}>
          {t('button.reload')}
        </button>
      </div>
    </div>
  );
}
```
