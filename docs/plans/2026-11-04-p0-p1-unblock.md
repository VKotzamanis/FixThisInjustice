# P0 harness + P1 unblock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phone-emulated end-to-end tests that reproduce the owner's week of bugs, then the fixes that turn every one of them green: a session left open overnight never blocks the schedule, Skip postpones, any day is trainable, decimal commas are parsed, the store refuses documents it could not reload, and a refused document opens a recovery screen instead of first-run setup.

**Architecture:** P0 adds Playwright (Chromium only, `iphone13` + `pixel7` device emulation, one worker, fixed clock in the profile's zone) driving a fresh production build, plus one failing repro spec per owner/S1 bug, each marked `test.fail()` so the suite stays green; the task that fixes a bug deletes that marker. P1 lands domain first (additive schema fields, pure stale-session closer, postpone, quota forecast), then store wiring (persisted rest, boundary validation, set-slot uniqueness, `storage`-event stopgap), then UI (Today, Train, NumericField, wizard, intro CSS, recovery screen).

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, Zustand 5, Zod 4, date-fns 4 + @date-fns/tz, Vitest 4, @playwright/test 1.63.0 (bundles Chromium revision 1243).

**Spec:** `docs/plans/2026-11-04-aaa-rebuild-spec.md` (rulings R1-R5, R12; phases P0 and P1). Audit finding IDs (A01, B03, C02, D01 ...) refer to `docs/private/audit-2026-11-04/` (gitignored, this laptop only).

## Global Constraints

- AGENTS.md rules 1-10 and its Verify block apply to every task.
- Rule 1: never invent a citation, dose or coefficient. The only new numeric constants in this plan are engineering bounds (grace period, plausibility ratio from spec R4, sanity ceilings); each carries its unit and its source in a comment.
- Rule 2: derive, never copy. A constant in two places is derived from one, or one test reads both.
- Rule 3: stage with pathspecs (`git add -- <files>`), never `git add -A`.
- Rule 5: colours only through tokens in `src/ui/styles/tokens.css`; no hex in component CSS.
- Rule 6: only `src/store/persistence.ts` touches web storage from app code (`src/store/sessionMirror.ts` owns sessionStorage); `toISOString()` only in `src/domain/dates.ts`. `e2e/` is a harness, not app code (Task 1 lifts the storage ban there only).
- Rule 7 (spec): old `fti.v3` documents and old exports load unchanged. Schema changes in this plan are additive OPTIONAL fields only; no new enum value anywhere (an unknown enum value makes an older deployed build refuse the whole document, audit B06). `CURRENT_SCHEMA_VERSION` stays 3.
- Wording is out of scope (owner: "Do not focus on the text"). New copy keys only where a control or notice needs one: base table `src/content/copy.ts` only, never `copy.limelight.ts`; `button.`/`label.`/`hero.` values in Title Case; a button is at most 3 words, a hero at most 8, an advice line at most 12, a banner at most 2 sentences; no em dash, no emoji, no exclamation mark. Existing strings are never edited.
- Tests: always `--maxWorkers=1`; e2e runs with 1 worker. 16 GB machine shared with MATLAB: one heavy process at a time. "Test timed out" is not an assertion failure; rerun once alone before diagnosing.
- Units and sign conventions are annotated in comments for every physical quantity: `[kg]`, `[ms] epoch, UTC`, `[s]`, `[sets]`, `[sessions/week]`.
- Phone width 320-412 px; installed iPhone Safari and Android Chrome are the targets. Playwright here is Chromium with iPhone/Pixel emulation, NOT WebKit.
- Commit once per task with the message given; never push (the owner pushes). In a `.claude/worktrees/*` worktree the git guard refuses git: stop, leave changes uncommitted, list the files.
- E2E repro specs carry `test.fail()` until the task that fixes them deletes that one line. A spec that passes while still marked fails the suite ("expected to fail, but passed"): if that happens in a task that was not meant to fix it, stop and report which spec flipped.

// e2e/support/app.ts
//
// Browser-side helpers. The document is seeded by an init script BEFORE the app's own scripts
// run, guarded by a marker key, so a relaunch (a new page in the same context, which is how an
// installed app's cold start is simulated: sessionStorage is new, localStorage is kept) reads
// what the previous page wrote instead of the seed.
import { expect, type BrowserContext, type Page } from '@playwright/test';
import type { AppState } from '../../src/domain/types';
import {
  E2E_BASE_URL,
  LABEL,
  SEEDED_MARKER_KEY,
  STORAGE_KEY,
  logLabel,
  loadLabel,
  repsLabel,
} from './constants';

/**
 * A wall-clock instant for a civil date and time in America/Chicago. Fixed offset -05:00 (CDT),
 * valid from 2026-03-08 to 2026-10-31; refuses any other month rather than silently shifting.
 */
export function chicago(date: string, time: string): Date {
  const month = Number(date.slice(5, 7));
  if (month < 4 || month > 10) throw new Error(`chicago(): ${date} may be outside CDT; add its offset`);
  return new Date(`${date}T${time}:00-05:00`);
}

export async function seedDocument(context: BrowserContext, doc: AppState): Promise<void> {
  await context.addInitScript(
    ({ key, marker, text }) => {
      if (window.localStorage.getItem(marker) !== null) return;
      window.localStorage.setItem(key, text);
      window.localStorage.setItem(marker, '1');
    },
    { key: STORAGE_KEY, marker: SEEDED_MARKER_KEY, text: JSON.stringify(doc) },
  );
}

const clocks = new WeakSet<BrowserContext>();

/**
 * Sets the context's wall clock (every page in it). The first call installs fake timers that keep
 * running from `at`; later calls jump the system time without firing timers, which is what a
 * phone that slept overnight looks like to the next launch.
 */
export async function setClock(context: BrowserContext, at: Date): Promise<void> {
  if (clocks.has(context)) {
    await context.clock.setSystemTime(at);
    return;
  }
  await context.clock.install({ time: at });
  clocks.add(context);
}

/** A cold launch: a new page at the app's URL, waited until the shell has rendered. */
export async function openApp(context: BrowserContext): Promise<Page> {
  const page = await context.newPage();
  await page.goto(E2E_BASE_URL);
  await page.locator('main').waitFor();
  return page;
}

export async function readRaw(page: Page): Promise<string | null> {
  return page.evaluate((key) => window.localStorage.getItem(key), STORAGE_KEY);
}

export async function readDocument(page: Page): Promise<AppState> {
  const text = await readRaw(page);
  if (text === null) throw new Error(`no document under ${STORAGE_KEY}`);
  return JSON.parse(text) as AppState;
}

 * Writes any debounced change now: the store flushes on `pagehide` (src/store/index.ts
 * startPersistence), so this dispatches one instead of sleeping past SAVE_DEBOUNCE_MS.
 */
export async function flushWrites(page: Page): Promise<void> {
  await page.evaluate(() => {
    window.dispatchEvent(new PageTransitionEvent('pagehide'));
  });
}

/** Taps Start on Today and waits for the Train view's Finish control. */
export async function startFromToday(page: Page): Promise<void> {
  await page.getByRole('button', { name: LABEL.start }).click();
  await expect(page.getByRole('button', { name: LABEL.finish })).toBeVisible();
}

/**
 * Logs set `n` of the open card. The Log tap is dispatched rather than clicked: on iPhone-size
 * screens the coach/undo toast covers the next Log button (audit C08, fixed in P4), and a real
 * click would land on the toast. This spec family tests the store, not that overlap.
 */
export async function logSet(page: Page, n: number, load: string, reps: string): Promise<void> {
  await page.getByLabel(loadLabel(n), { exact: true }).fill(load);
  await page.getByLabel(repsLabel(n), { exact: true }).fill(reps);
  await page.getByRole('button', { name: logLabel(n), exact: true }).dispatchEvent('click');
}

// src/domain/schedule/staleSessions.ts
//
// Spec R1 (audit C01/D01, owner O1): a session left open on an earlier civil date never blocks
// the schedule. cursor.ts refuses to open a day while another is non-terminal, and before this
// module nothing could close a day the clock had moved past, so one forgotten Finish froze every
// later Start. Pure: the store runs it on launch and on every return to the foreground
// (src/app/useWeeklyClose.ts) and before Today's Start.
//
// Every date is a LocalDate in the profile's zone; every instant is epoch ms, UTC.
import { compareLocalDate } from '../dates';
import { completeSession, isTerminal } from './cursor';
import type { AppState, EpochMs, LocalDate, SessionAssignment } from '../types';

/**
 * [ms] A session whose last activity (its last set, else its start) is younger than this stays
 * open past midnight, so a lifter training at 23:30 is not cut off when the phone wakes at 00:05
 * between sets. 4 h is an engineering bound: longer than any session the plan prescribes,
 * shorter than a night. Not a physiological figure.
 */
export const STALE_SESSION_GRACE_MS = 4 * 60 * 60 * 1000; // [ms] 4 h

/** What the closer did to one day, for the one notice the user gets. */
export interface StaleClosure {
  date: LocalDate;
  sessionId: string;
  /** completed: it had sets, closed at the last one. released: no sets; the session is next again. */
  outcome: 'completed' | 'released';
}

/** The profile's open (in-progress) session, on whatever date it was opened, or null. */
export function openAssignment(
  state: Pick<AppState, 'assignments'>,
  profileId: string,
): SessionAssignment | null {
  return (state.assignments[profileId] ?? []).find((a) => a.status === 'in-progress') ?? null;
}

/** [ms] The newest loggedAt among this profile's sets on `date`, or null when there are none. */
function lastLoggedAt(state: AppState, profileId: string, date: LocalDate): EpochMs | null {
  let last: EpochMs | null = null;
  for (const s of Object.values(state.sets)) {
    if (s.profileId !== profileId || s.assignmentDate !== date) continue;
    if (last === null || s.loggedAt > last) last = s.loggedAt;
  }
  return last;
}

/**
 * Closes every non-terminal assignment of `profileId` dated before `today` whose last activity is
 * older than STALE_SESSION_GRACE_MS. With sets: completed, completedAt = the last set's instant,
 * cursor advanced by one (cursor.ts completeSession). Without: the row is removed and the cursor
 * holds, so the same session is served next. Returns the argument itself when nothing closes.
 *
 * @param now [ms] epoch, UTC
 */
export function closeStaleSessions(
  state: AppState,
  profileId: string,
  today: LocalDate,
  now: EpochMs,
): { state: AppState; closed: StaleClosure[] } {
  const stale = (state.assignments[profileId] ?? []).filter(
    (a) => !isTerminal(a) && compareLocalDate(a.date, today) < 0,
  );
  if (stale.length === 0) return { state, closed: [] };

  let next = state;
  const closed: StaleClosure[] = [];
  for (const a of stale) {
    const last = lastLoggedAt(state, profileId, a.date); // [ms] or null
    const activity = Math.max(last ?? Number.NEGATIVE_INFINITY, a.startedAt ?? Number.NEGATIVE_INFINITY); // [ms]
    if (Number.isFinite(activity) && now - activity < STALE_SESSION_GRACE_MS) continue;
    if (last !== null) {
      const completed = completeSession(next, profileId, a.date, last); // completedAt [ms] = last set
      if (completed === next) continue; // no cursor or plan: nothing the domain can close
      next = completed;
      closed.push({ date: a.date, sessionId: a.sessionId, outcome: 'completed' });
    } else {
      next = {
        ...next,
        assignments: {
          ...next.assignments,
          [profileId]: (next.assignments[profileId] ?? []).filter((r) => r.date !== a.date),
        },
      };
      closed.push({ date: a.date, sessionId: a.sessionId, outcome: 'released' });
    }
  }
  return closed.length === 0 ? { state, closed } : { state: next, closed };
}
```

/**
 * Spec R2: Skip Today POSTPONES. The cursor never moves, so the same session is served on the
 * next visit; `date` joins cursor.postponed so the forecast serves nothing on it; a planned pick
 * on `date` is removed. Dates before `date` are pruned: only today and later can still matter.
 *
 * A no-op (the argument itself) for a closed day, a day already postponed, or no cursor/plan.
 * Throws when the day's session has started (in progress, or a pick that already holds sets):
 * the way out of a started session is Finish, not Skip.
 */
export function postponeSession(state: AppState, profileId: string, date: LocalDate): AppState {
  const r = resolve(state, profileId);
  if (!r) return state;
  const day = r.assignments.find((a) => a.date === date) ?? null;
  if (day !== null && isTerminal(day)) return state;
  const hasSets = Object.values(state.sets).some(
    (s) => s.profileId === profileId && s.assignmentDate === date,
  );
  if (day?.status === 'in-progress' || (day !== null && hasSets)) {
    throw new Error(`postponeSession: session already started on ${date}`);
  }
  const kept = (r.cursor.postponed ?? []).filter((d) => compareLocalDate(d, date) >= 0);
  if (day === null && kept.includes(date)) return state;
  const postponed = kept.includes(date) ? kept : [...kept, date].sort(compareLocalDate);
  return {
    ...state,
    assignments:
      day === null
        ? state.assignments
        : { ...state.assignments, [profileId]: r.assignments.filter((a) => a.date !== date) },
    cursors: { ...state.cursors, [profileId]: { ...r.cursor, postponed } },
  };
}

// src/store/validate.ts
//
// The one copy of the store's boundary check (spec R5, AGENTS.md rule 2). Every action that
// stores user input parses it with the schema the loader uses, so a value the document could
// not be reloaded with is refused where it is entered, not at the next launch (audit B02).
import type { z } from 'zod';

/**
 * Validates against a schema or throws, naming the field that failed. The message is assembled
 * the way parseState assembles its own (first issue, path then reason) rather than from
 * `error.message`, which in Zod 4 is the serialised issue array.
 */
export function parseOrThrow<S extends z.ZodType>(schema: S, value: unknown, what: string): z.output<S> {
  const result = schema.safeParse(value);
  if (result.success) return result.data;
  const first = result.error.issues[0];
  const where = first === undefined ? '(root)' : first.path.join('.') || '(root)';
  const why = first === undefined ? 'unknown validation failure' : first.message;
  throw new Error(`${what}: ${where}: ${why}`);
}

/**
 * Audit B03 stopgap (spec P1): another instance of the app (a second tab, the installed app
 * beside a browser tab) wrote or removed the document. Browsers fire `storage` in every OTHER
 * same-origin document, never in the writer. `key === null` is a `clear()`. Returns the
 * unsubscribe. P2's IndexedDB engine replaces this with BroadcastChannel and a revision.

export function onExternalWrite(listener: () => void): () => void {
  const handler = (e: StorageEvent): void => {
    if (e.key !== null && e.key !== STORAGE_KEY) return;
    listener();
  };
  window.addEventListener('storage', handler);
  return () => {
    window.removeEventListener('storage', handler);
  };
}

// src/domain/numberInput.ts
//
// Spec R4 (audit C02/A03): numeric fields are text the app parses, so a decimal comma is never
// dropped by the browser. Pure; no locale lookup: the user's mark is read from what they typed.

/** An optional sign, a whole part, and at most one decimal mark (`.` or `,`) with digits after. */
const DECIMAL = /^([+-]?)(\d*)(?:([.,])(\d*))?$/;

/**
 * The number typed, or null when the text is empty, not a number, or ambiguous. Ambiguous: both
 * marks, more than one mark, or one mark followed by exactly three digits after a non-zero whole
 * part ("1,234", "2.100"): half the locales read that as a thousands group, the other half as a
 * decimal, and a guess there is a 1000x error. "0,125" is accepted: a zero whole part cannot be
 * a group.
 */
export function parseDecimalInput(text: string): number | null {
  const trimmed = text.trim();
  if (trimmed === '') return null;
  const m = DECIMAL.exec(trimmed);
  if (m === null) return null;
  const sign = m[1] ?? '';
  const whole = m[2] ?? '';
  const mark = m[3];
  const fraction = m[4] ?? '';
  if (whole === '' && fraction === '') return null;
  if (mark !== undefined && fraction.length === 3 && whole !== '' && Number(whole) !== 0) return null;
  const value = Number(`${sign}${whole === '' ? '0' : whole}.${fraction === '' ? '0' : fraction}`);
  return Number.isFinite(value) ? value : null;
}
```

/**

 * a missing or non-positive reference are never questioned.

 * @param loadKg [kg] the load about to be logged

 */
export function implausibleLoad(loadKg: Kg, referenceKg: Kg | null): boolean {

  return (

        {t(raw === null ? 'hero.storageUnreadable' : 'hero.storedDataRefused')}
      </h1>
      <p>{t('status.writesPaused')}</p>
      <div className="view-field">
        <label htmlFor="recovery-import">{t('label.importBackup')}</label>
        <input
          id="recovery-import"
          type="file"
          accept="application/json,.json"
          onChange={(e) => {
            const file = e.target.files?.[0];
            if (file !== undefined) readFile(file);
          }}
        />
      </div>
      {importError !== null && (
        <p className="wiz-error" role="alert">
          {importError}
        </p>
      )}
      {wipeOpen ? (
        <ConfirmDestructive
          titleKey="label.confirmWipe"
          word={CONFIRM_WORD}
          exportLabelKey="button.exportStoredData"
          exportFilename="fixthisinjustice-recovery.json"
          // B04: the backup is the STORED text being destroyed, not the in-memory default.
          exportText={() => raw ?? '{}'}
          confirmLabelKey="button.wipeConfirm"
          onConfirm={() => {
            useAppStore.getState().wipeAll();
            setWipeOpen(false);
          }}
          onCancel={() => {
            setWipeOpen(false);
          }}
        />
      ) : (
        <button
          type="button"
          onClick={() => {
            setWipeOpen(true);
          }}
        >
          {t('button.wipeAll')}
        </button>
      )}
    </section>
  );
}
