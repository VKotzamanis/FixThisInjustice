# FixThisInjustice v2 — Master Plan (architecture, contracts, and plan set)

> **For agentic workers:** this document is the specification shared by every numbered plan in `docs/plans/`. Each numbered plan follows the `writing-plans` format and is executed with `subagent-driven-development`. Implement the numbered plans in order; every plan produces working, tested software on its own.

**Goal:** turn the single-user 24-week console into a generic, phone-first, offline-capable training companion that any friend can install on Android or iPhone, configure with their own body data, goals, units, and weekly availability, and that reminds them before each session, times their rest, pauses without losing their place, and confronts a missed week with a video.

**Architecture:** one static PWA (Vite + React + TypeScript) hosted on GitHub Pages, with all user data on the device in one validated localStorage document, plus one Cloudflare Worker whose only job is to send scheduled Web Push reminders. No accounts, no server-side user data beyond push subscriptions and the next three weeks of reminder instants.

**Tech Stack:** Node 22, Vite 8, React 19, TypeScript 5.9, Zod 4, Zustand 5, date-fns 4 + @date-fns/tz, vite-plugin-pwa 1.3 (Workbox, `injectManifest`), Vitest 4 + Testing Library + jsdom + fast-check, ESLint 10 + typescript-eslint 8, Cloudflare Workers (Wrangler 4, KV, Cron Triggers) with `@pushforge/builder` for VAPID Web Push.

Review inputs this plan is built on (read them before writing or executing any numbered plan):
- `docs/review/2026-09-01-security-review.md` (23 findings; constraints section)
- `docs/review/2026-09-01-code-review.md` (72 findings; port/rewrite/drop table; data-model proposal)
- `docs/review/2026-09-01-content-peer-review.md` (equations, programming rules, citations, lines to delete)
- `REFERENCES.md` (every external fact used here, with method and session id)

## 1. Decisions

Each decision names what was rejected and why. Headers follow the repository decision-tracking convention so `graphify` indexes them.

<!-- decision: platform-stay-pwa-vite | status: adopted | supersedes: none -->
### 1.1 Platform: stay a web PWA, replace the toolchain (adopted)
Vite + React + TypeScript compiled ahead of time; installable via "Add to Home Screen" on Android and iPhone. Rationale: distribution by URL covers both phone platforms; Babel's own documentation says not to use `@babel/standalone` in production; the live site also ships React's development build. Platform floor: iOS 18.4 or later (Web Push needs an installed Home Screen app since 16.4; Screen Wake Lock in installed web apps was fixed in 18.4), Android with Chrome.

<!-- decision: platform-capacitor-native | status: rejected | supersedes: none -->
### 1.2 Capacitor native wrapper (rejected in favour of platform-stay-pwa-vite)
Would give exact-time offline local notifications on both platforms. Rejected because an iOS build requires macOS + Xcode and the Apple Developer Program (99 USD/yr) for TestFlight; this development machine is Linux. On Android 14 the exact-alarm permission is off by default and Google Play reserves the frictionless variant for alarm and calendar apps. Remains a possible later Android-only add-on because the web code is unchanged.

<!-- decision: platform-expo-rewrite | status: rejected | supersedes: none -->
### 1.3 Expo / React Native rewrite (rejected in favour of platform-stay-pwa-vite)
Same iOS distribution barrier plus a full rewrite of working presentation code.

<!-- decision: reminders-cloudflare-worker-webpush | status: adopted | supersedes: none -->
### 1.4 Reminders: Web Push sent by a Cloudflare Worker cron (adopted)
No web API in 2026 schedules a future local notification without a server (Chrome ended Notification Triggers; Periodic Background Sync is Chromium-only with no time control). The client computes concrete reminder instants and uploads them; a Worker cron (`* * * * *`, free plan) sends due pushes. Free-plan budget: 100,000 requests/day, KV 100,000 reads/day and 1,000 writes/day, 5 cron triggers.

<!-- decision: reminders-zero-server | status: rejected | supersedes: none -->
### 1.5 Zero-server reminders: calendar export or ntfy (rejected in favour of reminders-cloudflare-worker-webpush)
Calendar `.ics` alarm firing on import has insufficient evidence on both platforms; ntfy needs a second app and re-posting every 3 days. A one-time `.ics` export stays as a courtesy in the Export view only.

<!-- decision: reminders-durable-object-alarms | status: rejected | supersedes: none -->
### 1.6 Durable Object alarms instead of cron + KV (rejected in favour of reminders-cloudflare-worker-webpush)
More precise, but adds bindings, migrations, and per-object state for a handful of users. Cron + KV with an index key is one file. Revisit only if minute-level polling proves unreliable.

<!-- decision: push-library-pushforge | status: adopted | supersedes: none -->
### 1.7 Push library: `@pushforge/builder` (adopted)
Zero-dependency Web Crypto VAPID implementation built for Workers, MIT, released 2026-04. The alternative `@block65/webcrypto-web-push` was last published 2024-12 and is rejected as unmaintained.

<!-- decision: state-storage-localstorage-zod | status: adopted | supersedes: none -->
### 1.8 State persistence: one localStorage key, Zod-validated, versioned (adopted)
The whole state for a year of training is well under 1 MB; synchronous load at boot avoids a loading state; quota failure is handled explicitly (`QuotaExceededError` → blocking banner + export). IndexedDB (`idb`) is used only for binary assets (the user-picked motivation video). Rejected: IndexedDB for all state (async boot and transaction code for no capacity gain at this volume).

<!-- decision: state-management-zustand | status: adopted | supersedes: none -->
### 1.9 State management: Zustand with selectors (adopted)
Selector subscriptions stop the whole-tree re-render the monolithic `useState` caused (code review A41). Rejected: React Context + `useReducer` (same re-render churn); Redux Toolkit (weight without benefit here).

<!-- decision: dates-date-fns-tz | status: adopted | supersedes: none -->
### 1.10 Dates: date-fns 4 + `@date-fns/tz`, explicit IANA zone everywhere (adopted)
Every civil date is derived from the profile's IANA zone through `TZDate`; `Date.prototype.toISOString` on civil dates is banned by lint. Rejected: `Temporal` (polyfill size, uneven shipping); Luxon (larger, overlapping).

<!-- decision: typescript-5-9-line | status: adopted | supersedes: none -->
### 1.11 TypeScript 5.9 line (adopted)
`typescript@7` (the native compiler) is `latest` on npm but was not evaluated against Vite 8, Vitest 4, and typescript-eslint 8 here. Pin `^5.9.3`; revisit after the first release.

<!-- decision: csp-meta-no-frame-ancestors | status: adopted | supersedes: none -->
### 1.12 Clickjacking: confirmations, not CSP (adopted)
GitHub Pages cannot set response headers, and MDN states `frame-ancestors` "is not supported in the `<meta>` element". Therefore every destructive action requires a typed confirmation and an automatic export first, and a JavaScript frame check hides the UI when framed. The security review's constraint 15 is corrected accordingly.

Worker: `wrangler ^4.128.0`; `@cloudflare/workers-types ^5.20260901.1`; `@pushforge/builder ^2.0.5`.

**TypeScript:** `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`, `verbatimModuleSyntax: true`, `target: ES2022`, `moduleResolution: bundler`. No `any`, no `as` casts on external data.

**Lint gates (must fail the build):** `no-empty` with no `allowEmptyCatch`; `no-restricted-syntax` banning `CallExpression[callee.property.name='toISOString']` outside `src/domain/dates.ts`; `no-restricted-globals` banning bare `localStorage` and `no-restricted-syntax` banning `window.localStorage`/`globalThis.localStorage` outside `src/store/persistence.ts`; `react-hooks/rules-of-hooks` and `react-hooks/exhaustive-deps` as errors; `@typescript-eslint/no-explicit-any` error.

**Units and sign conventions (canonical storage, no exceptions):** mass kg, volume mL, duration s, instants epoch ms UTC, distances m, energy kcal, protein g. Display unit is a profile property applied only in `src/domain/units.ts`. `1 lb = 0.45359237 kg` exactly. US fluid ounce is 29.5735295625 mL exactly. Logged loads display at 0.1 resolution in the display unit with no plate quantisation (a logged value is never altered for display); only *suggested* loads are quantised, rounding down, to the user's equipment step (defaults: barbell 2.5 kg or 5 lb, dumbbells 5 kg or 10 lb per pair, from the content review's verified plate table). Body mass displays at 0.1. Entered values are converted exactly and stored with `enteredUnit`. Deltas are `current − reference`: negative body-mass delta means loss; negative weekly delta means sessions missed. Every physical quantity in code carries a unit comment.

**Dates:** `LocalDate` is `"YYYY-MM-DD"` in the profile's IANA zone, produced only by `src/domain/dates.ts`. Week starts Monday (ISO). Tests for date logic run fixtures in `Europe/Athens`, `America/New_York`, `America/Los_Angeles`, and `UTC`, across both DST transitions; a 168-day programme must measure 168 days in every zone.

**Content Security Policy (meta tag in `index.html`; enforced in CI by grepping `dist/index.html`):**
`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; font-src 'self'; connect-src 'self' https://*.workers.dev; frame-src <generated>; worker-src 'self'; base-uri 'none'; form-action 'none'; object-src 'none'`.
(`connect-src` is replaced at build by the exact Worker origin from `VITE_REMINDER_API`, and by `'self'` alone when the variable is unset, which fails closed. `frame-src` is generated at build from `src/config/videoInstances.ts`, whose entries `{ host, label }` are ported from the legacy `INSTANCES` list in `console-video.jsx` (the current curated list: invidious.nerdvpn.de, inv.nadeko.net, invidious.tiekoetter.com, yt.chocolatemoo53.com, inv.thepixora.com, invidious.f5.si) so policy and modal never drift. PWA precache: `injectManifest.globIgnores` excludes `**/media/*.mp4`; the clip is cached at first play by the `CacheFirst` route for `/media/`.) No inline `<script>`, no `eval`, no runtime JSX. `<meta name="referrer" content="no-referrer">`.

**Personal data:** no medication, biometric, or location strings in tracked source. CI gate (this list supersedes security constraint 26's; legacy field *names* such as `weight_kg` may remain with zeroed values): `git grep -nEi 'vyvans[e]|lisdexamfetamin[e]|ymc[a]|amphetamin[e]' -- 'src/' 'worker/' 'public/' 'index.html'` must return nothing (the one-character classes stop the pattern matching its own definition in the workflow); during P1–P6 the legacy tree under `legacy/` is scrubbed of the lines listed in the content review §7 and security H1 before the baseline commit.

**Storage:** single key `fti.v3`, owned by `src/store/persistence.ts`; payload carries `schemaVersion`; every load, import, and paste passes `AppStateSchema.safeParse`; on failure keep last known-good state in memory, show the error, offer export; `QuotaExceededError` shows a persistent banner with an export control (non-modal, so the user can still reach Export). No derived values persisted.

**Destructive actions:** typed confirmation (`type DELETE`) gated behind a completed JSON export (the export control must have been used in the same dialog before the confirmation is enabled; a download cannot be forced silently in every browser, so a manual, gated export replaces the earlier "automatic" wording). The clear path must cancel any pending debounced write (call the store's `wipeAll`, never `clearStorage` alone). No always-visible wipe control.

**Tests:** Vitest; unit tests next to modules as `*.test.ts`; UI tests with Testing Library under `src/ui/**/*.test.tsx`; property tests with fast-check for units and schema round-trips. `npm test` must pass before every commit.

**Copy in all user-facing strings (default skin):** concise and honest; no em-dashes or en-dashes as sentence connectors (en-dashes in numeric ranges such as 6–8 are fine); no emoji; no hedging or filler; no exclamation marks. Buttons ≤ 3 words, hero lines ≤ 8 words, advice lines ≤ 12 words. The arithmetic behind a value (progression percentages, plate rounding, delta formulas, unit conversions) is NOT shown inline; it lives behind a "why?" disclosure and appears only when the user must act differently because of it. Exercise form cues, tips, and the Atlas cards are exempt from the length limits. The full rules are in `docs/design/2026-09-01-copy-contract.md`, which every UI task follows. Terminology: use the defined quantity (kcal, g protein, kg, mL, RPE, RIR, 1RM) never a colloquial stand-in.
**Skins:** the clinical copy is the default. A skin is a token set, a copy table (`Record<CopyKey, string>` merged over the default), an optional icon set, and optional sound effects, selected by `UiPrefs.skin`. Skins may use camp, profanity, and slang (the user's group asked for it); they may not use slurs, body-shaming, or food morality, and they never alter a number, a unit, or the meaning of a plan-altering control. Skin assets ship under licences recorded in the design docs (Google Fonts OFL; CC0/CC-BY icons; own Gemini generations).

**Commits:** each task ends with a commit on `main` of this repository (no push unless the user asks). Commit messages: `feat|fix|test|chore|docs: <summary>`.

## 5. Shared types (`src/domain/types.ts`)

These are the contract. Numbered plans may add fields only by editing this section first.

```ts
// ---- primitives (canonical units in comments; storage is always canonical) ----
export type Kg = number;        // kilograms, >= 0
export type ML = number;        // millilitres, integer >= 0
export type Seconds = number;   // seconds, >= 0
export type EpochMs = number;   // epoch milliseconds, UTC
export type LocalDate = string; // "YYYY-MM-DD" in Profile.timezone; produced only by dates.ts
export type LocalTime = string; // "HH:mm" 24 h in Profile.timezone
export type TimeZone = string;  // IANA id, e.g. "America/Chicago"
export type IsoWeekday = 1 | 2 | 3 | 4 | 5 | 6 | 7; // 1 = Monday
export type UnitSystem = "metric" | "imperial";
export const KG_PER_LB = 0.45359237;                       // exact by definition
export const DEFAULT_BARBELL_STEP: Record<UnitSystem, number> = { metric: 2.5 /* kg total: pair of 1.25 kg plates */, imperial: 5 /* lb total: pair of 2.5 lb plates */ };
export const DEFAULT_DUMBBELL_STEP: Record<UnitSystem, number> = { metric: 5 /* kg per pair */, imperial: 10 /* lb per pair */ };
export const DEFAULT_STACK_STEP: Record<UnitSystem, number> = { metric: 5 /* kg per pin, typical; user-editable */, imperial: 10 /* lb per pin */ };
export const MICRO_PLATE_STEP: Record<UnitSystem, number> = { metric: 0.5 /* kg total: pair of 0.25 kg */, imperial: 1 /* lb total: pair of 0.5 lb */ };

// ---- profile ----
export type Sex = "male" | "female";                        // required by the RMR equation; collected as such
export type ActivityLevel = "sedentary" | "moderate" | "vigorous"; // the three FAO/WHO/UNU 2004 PAL bands the content review verified; no invented midpoints
export type GoalKind = "fat-loss" | "muscle-gain" | "recomposition" | "maintenance";
export type Experience = "novice" | "intermediate" | "advanced";
export type Equipment = "full-gym" | "dumbbells-only" | "bodyweight";

export interface Profile {
  id: string; displayName: string; timezone: TimeZone; units: UnitSystem; createdAt: EpochMs;
  body: { sex: Sex; birthYear: number; heightCm: number; baselineMassKg: Kg; baselineAt: LocalDate; baselineBodyFatPct: number | null; };
  activity: ActivityLevel;
  experience: Experience;
  equipment: Equipment;
  equipmentSteps: { barbellKg: number; dumbbellPairKg: number; stackKg: number; hasMicroPlates: boolean; microPlateKg: number; }; // canonical kg; seeded from DEFAULT_*_STEP / MICRO_PLATE_STEP in the user's unit at setup, editable
  goal: { kind: GoalKind; targetMassKg: Kg | null; targetBodyFatPct: number | null; targetDate: LocalDate | null; };
  supplements: { creatine: boolean; };                     // no medication fields exist by design
  hydration: { dailyTargetML: ML; cupSizeML: ML; weighInOptIn: boolean; }; // cupSizeML is display granularity only; weighInOptIn enables the pre/post-session mass check
  readiness: { screenedAt: LocalDate | null; flagged: boolean; };          // pre-participation screen (P2): flagged = any positive answer; the app then shows the physician-consult notice on every session start
}

// ---- availability ----
export interface AvailabilitySlot { weekday: IsoWeekday; startTime: LocalTime; expectedDurationS: Seconds; }
export interface Availability { slots: AvailabilitySlot[]; weeklySessionTarget: number; } // 1 <= target <= slots.length

// ---- plan template (calendar-free) ----
export type Prescription =
  | { kind: "reps"; lo: number; hi: number }               // hi >= lo
  | { kind: "amrap"; minimum: number | null }
  | { kind: "time"; targetS: Seconds }
  | { kind: "duration"; targetS: Seconds }
  | { kind: "none" };
export type Modality = "barbell" | "dumbbell" | "machine" | "cable" | "bodyweight";
export type LoadClass = "lower-compound" | "upper-compound" | "isolation"; // drives the progression percentage (5 % / 2.5 % / 2.5 %)
export interface Exercise { id: string; name: string; isBodyweight: boolean; isCompoundPrimary: boolean; modality: Modality; loadClass: LoadClass; muscleGroups: string[]; secondaryMuscles: string[]; equipment: Equipment[]; videoQuery: string | null; formCueId: string | null; note: string | null; } // muscleGroups = direct movers (1.0 set), secondaryMuscles = dynamic assisting movers (0.5 set) for fractional weekly set counting
// Canonical exercise ids (P2 library MUST use exactly these slugs; formCueId === id where a cue exists): barbell-bench-press, overhead-press-barbell, incline-db-press, lateral-raise, triceps-overhead-extension, pull-up, lat-pulldown, barbell-row-pendlay, barbell-row, db-single-arm-row, face-pull, barbell-curl, hammer-curl, barbell-back-squat, romanian-deadlift, leg-press, bulgarian-split-squat, leg-curl-machine, calf-raise, push-up, trap-bar-deadlift, conventional-deadlift, weighted-pull-up, close-grip-bench-press, push-press, rower-intervals, plank, ab-wheel-rollout, hanging-knee-raise, walk, stair-climber. `barbell-row-heavy` is excluded until its cue is rewritten.
export interface PlannedExercise { exerciseId: string; setsLo: number; setsHi: number; prescription: Prescription; restS: Seconds; }
```

```ts

export function formatVolume(ml: ML, units: UnitSystem): string;      // "500 mL" | "17 fl oz" (US fl oz = 29.5735295625 mL exactly)
```

### 6.6 `src/domain/reminders/instants.ts` and the Worker API (P5)
```ts
export function computeReminderInstants(state: AppState, profileId: string, from: LocalDate, days: number, now: EpochMs): ReminderInstant[];
// For each CalendarDay in projectedCalendar(from, days) with a slot and not paused: one "day-of" instant at ReminderSettings.dayOfTime and one per leadMinutes before slot.startTime. Skip instants already in the past, and clamp the horizon to now + 21 d in MILLISECONDS (21 calendar days across a fall-back exceed 21 d elapsed and would make the Worker reject the whole upload). Title: `${session.label} today`; body: `${session.name} at ${slot.startTime} — session ${ordinal} of ${plan.sessions.length}`.
export function scheduleHash(instants: ReminderInstant[]): string; // stable hash for change detection
```
Worker HTTP contract (JSON, CORS restricted to the Pages origin):
- `PUT /v1/devices/{deviceId}` body `{ secret: string, subscription: { endpoint, keys: { p256dh, auth } }, reminders: ReminderInstant[] }` → `204`. Creates on first call; later calls must present the same `secret` or receive `403`. Limits: ≤ 200 reminders; `at` within `[now − 1 h, now + 21 d]`; otherwise `400`.
- `DELETE /v1/devices/{deviceId}` with header `Authorization: Bearer {secret}` → `204`.
- `GET /v1/health` → `{ ok: true, vapidPublicKey }` (echoing the public key makes a key mismatch a one-command check). Other refusals: `401` (no bearer on DELETE), `404`, `405`, `413` (body > 64 KB), `503` (device index at the 100-device cap).
- Cron `* * * * *`: read KV `idx` (JSON string[] of deviceIds); for each `dev:{id}` record, send every reminder with `at <= now && at > now − 15 min && key ∉ record.sent` (any 2xx counts as sent; the stored `sent` map is carried across client re-syncs); append sent keys (prune those older than 24 h); write the record back only if it changed; on push-service `404`/`410` delete the record and remove the id from `idx`.
- KV namespace binding `REMINDERS`; secrets `VAPID_PRIVATE_JWK`; vars `VAPID_PUBLIC_KEY`, `ADMIN_CONTACT` (mailto), `ALLOWED_ORIGIN`.
- The Worker stores nothing but the above. No names, no body data.
