# P3a Exercise Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the basic movement patterns the owner found missing (lunges, step-ups, hip thrust, dumbbell bench press, cable row and 23 more), make plan generation and the swap/add pickers respect the setup inventory (audit D07), and stop sub-gym sessions collapsing or putting push-ups on a lower day (audit D08).

**Architecture:** A new pure module `src/domain/plan/inventory.ts` holds the per-exercise required items and turns a profile's setup answers into an `Inventory` (null = no filter). `templates.ts` resolves each slot through tier AND inventory, and a new `resolveWeek` tops short sessions up to a stated floor from region pools under a weekly volume guard; the generator emits `resolveWeek`. The profile gains one optional field recording where the inventory was asked, so an old profile keeps the pre-P3a behaviour (rule 7).

**Tech Stack:** TypeScript 5.9, React 19, Zod 4, Vitest 4 (`--maxWorkers=1`).

**Spec:** `docs/plans/2026-11-04-aaa-rebuild-spec.md` (ruling R11; phase P3 "R11 library + D07/D08 inventory (O3)"). Findings: `docs/private/audit-2026-11-04/D-schedule.md` D07, D08. Owner complaint O3: "it doesn't have very basic exercises such as lunges."

## Rulings (each names the rejected alternative)

1. **Requirements live in a table beside the library, not on `Exercise`.** `EXERCISE_REQUIREMENTS` in `inventory.ts`, one entry per library id (a test asserts the key set). Rejected: a `requires` field on `Exercise` (changes `ExerciseSchema`, `customExercises` storage and every fixture for data only the shipped library has).
2. **Four required items, mapped from the wizard ids:** `dumbbells` (any `dumbbells-*` band), `bench` (`bench`), `pull-up-bar` (`pull-up-bar`), `resistance-bands` (`resistance-bands`). Machines, rack and cardio machines unlock nothing new: those exercises stay full-gym tier. Rejected: letting a home `cable-machine`/`leg-press`/`lat-pulldown`/`squat-rack` unlock full-gym exercises (a tier-model change; listed as an open item for the lead).
3. **Setup constraints are not items:** a chair (bench dip, Bulgarian rear foot), a stair (bodyweight step-up), a table edge (incline push-up), an anchor (Nordic curl), a door frame (door-frame row). Loaded bench work (incline and flat dumbbell press, dumbbell step-up) needs `bench`. A full gym holds every item, so the filter never runs when the access level includes `full-gym`.
4. **Absent inventory = the pre-P3a assumption, not "no filter" and not "nothing".** `Profile.homeEquipment`/`bodyweightEquipment` parse to `[]` for old documents, so an empty list cannot mean "has nothing". New optional `Profile.inventoryAnsweredFor` (the access level setup asked the lists at) decides: a list is read only if it was shown at that level; every other item falls back to `LEGACY_ASSUMED_ITEMS = {dumbbells, bench, pull-up-bar}` (what the library assumed before: "needs only a bar, which every tier assumes"; dumbbells and bench in a home gym). Every pre-P3a exercise fits that set (test), so an old profile resolves every old exercise as before; it does not get band exercises (bands were never assumed). Rejected: empty list = never asked (reproduces the audit's exact D07 symptom for a user who ticks nothing); empty list = has nothing (an old profile would lose pull-ups and bench work on its next generation, rule 7).
5. **The portable list (mat, rope, bar, bands) is asked for every access level except Full gym**, inside the home block for the home levels. A home gym's bar and bands decide its pulling work, and the wizard never asked. No new copy key: the row has no label (wording out of scope).
6. **Lunges reach full-gym users volume-neutrally.** The split-squat slot (Lower B 4/5-day, Legs B 6-day) becomes a lunge slot led by `db-walking-lunge`, which carries the Bulgarian split squat's exact tags (quads and glutes direct, hamstrings secondary), so every weekly figure is unchanged. Rejected: a new lunge slot (pushes quads and glutes above the 4/5/6-day band tops in the full-gym tier). Honest limit: full-gym Lower A, Legs A and the 2/3-day full-body sessions still have no lunge-family exercise (no volume-neutral swap exists there); the generator matrix asserts the lunge slot only.
7. **Push-ups leave the lower day:** the 4-day `push-up` slot moves from Lower B to Upper B (same exercises per week, same volume). Rejected: deleting it (chest leaves the 4-day full-gym band).
8. **Session floor (audit D08):** `sessionFloor = max(4, slots - 1)` exercises: at most one slot short of its template, never under four (4 = the shortest template session, 5 slots, minus one). A HEURISTIC; no source sets a minimum exercise count. Filled from region pools (push / pull / upper / lower / full: equipment-free and band exercises of that region, then trunk), each entry filtered by tier and inventory, and accepted only if the week stays at or below the band top (midpoint) and the 20-set evidence ceiling (interval top). The evidence cap outranks the floor: 28 matrix cells stay short (all 6-day Pull A or 5-day advanced Upper B, no bands, never below 2), listed as an exact census. Rejected: trunk-only filler (measured: abs reached 40 sets/week); fixed floor 4 (measured 7 short cells but thinner sessions: 3-day bodyweight [4,5,5] against [5,6,5]); `max(5, slots-1)` (49 short cells).
9. **Two exercises beyond R11's list, each closing a measured gap:** `door-frame-row` (without it a no-bar, no-band user has no horizontal pull at all: 6-day Pull A had 1 exercise) and `prone-t-raise` (no-equipment rear-delt work). Plus `bw-squat`, `band-curl`, `db-single-leg-rdl`/`bw-single-leg-rdl` and `db-floor-press` from the brief.
10. **Prescriptions reuse existing rules only:** every bodyweight-loaded compound except the weighted pull-up takes AMRAP (existing rule: no load step), now derived in a test rather than only listed; `side-plank` takes the plank's legacy 60 s hold; `farmer-carry` takes `{ kind: 'none' }` (no sourced duration or distance); everything else falls to the existing load-class defaults. Band exercises are `isBodyweight: true`, `modality: 'bodyweight'` (band tension has no plate step; progression extends reps).

    bodyweightEquipment: [] as const,

      );
    }

          access,
          fits: true,
        });
      }
    }
  });

  it('never filters with a full gym in the access level, whatever the inventory says', () => {

      expect(fitsInventory(e, 'full-and-home', set())).toBe(true);

    const custom: Exercise = { ...ex('push-up'), id: 'custom-7', name: 'Sled push' };
    expect(fitsInventory(custom, 'bodyweight', set())).toBe(true);
  });
});

 * The items the app assumed before it read the inventory: dumbbells and a bench in a home gym, a
 * bar in every tier (library.ts pull-up row: "needs only a bar, which every tier assumes"). Bands
 * were never assumed. Used for every answer the profile does not hold (rule 7: a profile that
 * never answered keeps resolving every pre-P3a exercise exactly as before; inventory.test.ts
 * asserts it).
 */
export const LEGACY_ASSUMED_ITEMS: ReadonlySet<RequiredItem> = new Set<RequiredItem>([
  'dumbbells',
  'bench',
  'pull-up-bar',
]);

/** Setup shows the home-gym list (dumbbells, bench, machines) for these access levels. */
export function showsHomeEquipment(access: EquipmentAccess): boolean {
  return access === 'home' || access === 'home-and-bodyweight' || access === 'full-and-home';
}

/**
 * Setup shows the portable list (mat, rope, pull-up bar, bands) for every access level that
 * trains outside a full gym, home gyms included: a home gym's bar and bands are what decide its
 * pulling work.
 */
export function showsPortableEquipment(access: EquipmentAccess): boolean {
  return access !== 'full-gym';
}

const DUMBBELL_BANDS: readonly HomeEquipmentItem[] = [
  'dumbbells-5-20',
  'dumbbells-20-40',
  'dumbbells-40-plus',
];

export interface InventoryAnswers {
  equipment: EquipmentAccess;
  homeEquipment: readonly HomeEquipmentItem[];
  bodyweightEquipment: readonly BodyweightEquipmentItem[];
  /** The access level setup asked the lists at; null or absent = never asked (Profile field). */
  inventoryAnsweredFor?: EquipmentAccess | null | undefined;
}

/**
 * The inventory the generator and the pickers filter by.
 *
 * null when the access level includes a full gym. Otherwise each item comes from the list that
 * was shown at `inventoryAnsweredFor`, and an item from a list that was never shown falls back to
 * LEGACY_ASSUMED_ITEMS. So an old profile (no answers) resolves exactly as before, and a profile
 * whose access level was changed in Settings after setup keeps only the answers that still apply.
 */
export function inventoryOf(a: InventoryAnswers): Inventory {
  if (ACCESS_UNLOCKS[a.equipment].includes('full-gym')) return null;
  const askedAt = a.inventoryAnsweredFor ?? null;
  const homeAsked = askedAt !== null && showsHomeEquipment(askedAt);
  const portableAsked = askedAt !== null && showsPortableEquipment(askedAt);
  const items = new Set<RequiredItem>();
  const pick = (item: RequiredItem, asked: boolean, has: boolean): void => {
    if (asked ? has : LEGACY_ASSUMED_ITEMS.has(item)) items.add(item);
  };
  pick('dumbbells', homeAsked, a.homeEquipment.some((i) => DUMBBELL_BANDS.includes(i)));
  pick('bench', homeAsked, a.homeEquipment.includes('bench'));
  pick('pull-up-bar', portableAsked, a.bodyweightEquipment.includes('pull-up-bar'));
  pick('resistance-bands', portableAsked, a.bodyweightEquipment.includes('resistance-bands'));
  return items;
}

/**
 * True when the user can do `ex` with what they have: always with a full gym in the access level
 * (or a null inventory), otherwise only when the inventory holds every item the exercise needs.
 * A custom exercise (no table entry) needs nothing.
 */
export function fitsInventory(ex: Exercise, access: EquipmentAccess, inventory: Inventory): boolean {
  if (inventory === null || ACCESS_UNLOCKS[access].includes('full-gym')) return true;
  return (EXERCISE_REQUIREMENTS[ex.id] ?? []).every((item) => inventory.has(item));
}

 * So the fill never creates a volume the band tests would reject. A filled entry takes a
 * synthetic slot: compound-primary exercises a moderate compound slot (inserted after the last

 *
 * With a full gym, or any tier and a null inventory, every template session already meets its
 * floor, so this returns exactly the slot resolution; templates.test.ts asserts it.
 */
export function resolveWeek(
  days: SessionsPerWeek,
  experience: Experience,
  equipment: EquipmentAccess,
  inventory: Inventory = null,
  library: Readonly<Record<string, Exercise>> = EXERCISE_BY_ID,

  const bandTop = WEEKLY_SET_BAND[days][1]; // [sets/muscle/week]

  const top: Record<string, number> = {}; // [sets/muscle/week] interval tops
  const credit = (ex: Exercise, slotClass: SlotClass, sign: 1 | -1): void => {
    const s = sets[slotClass];
    const m1 = (sign * (s.lo + s.hi)) / 2;
    const t1 = sign * s.hi;
    for (const m of ex.muscleGroups) {
      mid[m] = (mid[m] ?? 0) + m1;
      top[m] = (top[m] ?? 0) + t1;
    }
    for (const m of ex.secondaryMuscles) {
      mid[m] = (mid[m] ?? 0) + m1 * INDIRECT_SET_FRACTION;
      top[m] = (top[m] ?? 0) + t1 * INDIRECT_SET_FRACTION;
    }

  for (const session of week) for (const r of session) credit(r.exercise, r.slot.slotClass, 1);

    const sessionTemplate = template.sessions[i];
    if (sessionTemplate === undefined) return session;

    const used = new Set(out.map((r) => r.exercise.id));
    for (const id of FLOOR_POOLS[sessionRegion(sessionTemplate.label)]) {
      if (out.length >= floor) break;
      const ex = library[id];
      if (ex === undefined || used.has(id)) continue;
      if (!ex.equipment.some((tier) => unlocked.includes(tier))) continue;
      if (!fitsInventory(ex, equipment, inventory)) continue;
      const slotClass: SlotClass = ex.isCompoundPrimary ? 'compound' : 'isolation';
      credit(ex, slotClass, 1);
      const over = [...ex.muscleGroups, ...ex.secondaryMuscles].some(
        (m) => (mid[m] ?? 0) > bandTop || (top[m] ?? 0) > EVIDENCE_CEILING_SETS,
      );
      if (over) {
        credit(ex, slotClass, -1);
        continue;
      }
      used.add(id);
      const slot: ExerciseSlot =
        slotClass === 'compound' ? comp('floor fill', [id]) : iso('floor fill', [id]);
      if (slotClass === 'compound') {
        let lastCompound = -1;
        out.forEach((r, j) => {
          if (r.exercise.isCompoundPrimary) lastCompound = j;
        });
        out.splice(lastCompound + 1, 0, { slot, exercise: ex });
      } else {
        out.push({ slot, exercise: ex });
      }
    }
    return out;
  });
}
